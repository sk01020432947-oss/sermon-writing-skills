# 설교 파이프라인 (종합)

```
 R 상시 자료층 ─ Logos MCP · 주석 폴더 · NotebookLM MCP ─────────────────┐
                                                                          │ (모든 트랙이 끌어다 쓴다)
 A 기획(설교 이전) → B 준비 6단계 → C 활용(설교 이후)                      │
   연간·시리즈·본문    1 본문개론 → 2 개요 → 3 주해                        │
   확정                → 4 주제선택 → 5 설교문작성 → 6 퇴고  ◀────────────┘
```

모든 스킬 실행은 서브에이전트가 맡고, 결과는 **파일로만** 다음 단계에 넘긴다. 메인 컨텍스트에는 각 단계의 3줄 요약만 남긴다.

## 진입 (무엇을 돌릴지)

| 사용자의 말 | 실행 범위 |
|---|---|
| 본문을 준다 ("롬 8:28-30으로 설교 준비") | B → C (기본) |
| "내년 설교 계획", "시리즈 기획", 본문이 아직 없다 | A → (본문 확정되면) B → C |
| "전 과정", "기획부터 활용까지" | A → B → C |
| "N단계부터", "퇴고만" | B의 해당 단계부터 |
| "설교 후 활용만", "발표자료만", "블로그로" | C만 (`06_설교문_최종.md` 필요) |

## KBG-Bible Labs 설정 블록을 받았을 때

입력에 `[KBG-Bible Labs 설정]` 블록이 있으면(앱: `~/Documents/KBG-Bible-Labs/kbg-bible-labs.html`) 그 블록이 이 문서의 기본 구성보다 우선한다. 시작 질문을 하지 않는다.

- `진행:`에 적힌 단계만, 적힌 순서로 돈다 (기획=A, 본문개론~퇴고=B 1~6, 활용=C), 출력=D).
- **모든 스킬 사용.** `스킬:`에 적힌 스킬은 하나도 생략하지 않는다. 같은 단계에 방법론·코치가 여럿 골라져 있어도(예: 신학자 코치 3명) 전부 돌려 각자의 산출 파일을 남기고, 병합본에서 관점별로 나란히 정리한 뒤 하나의 결론으로 종합한다. 기본 구성의 "한 명만" 규칙은 설정 블록 앞에서는 적용하지 않는다.
- `스킬:`의 각 단계에 적힌 스킬만 띄운다. 기본 단계표에 있어도 블록에 없으면 건너뛴다. 기본 단계표에 없던 스킬이 적혀 있으면 그 단계 작업자로 추가한다 (병렬 4개 묶음 규칙은 그대로).
- `세부:` 항목은 서브에이전트 프롬프트 1번에 "이 중 {항목들}만 수행한다"로 넣는다. "(선택 없음 → 스킬 기본값)"이면 제한 없이 돌린다.
- "(대화형)" 표시가 붙은 스킬은 서브에이전트로 돌리지 않고, 그 단계 차례에 메인 대화에서 직접 부른다.
- `자료 작업자`가 적힌 단계에서만 자료 작업자를 띄운다. `자료:`의 Logos·NotebookLM(이름과 ID)·주석집·기타 자료집 목록만 조회하고, "없음"인 자료는 건너뛴다. `작업 폴더`가 출력 폴더의 상위 폴더다.
- `주석 인용 대조`·`NotebookLM 아카이브`는 스킬이 아니라 6단계·C-3의 작업 이름이다.
- 발표자료 스킬이 하나만 적혀 있으면 C-1 샘플 질문 없이 그 스타일로 바로 만든다. 매체 확장도 적힌 것만 만들고 C-2 질문을 생략한다.
- `실행 방식: 단계마다 확인`이면 각 단계 3줄 요약 뒤에 다음 단계로 갈지 묻는다. `자동`이면 묻지 않는다.
- `실행 방식: 무인`은 앱의 로컬 서버(`server.py`)가 `claude -p`로 띄운 실행이다. 사용자에게 아무것도 묻지 않는다 — 물어야 할 곳은 기본값으로 정하고 `00_진행상황.md`에 적는다. 셸(Bash)이 없으므로 폴더 탐색은 Glob·Grep·Read와 desktop-commander 검색으로 하고, pptx 변환·영상 제작처럼 셸이 필요한 작업은 건너뛰고 이유를 적는다.
- `설교일시:`는 분량과 어조의 기준이다. 아래는 기본값이고, 회중 맥락에 분량이 적혀 있으면 그쪽을 따른다. 4~6단계 작업자 프롬프트에 그대로 넣는다.

| 설교일시 | 분량(낭독 기준) | 어조·구성 |
|---|---|---|
| 새벽 | 10~15분 · 대지 1~2개 | 짧은 본문 풀이 → 오늘 하루의 적용 하나 → 기도 제목으로 마무리 |
| 주일오전 | 30~40분 · 대지 3개 안팎 | 새신자도 따라올 수 있게 배경을 풀어 주고, 복음 제시를 빠뜨리지 않는다 |
| 수요일저녁 | 25~35분 | 성경공부에 가깝게 본문 설명의 비중을 높인다 |
| 금요기도회 | 15~25분 | 결단과 간구로 이어지게 하고, 끝에 합심기도 제목 3개를 붙인다 |
| 기타(직접 입력) | 입력값에서 추정, 모르면 25분 | 입력된 자리(장례·청년 집회 등)에 맞춘다 |

- `설교방법:`은 5단계의 구조 스킬과 짜임을 정한다. 블록의 `[설교문작성]`에 구조 스킬이 따로 적혀 있으면 그 스킬을 쓰되, 짜임은 아래를 따른다.

| 설교방법 | 구조 스킬 | 짜임 |
|---|---|---|
| 강해설교 | sermon-expository-daeji | 본문의 흐름이 곧 설교의 흐름. 대지는 본문 단락에서 나온다 |
| 대지설교 | sermon-expository-daeji | 한 문장 주제 + 우산질문 + 3대지. 대지끼리 병렬·점층 관계를 분명히 |
| 주제설교 | sermon-topic-message-coach(작성법: 주제별) | 주제를 여러 본문으로 세우되, 중심 본문 하나를 주해로 받친다 |
| 네러티브설교 | sermon-topic-message-coach(작성법: 내러티브) | 갈등 → 심화 → 반전(복음) → 해소. 대지 번호를 드러내지 않는다 |
| 변증설교 | sermon-doctrinal-planner(교리 변증과 오해 교정 단계 중심) | 회중의 실제 의문·반론을 먼저 세우고 본문으로 답한다. 반론은 허수아비로 만들지 않는다 |
| 기타(직접 입력) | 입력값에 가장 가까운 위 항목 | 입력값(교리설교면 sermon-doctrinal-planner 4단계) |

## 입력 (시작 시 한 번만 묻는다)

| 항목 | 필수 | 기본값 |
|---|---|---|
| 본문 (예: 롬 8:28-30) | B에 필수 | A 트랙 산출에서 받음 |
| 설교 유형: 강해 / 주제 / 교리 | 아니오 | 강해 |
| 신학자 코치: calvin / luther / augustine / bavinck / lloyd-jones | 아니오 | calvin |
| 회중 맥락 (교회·절기·특별한 상황) | 아니오 | pastor-foundation의 기본 맥락 |
| 자료층 R (아래 절) | 아니오 | 자동 감지된 것 전부 |
| 출력 폴더 | 아니오 | `~/Documents/설교연구/{본문}_{YYYY-MM-DD}/` (본문은 `롬8_28-30`처럼 공백·콜론 없이) |

빠진 항목은 한 번에 묶어 묻고, C 트랙의 두 질문 외에는 끝까지 다시 묻지 않는다. 확정된 입력값은 아래 형식으로 `00_진행상황.md` 맨 위에 적고, 모든 서브에이전트 프롬프트에 그대로 붙인다.

```
[입력값] 본문: … / 유형: … / 신학자: … / 회중 맥락: … / Logos: (사용|없음) / 주석폴더: (절대 경로들 또는 없음) / NotebookLM: (노트북 ID들 또는 없음) / 출력 폴더: …
```

신학자 코치 이름은 다음 스킬로 고정한다. calvin → sermon-calvin-style-insight (sermon-calvin-institutes 아님), luther → sermon-luther-coaching, augustine → sermon-augustine-coaching, bavinck → sermon-bavinck-coaching, lloyd-jones → sermon-lloyd-jones-coaching.

## 실행 절차

1. 진입 표로 범위를 정하고, R 점검을 돌려 `[입력값]`을 확정한다. 출력 폴더를 만들고 `00_진행상황.md`에 `[입력값]` 줄과 단계 체크리스트를 적는다.
2. B 1~3단계: 서브에이전트 템플릿으로 그 단계 작업자를 **한 메시지에서** 동시에 띄운다. 끝나면 **병합 서브에이전트** 1개가 산출 파일들을 읽어 중복을 지운 병합본을 쓴다. 병합본 맨 위에는 `## 핵심 발견` 5줄. 메인은 그 5줄만 읽고, 다음 단계 작업자 프롬프트에 넣어 준다. 자료층에서 온 내용은 병합본에서도 출처 표기를 유지한다.
3. B 4~6단계: 스킬 하나에 서브에이전트 하나씩 **순차로** 띄운다. 프롬프트에 직전 산출 파일과 `03_주해.md` 경로를 넣는다. 코치형 스킬이 사용자에게 질문하도록 돼 있어도, 서브에이전트가 앞 단계 파일과 `[입력값]`으로 답을 채워 자동 진행한다.
4. 단계가 끝날 때마다 `00_진행상황.md`에 `[x] N단계 완료 — 파일명`을 적고, 사용자에게 3줄 요약과 파일 링크만 보고한 뒤 바로 다음 단계로 간다. "계속할까요?"를 묻지 않는다.
5. 6단계 끝: 최종 파일 링크와 회중 피드백 상위 3개 우려를 보고하고, 곧바로 C-0·C-1에 들어간다.

## 이어서 하기

- "4단계부터"라고 하면 `00_진행상황.md`의 완료 표시와 앞 단계 병합본 존재를 확인한 뒤 그 단계부터 시작한다.
- 특정 단계만 다시 돌리면 그 단계 파일을 덮어쓰고, 이후 단계는 사용자가 말할 때만 다시 돌린다.
- 옛 5단계 구조로 만든 폴더(`01_본문연구.md`·`02_배경자료.md`·`05_설교문_최종.md`)를 만나면: 01+02를 1~3단계 완료로, `05_설교문_최종.md`를 `06_설교문_최종.md`로 간주하고 파일명은 바꾸지 않는다.

## 하지 않는 것

- 설교 스킬을 전부 부르지 않는다. 신학자 코치는 한 명, PBS 심화(pbs-graduate-study·pbs-personal-bible-study)와 sermon-research·sermon-brainstorm은 사용자가 이름을 말할 때만 해당 단계에 끼운다.
- 산출물 전문을 메인 대화에 붙이지 않는다. 병합도 서브에이전트가 한다.
- 서브에이전트가 실패하면 같은 프롬프트로 한 번만 재시도하고, 또 실패하면 그 스킬을 건너뛰고 `00_진행상황.md`에 이유를 적은 뒤 나머지로 계속한다.
- A의 본문 확인과 C의 두 질문 외에는 사용자에게 선택을 넘기지 않는다.
- 외부에 게시·전송하지 않는다 (블로그·유튜브·SNS·메일). NotebookLM 노트북을 새로 만들거나 지우지 않는다.

## 자주 하는 실수

| 실수 | 고침 |
|---|---|
| 1~3단계 작업자를 하나씩 순서대로 띄움 | 한 메시지에서 동시에 띄운다 |
| 코치 스킬의 질문을 사용자에게 전달하고 멈춤 | 서브에이전트가 앞 단계 파일로 답을 채운다 (직접 주해 트랙만 예외) |
| ask-exegesis 스킬을 서브에이전트로 자동 실행 | 인터뷰형이다. 직접 주해 트랙에서 메인 대화로만 부른다 |
| 메인 컨텍스트에서 산출 파일을 직접 읽어 병합 | 병합 서브에이전트에 맡기고 핵심 발견 5줄만 읽는다 |
| 구약 본문에 메이첸 헬라어 문법을 적용 | 구약은 sermon-bible-dictionary 원어 항목으로 대체한다 |
| 2단계와 3단계에서 multimethod에 같은 항목을 시킴 | 2단계는 구조·문학, 3단계는 원어·신학·역사문화 |
| 주석 폴더를 셸 글롭으로 훑어 한글 파일명을 놓침 | desktop-commander 검색 또는 python3 os.walk |
| Logos·NotebookLM 도구가 없는데 계속 재시도 | 한 번 안내 후 "없음"으로 확정하고 진행한다 |
| 자료층 검색 결과를 자료 순서대로 이어 붙임 | 질문별로 종합하고, 갈리는 해석은 나란히 적는다 |
| C-1에서 샘플 없이 "어떤 스타일로 할까요?"만 물음 | 샘플 3개를 먼저 만들어 보여 준 뒤 고르게 한다 |
