# Nintendo01 Deck — Y2K 콘솔 하드웨어형 발표자료 생성기

2001년 Nintendo.com의 디자인 시스템을 재현하는 스킬. 입력(원고·개요·자료)을 받아
**자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 원본 스펙의 표현: **"웹을 콘솔 하드웨어로 렌더한 것."**
> 모든 영역이 게임보이와 같은 사출 성형 플라스틱에서 찍혀 나온 **개별 베벨 판**이다.
> 판을 없애고 평평하게 만드는 순간 이 시스템은 사라진다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

1. **원고/자료** — 없으면 주제만 받아 개요부터 작성해 확인받는다
2. **챕터 수** — 챕터마다 히어로 필드 색(틸·레드·라벤더)을 배정한다. 2~4챕터가 적정
3. **밀도 취향** — 이 스타일은 **작고 조밀한 타이포가 정체성**이다. 큰 글씨를 원하면
   다른 스킬(bmw-m·nike)이 맞다는 점을 먼저 알린다
4. **출력** — 화면 발표(기본) / PPTX 변환 / PDF 인쇄

## 1. 스타일 토큰 (절대 변경 금지)

```css
/* 따뜻한 색 = 길찾기 전용. 장식으로 번지면 안 된다 */
--red:#e60012; --signal:#f68d1f; --amber:#ecab37; --gold:#e48600;
/* 금속판 계열 */
--canvas:#7a8aba; --sky:#9fbee7; --lavender:#acace7; --ice:#c0d5e6; --peri:#8ba1d4;
--indigo:#3d4f97;      /* 베벨 그림자선 */
--platinum:#dedede; --surface:#fff; --carbon:#21242e;
--ink:#21242e; --ink-soft:#3d4f97;
--teal:#206479; --games-red:#a7282b;   /* 섹션별 히어로 필드 */
```

**색 규칙 (위반 시 스타일 붕괴)**
- **따뜻한 색은 "여기를 눌러라"라는 뜻일 때만.** 내비골드=내비 단어, 앰버=유틸리티·배지,
  시그널 오렌지=전진/Submit. 장식으로 쓰면 길찾기 신호가 죽는다.
- 페리윙클 금속은 **단색이 아니라 세로 그라디언트**다(밝은 위 → 어두운 아래). 평면으로 칠하지 않는다.
- 레드는 로고와 오류 표시에만.

## 2. 베벨 규칙 — 이 시스템의 전부

모든 영역은 판이다. 판의 규격:

```css
border-top:3px solid rgba(255,255,255,.6);     /* 밝은 위 모서리 */
border-left:3px solid rgba(255,255,255,.32);
border-right:3px solid var(--indigo);          /* 크롬인디고 그림자 */
border-bottom:4px solid var(--indigo);
background:linear-gradient(180deg,#9aa9d0,#8494c2 40%,#7989b6);
```

- **흐린 드롭섀도 엘리베이션 언어를 도입하지 않는다.** 깊이는 하드 베벨과 사진뿐이다.
- 판 안에 판을 넣어도 좋다. 그것이 이 시대의 레이아웃 방식이다.
- 워드마크 그림자도 블러 0의 **하드 오프셋**(`text-shadow:3px 3px 0 var(--indigo)`)이다.

## 3. 타입 규칙

| 역할 | 크기(1920 스테이지) | 웨이트 | 자간 |
|---|---|---|---|
| 워드마크 h1 | 88px | **900** | 0 · 대문자 |
| 섹션 제목 h2 | 51px | 900 | 0 · 대문자 |
| 히어로 태그라인 | 30px | 700 | 0 |
| 내비 링크 | 26px | 700 | **+1px** · 대문자 |
| UI 라벨 | 22px | 700 | **+1px** · 대문자 |
| 링크·본문 | 24px | 700 / 400 | 0 |
| 미세 문구 | 20px | 400 | 0 |

- 표기 크기는 **원본 웹 토큰 × 2**(워드마크 44 → 88px).
  **이 값을 더 키우지 않는다** — 작고 조밀한 밀도가 2001년의 정체성이다.
- **구조 라벨은 대문자 Arial Bold + 0.5px(덱 1px) 트래킹.** 스펙의 표현대로
  "실크스크린 표기(silkscreen legend)의 목소리"다.
- **폰트**: 원본에는 웹폰트가 없다(Arial/Helvetica). 한글 글리프가 없으므로 Pretendard만 폴백으로
  싣는다. 미세 라벨에 시대감을 더하려면 **Silkscreen**(픽셀 서체)을 캡션·푸터에만 쓴다.
- **한글 워드마크는 행간 1.02에서 받침이 물린다.** 템플릿의 `h1.ko`(1.14)를 쓴다.

## 4. 슬라이드 아키타입 (8종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|---|---|---|---|
| Z1 | 표지 | 듀얼 내비 + 라벤더 히어로 판 + 워드마크 | 첫 장 |
| Z2 | 패널 그리드 | 라벨바 + 판 3~4개 | 항목 나열 |
| Z3 | 목록 + 우측 레일 | 뉴스 행 + 정보 박스 + 설문 판 | **주력** — 2001 포털 레이아웃 |
| Z4 | 수치 | 판 위 아웃라인 숫자 4개 | 지표 |
| Z5 | 컬러 히어로 필드 | 틸 / 레드 판 2분할 | 챕터 전환 |
| Z6 | 폼 패널 | 플래티넘 입력 판 + 설명 판 | 절차·참여 안내 |
| Z7 | 선언 | 카본 전면 + 워드마크 | 전환 (1~2회) |
| Z8 | 클로징 | 히어로 판 + 카본 푸터 + ESRB 배지 | 마지막 장 |

**리듬 규칙**
- **듀얼 내비를 한 줄로 합치지 않는다.** 계층 지휘 구조가 이 시스템의 서명이다.
  (표지는 2줄 다, 내부 장은 하단바만 유지해도 된다.)
- Z3(목록 + 레일)이 이 스타일이 가장 잘 사는 장이다. 정보 밀도를 두려워하지 않는다.
- 히어로 필드 색은 챕터마다 하나. 그 챕터 안에서는 바꾸지 않는다.

## 5. 원고 → 슬라이드 분해 규칙

1. **한 판 = 한 정보 단위.** 판 하나에 라벨 + 제목 + 본문 + 버튼까지 담는다.
2. 목록은 Z3 뉴스 행(날짜 + 제목 + 셰브런 칩)으로. 카드로 감싸지 않는다.
3. 부가 정보·주의사항은 우측 레일의 정보 박스(앰버 헤더 탭)에 넣는다.
4. 수치는 Z4에서 아웃라인 900으로 찍는다.
5. 마지막은 Z8, 카본 푸터로 닫는다.

## 6. 형태 규칙

- **모서리는 기본이 각짐/모따기**다. 둥근 것은 **로고 pill·라디오 점·원형 화살표 배지**뿐이다.
  전부 둥글게 만들면 정체성이 지워진다(스펙의 명시 금지 항목).
- 라운딩 사다리: 유틸 버튼 `--r-xs`(4px) → 작은 판 `--r-sm`(8px) → 콘텐츠 판 `--r-md`(12px)
  → 바깥 섹션 판 `--r-lg`(20px).
- 버튼도 판이다 — 위 밝은 모서리 + 아래 진한 모서리를 준다.

## 7. 모션 규칙 (CSS만)

- **하드 등장**(`steps(1)`). 2001년에는 트랜지션이 없었다. 부드러운 페이드를 넣지 않는다.
- 등장 간격 0.11s로 순차 표시만 유지한다.
- `@media print`: 애니메이션 해제, 슬라이드당 1페이지.

## 8. 빌드 절차

1. `template.html`을 골격으로 사용한다 — 토큰·베벨 판·듀얼 내비·8종 아키타입·발표자 노트 포함.
2. 원고를 5장 규칙으로 분해해 **슬라이드 시퀀스 표**(아키타입·판 색·라벨·제목·버튼)를 먼저 보여준다.
   **따뜻한 색이 버튼 외에 쓰이지 않는지 여기서 확인한다.**
3. `<section class="slide">` 단위로 생성. 판 색은 `.plate.light` / `.lav` / `.teal` / `.red` 등으로 건다.
4. **발표자 노트**는 `data-note` 속성(HTML 태그 가능, `"` 금지). `S` 토글, 기본 숨김.
5. `{주제}-deck.html`로 저장. **PPTX 변환**은 `../monoline-deck/deck2pptx.py` 공유.
6. **검증**: 첫·중간·마지막 장을 캡처해 점검한다 —
   ① 모든 모서리를 둥글게 만들었는가 ② 흐린 드롭섀도가 들어갔는가
   ③ 앰버·오렌지가 장식으로 번졌는가 ④ 듀얼 내비를 한 줄로 합쳤는가
   ⑤ 판이 평면 단색이 됐는가(그라디언트 유지) ⑥ 타이포를 원본보다 크게 부풀렸는가.

**함정**
- 한글 파일명은 Edge 헤드리스 캡처가 안 된다. 스크래치패드에 ASCII 이름으로 복사해 찍는다.
  `--user-data-dir`을 새로 주면 Edge 새 탭이 찍히므로 쓰지 않는다.
- **한글은 Arial에 없어 Pretendard로 떨어진다.** 대문자 트래킹의 "실크스크린" 인상은 영문에서만
  나오므로, 라벨·내비는 **영문으로 두는 편이 원본에 가깝다**(HOME · SECTION 01 …).
- 판을 중첩할 때 안쪽 판의 베벨을 얇게(2px) 하지 않으면 테두리가 뭉쳐 보인다.

## 9. 조작법 (생성물 안내에 포함할 것)

- `→` / `Space` 다음, `←` 이전, `Home`/`End` 처음·끝, 화면 좌우 클릭·스와이프
- **`S` 발표자 노트 토글** (기본 숨김)
- `#3` 해시로 특정 장 직행, `?shot#3`은 캡처 모드
- 브라우저 인쇄(Ctrl+P, 가로)로 PDF 출력
