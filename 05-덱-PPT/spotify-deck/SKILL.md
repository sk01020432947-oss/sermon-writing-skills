# Spotify Deck — 다크 몰입형 발표자료 생성기

Spotify 웹 플레이어의 디자인 시스템을 재현하는 스킬. 입력(원고·개요·자료)을 받아
**자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 원본 스펙의 철학: **"콘텐츠 우선의 어둠."** UI는 그림자 속으로 물러나고
> 앨범아트가 유일하게 빛난다. 화면을 밝히거나 색을 더하려는 시도가 이 시스템을 깨뜨린다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

1. **원고/자료** — 없으면 주제만 받아 개요부터 작성해 확인받는다
2. **아트 이미지** — 이 시스템에서 **색은 전부 아트 타일에서 나온다.** 주제 이미지가 있으면
   그 색을 상단 글로우(`--art`)에 그대로 쓴다. 없으면 템플릿의 그라디언트 타일이 대신한다
3. **출력** — 화면 발표(기본) / PPTX 변환 / PDF 인쇄

## 1. 스타일 토큰 (절대 변경 금지)

```css
--green:#1ed760;   /* 기능색. 재생·활성·주 CTA에만 */
--canvas:#121212; --s1:#181818; --s2:#1f1f1f;   /* 근사흑 3단 */
--card:#252525; --card2:#272727;
--border:#4d4d4d; --border-light:#7c7c7c; --light:#eee;
--white:#fff; --silver:#b3b3b3; --near:#cbcbcb;
--shadow:rgba(0,0,0,.4) 0 16px 16px;   /* 어두운 면에서는 진해야 보인다 */
```

**색 규칙 (위반 시 스타일 붕괴)**
- **초록을 장식이나 배경으로 쓰지 않는다.** 재생 버튼·활성 상태·주 CTA 전용이다.
  숫자·제목·아이콘을 초록으로 칠하는 순간 기능색이 장식색으로 떨어진다.
- **밝은 배경을 주 화면으로 쓰지 않는다.** 어둠 속 몰입이 시스템의 핵심이다.
- 초록 + 무채색 회색이 팔레트의 전부다. 추가 브랜드색을 도입하지 않는다.
- **회색 테두리를 노출하지 않는다.** 면 밝기 차이와 그림자로 경계를 만든다.
- **얕은 그림자를 쓰지 않는다.** 어두운 배경에서는 0.3~0.5 불투명도가 필요하다.

## 2. 타입 규칙 — 조밀함

| 역할 | 크기(1920 스테이지) | 웨이트 | 비고 |
|---|---|---|---|
| **덱 히어로 (확장)** | 112px | 700 | 아래 '스케일 확장' 참조 |
| 섹션 타이틀 | 48px | 700 | 원본 최대 토큰(24px) × 2 |
| 기능 헤딩 | 36px | 600 | 행간 1.30 |
| 본문 | 32px | 400 | 행간 1.4 |
| 캡션 | 28px | 400/700 | |
| 대문자 버튼 | 28px | 600 | **자간 +2.8px** · 대문자 |
| 배지·미세 | 20~24px | 400/700 | |

> **스케일 확장 알림:** 원본은 앱 UI라 **최대 타입이 24px**이고 스펙이 "잡지가 아니라 앱이니
> 10~24px 범위를 지켜라"라고 명시한다. 1920 덱 표지에는 48px이 약해 **112px 히어로를 확장**했다.
> 이 확장은 표지·선언 두 곳에만 쓰고, 나머지는 원본 × 2를 지킨다.

- **느슨한 행간을 쓰지 않는다.** 이 시스템의 타이포는 조밀하고 빽빽하다.
- 대문자 버튼 라벨의 넓은 자간(1.4~2px, 덱 2.8px)이 이 브랜드의 버튼 표식이다.
- **폰트**: SpotifyMixUI는 사유 폰트다. Circular 계열 대체로 Inter, 한글은 Pretendard.

## 3. 슬라이드 아키타입 (8종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|---|---|---|---|
| S1 | 표지 | 아트 글로우 + 칩 + 원형 재생 | 첫 장 |
| S2 | 아트 카드 그리드 | 4-up, 강조 카드에 초록 FAB | **주력** — 항목 나열 |
| S3 | 2단 큰 아트 + 목록 | 좌 텍스트 / 우 트랙 행 | 순서·구성 |
| S4 | 수치 | 카드 4-up, 흰 숫자 | 지표 |
| S5 | 필터 + 목록 | 칩 + 검색 pill + 행 | 분류·탐색 |
| S6 | 선언 | 글로우 전면 + 중앙 문장 | 전환 (1~2회) |
| S7 | 설명 카드 3-up | `--card`(#252525) 면 | 개념 설명 |
| S8 | 클로징 | 초록 pill 하나 | 마지막 장 |

**리듬 규칙**
- 배경은 `--canvas` / `--s1` / `--s2`를 오가며 밝기 차이로만 구간을 나눈다.
- **초록은 덱 전체에서 5~6회 이하.** 표지 재생, 강조 카드 FAB, 선언 CTA, 클로징 CTA 정도.
- 아트 글로우 색은 챕터마다 바꾸되, 한 장에 한 색이다.

## 4. 원고 → 슬라이드 분해 규칙

1. **한 카드 = 한 항목**(제목 한 줄 + 메타 한 줄). 카드에 문단을 넣지 않는다.
2. 순서가 있는 내용은 S3 트랙 목록 형식이 가장 잘 맞는다(번호·썸네일·제목·부제·시간).
3. 수치는 S4, 분류·탐색은 S5.
4. 마지막은 S8, 초록 pill 하나.

## 5. 형태 규칙

- **모든 버튼은 pill(500px), 재생만 원형(50%).** 사각 버튼은 정체성을 깬다.
- 카드 라운딩은 6~8px(덱 12~16px)로 **작게** 유지한다. 크게 굴리면 다른 브랜드가 된다.
- 원형 아트는 인물·팟캐스트용이다. 일반 항목에는 사각 아트를 쓴다.
- 활성 칩은 **밝은 면(#eeeeee) + 어두운 글자**다. 초록으로 칠하지 않는다.

## 6. 모션 규칙 (CSS만)

- 페이드 + 16px 상승, 0.5s, 간격 0.08s. 짧고 매끈하게.
- 글로우는 정지시킨다. 색이 움직이면 몰입이 깨진다.
- `@media print`: 애니메이션 해제, 슬라이드당 1페이지.

## 7. 빌드 절차

1. `template.html`을 골격으로 사용한다 — 토큰·8종 아키타입·아트 글로우·발표자 노트 포함.
2. 원고를 4장 규칙으로 분해해 **슬라이드 시퀀스 표**(아키타입·배경 단계·글로우 색·제목)를
   먼저 보여준다. **초록 등장 횟수를 이 표에서 센다.**
3. 아트는 `.art`/`.thumb`/`.bigart`에 `--art:url(...)`, 글로우는 `.glow`에 `--art:#색`으로 건다.
4. **발표자 노트**는 `data-note` 속성(HTML 태그 가능, `"` 금지). `S` 토글, 기본 숨김.
5. `{주제}-deck.html`로 저장. **PPTX 변환**은 `../monoline-deck/deck2pptx.py` 공유.
6. **검증**: 첫·중간·마지막 장을 캡처해 점검한다 —
   ① 초록이 숫자·제목·배경에 칠해졌는가 ② 밝은 배경 장이 생겼는가
   ③ 사각 버튼이 있는가 ④ 그림자가 얕아 안 보이는가
   ⑤ 회색 테두리가 노출됐는가 ⑥ 행간이 느슨해졌는가.

**함정**
- 한글 파일명은 Edge 헤드리스 캡처가 안 된다. 스크래치패드에 ASCII 이름으로 복사해 찍는다.
  `--user-data-dir`을 새로 주면 Edge 새 탭이 찍히므로 쓰지 않는다.
- **아트가 하나도 없으면 이 덱은 무채색 회색 덱이 된다.** 색을 넣고 싶어도 초록을 늘리지 말고
  **아트 타일(또는 글로우 색)을 늘린다.** 이것이 이 시스템이 색을 얻는 유일한 통로다.
- 프로젝터가 밝은 회의실이면 #121212와 #181818의 차이가 사라진다. 그런 현장에서는
  카드 배경만 `--card`(#252525)로 한 단계 올려 대비를 확보한다.

## 8. 조작법 (생성물 안내에 포함할 것)

- `→` / `Space` 다음, `←` 이전, `Home`/`End` 처음·끝, 화면 좌우 클릭·스와이프
- **`S` 발표자 노트 토글** (기본 숨김)
- `#3` 해시로 특정 장 직행, `?shot#3`은 캡처 모드
- 브라우저 인쇄(Ctrl+P, 가로)로 PDF 출력
