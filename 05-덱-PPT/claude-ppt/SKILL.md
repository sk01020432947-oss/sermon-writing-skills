# claude-ppt — 클로드 톤 IR 슬라이드

출처: 우석지니 「컨설턴트의 클로드 PPT 작성법」 워크플로 + 실제 산출물 PDF에서 추출한 실측 팔레트.

## 전제

- 산출물은 **16:9 .pptx**. `references/claude_ppt_engine.py`(python-pptx)로 직접 그린다.
- 캔버스 기준 좌표계는 **1000 × 563 px**(= 13.333 × 7.5 in, 1px = 1/75in).
- **모든 슬라이드에 발표자 노트를 넣는다.** 슬라이드에서 잘라낸 근거의 자리다.
- **눈으로 검증한다** — 만든 뒤 PDF로 렌더해(`soffice --headless --convert-to pdf`) 대표 슬라이드를 직접 본다. 좌표만 맞추고 넘기면 그림자·경계·모서리 결함을 놓친다.
- **AI 결과물은 초안이다.** 마지막 파워포인트 마감(STEP 4)까지 해야 완성이다.

## 워크플로 (4단계)

### STEP 1 · 데이터 정교화

슬라이드를 그리기 전에 아래 5개를 확정한다. 사용자가 안 주면 **물어본다.** 추정 금지.

1. **목적** — 이 장표로 무엇을 얻으려 하는가 (투자 유치 / 신뢰 회복 / 성장 증명)
2. **대상** — 주주·투자자 / 이사회 / 고객사
3. **대상이 알고 싶은 것** — 성장률, 수익성 전환 시점, 런웨이
4. **대상이 알아야 할 것** — 비용 구조, 리스크, 캡엑스 부담
5. **숫자의 의미** — 각 수치가 어떤 논리로 이어지는지 (흐름이 보여야 설득이 빨라진다)

각 슬라이드의 **거버닝 메시지 한 줄**을 여기서 먼저 쓴다. 차트는 그 문장의 증거다.

### STEP 2 · 레퍼런스 등록

- 참고 덱은 **PPTX 말고 PDF로 받는다** — 파싱 시간·토큰이 몇 배 차이난다.
- 브랜드 톤은 **고객사 홈페이지에서 뽑는다.** 배경색·카드색·메인/서브 컬러를 직접 집어 팔레트를 만든다.
- 만들 **타입을 5~7개로 먼저 확정**한다(아래 타입 카탈로그). 타입 모듈만 있으면 장표 수는 무한히 늘릴 수 있다.

### STEP 3 · 샘플 1장 완벽화 → 스킬화 → 증분 확장

**순서를 지킨다. 처음부터 전체를 만들지 않는다.**

1. 대표 타입(보통 차트 2분할) **한 장**만 만든다.
2. 만족할 때까지 그 한 장만 고친다 — 배경/폰트/여백/카드 높이/차트 요소 제거.
3. 확정되면 그 결과를 **스킬 MD로 저장**한다.
4. 이후 타입 2·3장씩 증분으로 늘린다.
5. 대화가 길어지면 끊고, 스킬 MD 갱신 + pptx 저장 후 새 창에서 재개한다.

**토큰 절약 4원칙**
- 직접 할 수 있는 건 요청하지 않는다 (파일 합치기·페이지 순서는 파워포인트에서 한다).
- 둥근 모서리 차트 같은 욕심을 부리지 않는다 — 동일 작업 대비 4~5배를 태운다. **차트 막대는 직각.**
- 샘플 1장 완벽화 후에만 확장한다.
- 후반 잡일(합치기, 미세 정렬)은 파워포인트로 넘긴다.

### STEP 4 · 파워포인트 마감 체크리스트

AI 산출물에서 **반드시 남는 결함**: 차트 중간값 누락, 0 기준선 어긋남, 카드/도형 미세 어긋남, 내용 넘침.

- [ ] 여러 pptx 병합 + 페이지 순서
- [ ] 톤앤매너 이탈 색상(너무 진하거나 밝은 값) 교정
- [ ] 폰트·여백·행간·자간 일관성
- [ ] 배색으로 가독성(읽힘)과 시인성(보임) 확보
- [ ] 헤더/푸터 — 로고, 브레드크럼, 페이지 번호 일관 처리
- [ ] 로고는 **SVG를 삽입**한다 (텍스트로 회사명 타이핑 금지, 크기·색 자유)
- [ ] 헤드라인 행간 **0.85~0.9** — 제목이 덩어리로 붙어 단단해진다
- [ ] 차트 하나만 있는 페이지는 **배경 카드를 빼는 게 낫다**
- [ ] 표는 왼쪽 여백을 넉넉히 — 당겨 읽힌다
- [ ] **표 경계 검사** — 행 구분선이 있는가, 헤더 아래와 마지막 행 아래가 닫혀 있는가, 진한 zebra 밴드가 배경과 부딪히지 않는가
- [ ] 한쪽은 비워둔다. 양쪽을 대칭으로 꽉 채우면 답답하다

## 디자인 토큰 (실측)

```
--bg          #F0EEE6   본문 배경 (연한 베이지, 흰색 금지)
--bg-alt      #F7F4EE   최연한 면
--card        #E3DACC   카드 면
--card-2      #DDD6CE   보조 카드 / 표 헤더행
--dark        #1C1810   표지·엔딩 배경 (잉크 브라운)
--main        #CF6B4A   메인 테라코타 (강조 수치, 로고, 강조 열)
--main-deep   #A5472A   진한 오렌지 (누적 차트 최하단, 큰 비중)
--main-soft   #E08B6A   중간 오렌지
--main-pale   #EDCBB8   연한 오렌지 (누적 차트 상단)
--tint        #EAD6CC   강조 열 배경 틴트
--gray        #B5ADA7   비교/전년 데이터 막대
--rule        #D0C9C2   구분선
--ink         #1C1810   본문 텍스트
--ink-2       #4A4540   보조 텍스트
--ink-3       #8A837C   캡션·축 라벨·각주
--pos         #3D6B45   증가/개선 (녹색)
--neg         #A03030   악화 (적색, 아껴 쓴다)
```

**색 사용 규칙** — 메인 테라코타는 "지금 말하려는 것" 하나에만. 비교 대상은 전부 `--gray`. 한 슬라이드에 테라코타가 3덩어리 넘으면 강조가 사라진다.

**폰트** (시스템 폰트만 — 없는 폰트는 깨진다)

| 용도 | 폰트 | 크기/스타일 |
|---|---|---|
| 헤드라인 | Trebuchet MS Bold | 34px / line-height 0.9 |
| 거버닝 메시지 | Georgia Italic | 14px / `--ink-2` |
| 표지 대제목 | Trebuchet MS Bold | 68px / line-height 0.85 |
| KPI 수치 | Trebuchet MS Bold | 40~46px |
| 본문·표 | Trebuchet MS | 12~14px |
| 라벨·각주 | Trebuchet MS | 10~11px / `--ink-3` |
| 한글 | Pretendard → 맑은 고딕 | 위 크기 −1px |

**레이아웃 상수**: 좌우 여백 45px · 상단 헤더 바 32px · 헤드라인 top 55px · 거버닝은 헤드라인 **바로 아래 붙인다**(간격 8px, 벌리면 벙벙해진다) · 카드 radius 6px · 카드 간격 20px · 각주 bottom 22px.

**액센트 카드 — 3조각 규칙** (레퍼런스 KPI 카드의 형태, 반복 검증 완료)

카드 radius 6px. 컬러 바는 **카드 위에 막대를 얹는 방식으로는 절대 맞지 않는다.** 얹으면 모서리 곡선 구간에 색이 닿지 않아 직선 구간만 칠해진 것처럼 보이고, 둥근 카드를 컬러 카드 위에 겹치면 반대로 옆구리로 색이 번진다. **조각 셋으로 쌓는다.**

상단 바 카드 — 바 7px, radius 6:
1. 액센트: 위 두 모서리만 둥근 면(`round2SameRect`) `(x, y, w, 2r+bar)` — 높이를 넉넉히 잡아야 radius가 카드와 같아진다
2. 몸통: **네 변이 곧은** 사각형 `(x, y+bar, w, h-bar-2r)` → 바와의 경계가 가로 직선
3. 하단: `round2SameRect` `(x, y+h-2r, w, 2r)` + **회전 180°** → 아래 두 모서리만 둥글게

좌측 바 카드 — 바 4px, radius 5: 같은 구성을 90° 돌린 것.
1. 액센트: `round2SameRect` + 회전 270° (visual box `(x, y, bar+2r, h)`)
2. 몸통: 곧은 사각형 `(x+bar, y, w-bar-2r, h)` → 세로 직선 경계
3. 우측: `round2SameRect` + 회전 90° (visual box `(x+w-2r, y, 2r, h)`)

**회전 90/270°는 가로세로가 바뀐다** — 도형을 만들 때 w/h를 미리 뒤집고 중심을 맞춰 배치할 것(아래 구현 레시피 참조).

색은 채도를 낮추지 않는다 — `--main` / `--main-deep`을 그대로 쓴다. 예외: 슬라이드 가장자리까지 흐르는 풀블리드 바(표지 좌측)는 각진 채로 둔다.

**차트 규칙**
- 막대는 **직각**. 세로 기준선 없음. 가로 그리드만 옅은 점선.
- 눈금은 최소, 필요 없으면 축 전부 제거. 값은 막대 위에 직접 라벨링.
- 성장률·마진 같은 부가 지표는 **차트 밖이 아니라 카드 안쪽 하단 스트립**에 넣는다.
- 범례는 하단 중앙, 12px 색상칩 + 10px 라벨.
- 0 기준선은 반드시 0에 맞춘다(AI가 자주 틀린다 — STEP 4에서 검증).

**발표자 노트 (모든 슬라이드 필수)**

슬라이드는 근거를 다 담지 못한다. 잘라낸 근거는 버리지 말고 노트로 내린다.

- **모든 슬라이드에 노트를 넣는다.** 표지·엔딩도 예외 없다.
- 노트는 요약이 아니라 **원문·원데이터 그대로**. 슬라이드에 한 문장만 올렸다면 노트에는 그 문단 전체를 넣는다.
- 구조는 `소제목(9.5pt Bold `--main-deep`) + 본문(9.5pt `--ink`)`의 반복. 줄 간격 1.22.
- **노트 마스터부터 고친다.** 개별 노트 슬라이드만 고치면 뷰에 따라 마스터의 넓은 기본 폭을 따라가 노트가 슬라이드 밖으로 밀려난다. `notesSz`를 7.5 × 10in로 못박고, 노트 마스터의 SLIDE_IMAGE·BODY placeholder를 아래 좌표로 맞춘 뒤 각 노트 슬라이드에 같은 좌표를 적용한다.
- **노트 페이지의 슬라이드 축소본을 먼저 16:9로 고친다.** 기본 축소본은 4:3(1.25 / 0.75 / 5.0 × 3.75in)이라 16:9 덱에서는 축소본과 노트 상자의 좌우 끝선이 어긋나 노트가 슬라이드 밖으로 튀어나온다. 축소본 `0.75 / 0.55 / 6.0 × 3.375in`, 노트 상자 `0.75 / 3.95 / 6.0 × 5.55in` — **좌우 끝선을 같은 자리에 맞춘다**(노트 페이지 7.5 × 10in 기준).
- 슬라이드당 **1,900자 상한**. 9.5pt 기준으로 노트 페이지 한 장에 들어가는 분량이며, 넘치면 `…`로 끊는다. 중요한 것을 앞에 둔다 — 잘리는 쪽은 항상 꼬리다.
- Alt+F5 발표자 보기와 「보기 → 노트 페이지」는 **같은 텍스트**를 쓴다. 발표자 보기는 스크롤되지만 노트 페이지는 잘리므로, 분량 기준은 노트 페이지에 맞춘다.
- PowerPoint 발표자 보기는 **Alt+F5**(처음부터) 또는 슬라이드쇼 중 우클릭 → 발표자 보기 표시. **단축키는 재지정할 수 없다** — `S`로 열고 싶다면 pptx가 아니라 reveal.js 계열 HTML 덱으로 만들어야 한다(그쪽은 `S`가 발표자 창 기본값).

## 구현 레시피

**.pptx는 python-pptx로 직접 그린다.** HTML→pptx 변환은 이 팔레트·좌표계에서 도형이 어긋나므로 쓰지 않는다.

`references/claude_ppt_engine.py` — 검증된 최소 엔진. 복사하거나 그대로 import 해서 쓴다. 담긴 것:

| 함수 | 하는 일 |
|---|---|
| `px(n)` | 1000 × 563px 좌표 → EMU (1px = 1/75in) |
| `slide(bg)` | 배경 깐 빈 슬라이드 |
| `rect(...)` | 사각/둥근/위-두-모서리 면 + **테마 그림자 제거**(`<p:style>` 삭제까지) |
| `card_top_bar` | 상단 액센트 카드 3조각 |
| `card_left_bar` | 좌측 액센트 카드 3조각 (회전 보정 포함) |
| `text(...)` | 문단 단위 서식 + 한글 `<a:ea>` 글꼴 지정 |
| `notes(...)` | 노트 마스터·축소본·노트 상자 폭까지 맞춘 발표자 노트 |

**빠지기 쉬운 함정 넷** — 전부 이 엔진에서 이미 처리되어 있다.
1. 도형 그림자: `shadow.inherit = False`만으로 안 꺼진다. `<p:style>`의 `effectRef`까지 지워야 한다.
2. 한글 글꼴: `font.name`만 지정하면 안 먹는다. `<a:ea>` / `<a:cs>` typeface를 직접 넣는다.
3. zebra 밴드: 나중에 그린 밴드가 앞 행의 구분선을 덮는다. 선만 쓰는 쪽이 안전하다.
4. 회전 90/270°: 가로세로가 바뀐다. w/h를 미리 뒤집고 중심을 맞춰 배치한다.

## 타입 카탈로그

**Type 0 · 표지 (다크)**
`--dark` 풀배경. 좌측 상단 워드마크(`--main`) + 그 아래 1px 헤어라인. 대제목 2줄(68px, lh 0.85), 부제(연도)는 `--main`. 그 아래 Georgia Italic 한 줄. 얇은 구분선 뒤 디스클레이머 2줄(`--ink-3` 10px). 좌하단 날짜. **우측 1/3에 KPI 3개 세로 스택** — 라벨(11px) / 수치(40px, `--main`) / 증감(11px, `--pos`), 각 항목 아래 구분선. 좌측 세로 4px 액센트 바.

**Type 1 · 하이라이트 (KPI 5카드)**
헤더 바: 좌 `문서명 | 번호`, 우 워드마크, 아래 1px 라인. 헤드라인 + 거버닝 1줄. 그 아래 **동일폭 카드 5개**(간격 20px): 상단 7px 컬러바(위 3조각 규칙, `--main` 또는 `--pos`로 방향 표시) / 중앙 라벨(12px) / 대형 수치(44px, 세로 중앙) / 캡션(10px, `--ink-3`) / 하단 구분선 + 증감(12px 컬러). 하단 각주.

**Type 2 · 테이블 (요약 재무제표 / 목록)**

*경계가 표를 만든다 — 채움이 아니라 선으로 행을 나눈다.*

- **행 구분선이 기본.** 각 행 아래 0.8px `--rule`. 이것 없이 음영만으로 행을 나누지 않는다.
- **표의 시작과 끝을 닫는다.** 헤더행 아래 1.6px `--ink-2`, 마지막 행 아래 1.6px `--rule`. 표가 어디서 끝나는지 눈에 보여야 한다.
- **zebra는 기본적으로 쓰지 않는다.** 도형을 순서대로 쌓는 방식(python-pptx·HTML 캔버스 모두)에서 **다음 행의 밴드가 앞 행의 구분선을 덮어** 선이 한 칸 걸러 사라진다. 굳이 쓰려면 밴드를 **전부 먼저** 그리고 구분선을 나중에 그리며, 색은 `--bg-alt`만 쓴다. `--card`처럼 진한 면은 배경과 부딪혀 경계가 색 덩어리로만 읽힌다.
- **도형 그림자를 반드시 끈다.** 행마다 그림자가 깔리면 행이 겹쳐 보이고 표의 끝이 뭉개진다. python-pptx에서는 `shadow.inherit = False`만으로 부족하고 도형의 `<p:style>`(테마 `effectRef`)까지 제거해야 사라진다. 카드·칩 등 모든 도형에 동일 적용.
- **행 높이는 32~44px 고정.** 행 수가 적다고 늘리지 않는다 — 늘리면 셀 텍스트가 상하로 떠 보인다. 남는 세로 공간은 표 아래 여백으로 둔다.
- **열은 정렬 기준선으로 구분한다.** 세로 괘선을 긋지 말고 열 간격을 최소 24px 두어 나눈다. 텍스트 열은 좌정렬, 숫자 열만 우정렬, 음수는 괄호.
- 헤더행 채움 `--card-2`, 헤더 글자 `--main-deep` Bold 9.5px. **헤더행은 위 두 모서리만 둥글게**(`round2SameRect`, radius 6px / 아래 모서리 0) — 아래는 본문 행과 붙어야 하므로 각지게 둔다. 카드 상단의 4px 컬러 바도 같은 방식(radius 2px).
- **강조 열**은 헤더 셀만 `--main` + 흰 글자, 본문 셀은 `--tint`로 옅게. 강조 열은 한 슬라이드에 하나만.
- 소계·합계 행은 Bold + `--card` 음영 + 위쪽 1.2px `--ink-2` 경계선.
- 셀 좌측 패딩 14~18px. 증감 열은 `--pos`/`--neg`. 좌하단에 단위 표기.

**Type 3 · 차트 2분할**
좌우 `--card` 카드 2개(각 452px). 카드 안: (선택)소제목 12px → 차트 영역 → 하단 구분선 → 요약 스트립(`라벨 · 값` 2~3쌍, 값은 `--main`/`--pos`). 좌우 카드의 차트 종류는 달라도 된다(막대 vs 워터폴, 막대 vs 표).

**Type 4 · 차트 단독 (풀 와이드)**
**배경 카드 없이** `--bg` 위에 바로 큰 차트. 누적 막대는 아래부터 `--main-deep` → `--main` → `--main-pale`, 세그먼트 값은 막대 안에 흰/잉크 글자로. 최신 열 위에 총합(20px Bold)과 성장률(`--pos`)을 콜아웃. 범례 하단 중앙.

**Type 5 · 혼합 (차트 + 지표 리스트)**
좌 카드는 차트, 우 카드는 가로 바 게이지 리스트(라벨 / 트랙 `--card-2` / 채움 `--main` 또는 `--gray` / 값) + 하단에 구성비 100% 스택 바 1줄 + 범례. 비중·인텐시티 표현 전용.

**Type 6 · 엔딩 (다크)**
`--dark` 풀배경, 중앙 워드마크(`--main`) + Georgia Italic 한 줄. 그 외 아무것도 두지 않는다.

## 발동 시 진행 순서

1. STEP 1의 5개 항목을 확인/질문한다.
2. 원자료가 있으면 **먼저 구조를 추출해 JSON으로 떨군다**(제목·본문·인용·질문). 슬라이드는 그 JSON에서 조립한다 — 원문을 요약하거나 다시 쓰지 않는다.
3. 필요한 타입을 골라 목차(슬라이드별 타입 + 거버닝 메시지)를 먼저 제시하고 승인받는다.
4. `references/claude_ppt_engine.py`를 가져와 **대표 1장만** 만들고, PDF로 렌더해 눈으로 확인받는다.
5. 승인 후 나머지를 증분 생성한다. 슬라이드마다 발표자 노트를 함께 채운다.
6. STEP 4 체크리스트를 사용자에게 남긴다 — 마감은 사람이 한다.
