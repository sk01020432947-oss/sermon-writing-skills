# Apple Deck — 제품 페이지형 발표자료 생성기

apple.com 제품 페이지의 디자인 시스템을 재현하는 스킬. 입력(원고·개요·자료)을 받아
**자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 이 시스템의 힘은 더한 것이 아니라 **덜어낸 것**에서 나온다.
> 악센트는 파랑 하나, 그림자는 제품 이미지 한 곳, 구분선은 색 전환 하나뿐이다.
> 무언가를 추가하고 싶어질 때마다 그것이 위 셋 중 하나인지 확인한다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

1. **원고/자료** — 없으면 주제만 받아 개요부터 작성해 확인받는다
2. **제품/피사체 이미지** — 있으면 히어로에 넣는다. 없어도 성립하지만
   **이 스타일에서 이미지가 없으면 타이포 하나로 화면을 버텨야 하므로 문장이 더 짧아져야 한다**
3. **출력** — 화면 발표(기본) / PPTX 변환 / PDF 인쇄

## 1. 스타일 토큰 (절대 변경 금지)

```css
--primary:#0066cc;  /* 액션 블루. 모든 상호작용이 이 색 하나다 */
--focus:#0071e3;    /* 포커스 링 */
--sky:#2997ff;      /* 다크 타일 위 링크 전용. 밝은 면에 쓰면 안 된다 */
--canvas:#fff; --parchment:#f5f5f7; --pearl:#fafafc;
--tile1:#272729; --tile2:#2a2a2c; --tile3:#252527;  /* 어두운 타일 3단 미세차 */
--void:#000;        /* 글로벌 내비·영상 배경에만. 타일 배경으로 쓰지 않는다 */
--ink:#1d1d1f; --ink80:#333; --ink48:#7a7a7a;
--hairline:#e0e0e0;
--product-shadow:rgba(0,0,0,.22) 6px 10px 60px;  /* 제품 이미지 전용 */
```

**색 규칙 (위반 시 스타일 붕괴)**
- **두 번째 악센트를 도입하지 않는다.** 링크·버튼·포커스·강조가 전부 `--primary` 하나다.
- 다크 타일 위 링크는 `--sky`, 밝은 면은 `--primary`. **서로 바꿔 쓰지 않는다.**
- 순검정(#000)은 타일 배경이 아니다. 어두운 타일은 #272729다.
- 그라디언트 배경을 만들지 않는다. 분위기는 사진이 만든다.

## 2. 타입 규칙

| 역할 | 크기(1920 스테이지) | 웨이트 | 자간 |
|---|---|---|---|
| 히어로 h1 | 112px | 600 | **-0.56px** |
| 타일 헤드라인 h2 | 80px | 600 | 0 |
| 섹션 h3 | 68px | 600 | -0.75px |
| 리드 | 56px | 400 | +0.4px |
| 에어리 리드 | 48px | **300** | 0 |
| 본문 | 34px | 400 | -0.75px · 행간 **1.47** |
| 캡션 | 28px | 400 | -0.45px |
| 버튼(대) | 36px | **300** | 0 |

- 표기 크기는 **원본 웹 토큰 × 2**(히어로 56 → 112px). 자간도 함께 2배다.
- **웨이트 500을 쓰지 않는다.** 이 시스템의 사다리는 300 / 400 / 600 / 700뿐이다.
- 본문 행간을 1.47 아래로 조이지 않는다. 조이는 순간 밀도가 생기고 이 스타일이 아니게 된다.
- 디스플레이는 **음수 자간**이 정체성이다. 한글에도 그대로 적용한다.
- **폰트**: SF Pro는 배포 폰트가 아니다. Windows·Android에서는 Pretendard가 대체하며
  한글도 함께 받는다. 스택 순서(SF Pro → Pretendard)를 바꾸지 않는다.

## 3. 화면 구조 (16:9 / 1920×1080 고정)

```
┌────────────────────────────────────────────┐
│                                            │  ← 상하 --sec(160px) 여백
│              헤드라인 600 112px             │  ← 중앙 정렬이 기본 자세
│                리드 한 줄                    │
│         자세히 보기 ›   구입하기 ›            │  ← 파란 링크, 화살표 글리프
│              [ 제품 이미지 ]                 │  ← 그림자는 여기에만
│                                            │
└────────────────────────────────────────────┘
```

- 좌우 기준선 `--xxl`(96px), 상하 `--sec`(160px). **여백이 이 시스템의 주재료다.**
- 왼쪽 정렬은 수치·표·카드 그리드에서만 쓴다. 서사 슬라이드는 전부 중앙 정렬.

## 4. 슬라이드 아키타입 (8종 — 이 중에서만 조합)

| 코드 | 이름 | 배경 | 사용 시점 |
|---|---|---|---|
| A1 | 제품 히어로 | 밝은 타일 | 표지·제품 소개 (가장 자주) |
| A2 | 다크 타일 | `--tile1` | 밝은 타일 다음. 색 전환이 곧 챕터 전환 |
| A3 | 2분할 타일 | 밝음 + 어두움 | 두 제품·두 관점 |
| A4 | 수치 | parchment | 지표 3~4개, 헤어라인으로만 분할 |
| A5 | 카드 그리드 | 밝음/어두움 | 기능 3개 |
| A6 | 선언 | `--tile2` | 챕터 끝·결론 |
| A7 | 비교 | 밝음 | 항목 비교, 가로 헤어라인만 |
| A8 | 클로징 | parchment | pill CTA + 푸터 |

**리듬 규칙 — 이 시스템의 핵심**
- **밝은 타일과 어두운 타일을 반드시 번갈아 놓는다.** 색이 바뀌는 것 자체가 구분선이므로
  같은 밝기가 연속되면 슬라이드 경계가 사라진다. 밝음 → 어두움 → 밝음 → 어두움.
- 같은 어두운 톤을 연속으로 쓸 땐 `--tile1`/`--tile2`/`--tile3` 미세차를 활용한다.
- A6(선언)은 챕터 끝에만, 전체에서 2~3회.

## 5. 원고 → 슬라이드 분해 규칙

1. **한 슬라이드 = 한 문장.** 헤드라인에 두 가지 메시지를 넣지 않는다.
   - 원고: "새 칩은 전력을 40% 덜 쓰면서 두 배 빠릅니다"
     → 히어로 `두 배 빠르게. / 절반의 전력으로.` · 리드는 생략 · 수치는 A4로 뺀다
2. 설명이 세 줄을 넘으면 그것은 헤드라인이 아니라 **다음 슬라이드**다.
3. 수치는 카드에 넣지 말고 A4에서 헤어라인으로 나눈다.
4. 챕터가 바뀔 때마다 배경 밝기를 반전시킨다.
5. 마지막은 A8, pill 버튼 하나로 닫는다.

## 6. 그림자·라운딩 규칙

- **그림자는 제품 이미지에만.** `filter:drop-shadow(rgba(0,0,0,.22) 6px 10px 60px)`.
  카드·버튼·텍스트에 그림자를 넣으면 즉시 다른 브랜드가 된다.
- 라운딩 문법을 섞지 않는다: 카드 `--r-lg`(36px), 버튼 `--r-sm`(16px),
  **CTA와 칩만 `--pill`**. pill은 액션 신호 전용이다.
- 전면 타일은 라운딩 0. 화면 끝까지 나가는 면에 모서리를 주지 않는다.
- 버튼 누름 상태는 `transform:scale(.95)` 하나로 통일한다.

## 7. 모션 규칙 (CSS만)

- 페이드 + 30px 상승, `cubic-bezier(.28,.11,.32,1)`, 0.9s. **느리고 부드럽게.**
- 등장 순서: 헤드라인(d1) → 리드(d2) → 링크(d3) → 이미지(d4).
- 스텝·바운스·회전 금지. 이 시스템의 모션은 "무겁고 조용하다".
- `@media print`: 애니메이션 해제, 슬라이드당 1페이지.

## 8. 빌드 절차

1. `template.html`(이 스킬 폴더)을 골격으로 사용한다 — 토큰·8종 아키타입·모션·발표자 노트가
   다 들어 있다. 예시 슬라이드 8장은 교체용 참조다.
2. 원고를 5장 규칙으로 분해해 **슬라이드 시퀀스 표**(아키타입·배경 밝기·헤드라인·리드·수치)를
   먼저 만들어 사용자에게 보여준다. **밝기 교차가 지켜지는지 이 표에서 확인한다.**
3. `<section class="slide">` 단위로 생성. 어두운 타일은 `class="slide dark"`.
4. **발표자 노트**는 각 `<section>`의 `data-note` 속성에 넣는다(HTML 태그 가능, `"` 금지).
   `S`로 토글되며 기본 숨김. 좌우 여백은 `fit()`이 슬라이드 본문 끝선(96px)에 맞춰 계산한다.
5. `{주제}-deck.html`로 저장. **PPTX 변환**은 `../monoline-deck/deck2pptx.py` 공유.
6. **검증**: 첫·중간·마지막 장을 캡처해 점검한다 —
   ① 밝은 타일이 두 장 연속인가 ② 카드나 버튼에 그림자가 생겼는가
   ③ 파랑 말고 다른 악센트가 들어갔는가 ④ 다크 타일에 `--primary`(어두운 파랑)를 썼는가
   ⑤ 본문 행간이 1.47 아래로 조여졌는가.

**함정**
- 한글 파일명으로 저장하면 Edge 헤드리스 캡처가 안 된다. 검증 시 스크래치패드에 ASCII 이름으로
  복사해 찍는다. `--user-data-dir`을 새로 주면 Edge 새 탭 화면이 찍히므로 쓰지 않는다.
- `.slide`는 `display:flex`다(`.active`에서). 새 아키타입을 만들 때 `display:block`으로
  바꾸면 중앙 정렬이 깨진다.
- 여백을 줄이고 싶은 충동이 이 스타일의 최대 적이다. 내용이 넘치면 여백이 아니라
  **슬라이드를 늘린다.**

## 9. 조작법 (생성물 안내에 포함할 것)

- `→` / `Space` 다음, `←` 이전, `Home`/`End` 처음·끝, 화면 좌우 클릭·스와이프
- **`S` 발표자 노트 토글** (기본 숨김)
- `#3` 해시로 특정 장 직행, `?shot#3`은 캡처 모드
- 브라우저 인쇄(Ctrl+P, 가로)로 PDF 출력
