# Starbucks Deck — 따뜻한 리테일 플래그십형 발표자료 생성기

starbucks.com의 디자인 시스템을 재현하는 스킬. 입력(원고·개요·자료)을 받아
**자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 원본 스펙의 표현: **"매장 앞치마의 초록을 모든 표면에 입은, 따뜻하고 확신에 찬 리테일 플래그십."**
> 이 시스템의 온기는 **크림 색온도**에서 나오고 신뢰는 **네 가지 초록의 역할 분담**에서 나온다.
> 순백 바닥으로 바꾸거나 초록을 하나로 통일하면 둘 다 사라진다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

1. **원고/자료** — 없으면 주제만 받아 개요부터 작성해 확인받는다
2. **사진** — 제품·인물 사진이 있으면 카드와 피처 밴드에 넣는다. 없어도 색면만으로 성립한다
3. **리워드/특전 성격의 내용이 있는가** — 있으면 그 장에만 골드를 쓴다. 없으면 골드를 아예 안 쓴다
4. **출력** — 화면 발표(기본) / PPTX 변환 / PDF 인쇄

## 1. 스타일 토큰 (절대 변경 금지)

```css
/* 네 가지 초록 — 역할이 다르다 */
--green:#006241;    /* 제목 */
--accent:#00754A;   /* CTA·링크 */
--house:#1E3932;    /* 피처 밴드 */
--uplift:#2b5148;   /* 장식 */
--green-light:#d4e9e2;
--gold:#cba258; --gold-lightest:#faf6ee;   /* 리워드 전용 */
/* 표면 — 순백은 페이지 바닥이 아니다 */
--white:#fff; --cool:#f9f9f9; --warm:#f2f0eb; --ceramic:#edebe9;
--ink:rgba(0,0,0,.87); --ink-soft:rgba(0,0,0,.58);
--hairline:#e7e7e7;
```

**색 규칙 (위반 시 스타일 붕괴)**
- **순백을 페이지 바닥으로 쓰지 않는다.** 크림(#f2f0eb) 또는 세라믹(#edebe9)이다.
  스펙 표현으로 "따뜻한 크림 색온도는 하중을 받는 요소(load-bearing)"다.
- **"브랜드 초록 하나"를 고르지 않는다.** 네 초록의 역할 분담이 의도된 설계이며,
  #006241 하나로 통일하면 브랜드가 납작해진다.
- **골드는 리워드 신호 전용.** 범용 악센트로 쓰지 않는다.
- **그라디언트를 쓰지 않는다.** 처음부터 끝까지 색블록이다.
- **본문에 순검정을 쓰지 않는다.** `rgba(0,0,0,.87)`이 크림 바닥과 맞는 먹색이다.

## 2. 타입 규칙 — 위계는 크기가 아니다

| 역할 | 크기(1920 스테이지) | 웨이트 | 색 |
|---|---|---|---|
| 디스플레이 | 160px | 600 | 먹색/흰색 |
| 점보 | 116px | 600 | |
| 히어로 | 90px | 600 | |
| **h1** | 48px | **600** | **초록 #006241** |
| **h2** | 48px | **400** | **먹색** |
| 리드 | 38px | 400 | 행간 1.75 |
| 본문 | 32px | 400 | 행간 1.5 |
| 버튼 | 30px | 600 | |

- 표기 크기는 **원본 웹 토큰 × 2**(디스플레이 80 → 160px).
- **h1과 h2는 같은 크기(24px, 덱 48px)다.** 크기 대비로 위계를 만들지 않고
  **웨이트 600 + 초록 / 웨이트 400 + 먹색**으로 구분한다. 이것이 이 시스템의 서명 규칙이다.
- **자간은 −0.01em(덱 −0.32px)을 전 서체에 일관되게** 건다.
- **폰트**: SoDoSans는 사유 폰트다(House Industries). 스펙이 지정한 오픈소스 대체가
  **Inter / Manrope / Nunito Sans**. 리워드 세리프(Lander Tall)는 **Lora**로 대체한다.
  한글은 Pretendard. **세리프와 스크립트를 일반 흐름에 넣지 않는다** — 세리프는 리워드,
  스크립트는 채용 맥락 전용이다.

## 3. 슬라이드 아키타입 (8종 — 이 중에서만 조합)

| 코드 | 이름 | 배경 | 사용 시점 |
|---|---|---|---|
| K1 | 표지 | 크림 + Frap | 첫 장 |
| K2 | 피처 밴드 | 하우스그린 46/54 분할 | 챕터 전환·주요 메시지 |
| K3 | 카드 3-up | 크림 + 흰 카드 | **주력** — 항목 나열 |
| K4 | 수치 | 세라믹 | 지표 4개 |
| K5 | 리워드 밴드 | 크림 + 골드 카드 | 특전·혜택 (골드는 여기만) |
| K6 | 표 | 크림 + 헤어라인 행 | 비교·명세 |
| K7 | 선언 | 하우스그린 전면 | 전환 (1~2회) |
| K8 | 클로징 | 세라믹 + Frap | 마지막 장 |

**리듬 규칙**
- 크림 → 하우스그린 → 크림 → 세라믹으로 **면 온도를 오간다.** 하우스그린이 연속되지 않게 한다.
- **카드 사이에 구분선을 넣지 않는다.** 크림 바닥이 숨 쉬는 것이 여백 전략이다.
- **Frap(떠 있는 원형 초록 버튼)**은 표지와 클로징에 둔다. 매 장에 두면 UI 목업처럼 보인다.

## 4. 원고 → 슬라이드 분해 규칙

1. **한 카드 = 한 항목**(제목 + 두세 줄 + 버튼). 카드 안에 표를 넣지 않는다.
2. 중요한 선언은 K2 피처 밴드나 K7 하우스그린 전면으로 올린다.
3. 수치는 K4에서 **스타벅스 그린(제목용 초록)**으로 찍는다. CTA 초록과 헷갈리지 않는다.
4. 혜택·특전이 있으면 K5 한 장에 모으고 골드를 거기서만 쓴다.
5. 마지막은 K8, 초록 pill 하나 + 아웃라인 하나.

## 5. 형태 규칙

- **모든 버튼은 50px 풀 pill.** 예외 없다. 각지게 만들지 않는다.
- **버튼 누름 상태는 `transform:scale(0.95)`** — 스펙이 "서명 마이크로 인터랙션"이라 부르며
  빠뜨리지 말라고 명시한 요소다. 템플릿에 이미 걸려 있다.
- 카드 라운딩 12px(덱 24px), 원형은 Frap·아이콘·아바타.
- **얕은 그림자를 2~3겹 겹친다.** 진한 한 겹을 쓰지 않는다.

## 6. 모션 규칙 (CSS만)

- 페이드 + 20px 상승, 0.6s, `cubic-bezier(.25,.46,.45,.94)`(원본 아코디언 곡선), 간격 0.10s.
- 이미지는 `opacity .3s ease-in`으로 페이드 인.
- `@media print`: 애니메이션 해제, 슬라이드당 1페이지.

## 7. 빌드 절차

1. `template.html`을 골격으로 사용한다 — 네 초록·8종 아키타입·Frap·발표자 노트 포함.
2. 원고를 4장 규칙으로 분해해 **슬라이드 시퀀스 표**(아키타입·면 색·제목 웨이트·골드 유무)를
   먼저 보여준다. **골드가 리워드 장에만 있는지 여기서 확인한다.**
3. 사진은 `.shot`/`.photo`/`.band .vis`에 `--img:url(...)`로 건다.
4. **발표자 노트**는 `data-note` 속성(HTML 태그 가능, `"` 금지). `S` 토글, 기본 숨김.
5. `{주제}-deck.html`로 저장. **PPTX 변환**은 `../monoline-deck/deck2pptx.py` 공유.
6. **검증**: 첫·중간·마지막 장을 캡처해 점검한다 —
   ① 페이지 바닥이 순백이 됐는가 ② 초록을 하나로 통일했는가
   ③ 골드가 리워드 밖에서 쓰였는가 ④ 각진 버튼이 생겼는가
   ⑤ 그라디언트가 들어갔는가 ⑥ h1/h2를 크기로 구분했는가
   ⑦ 본문이 순검정이 됐는가.

**함정**
- 한글 파일명은 Edge 헤드리스 캡처가 안 된다. 스크래치패드에 ASCII 이름으로 복사해 찍는다.
  `--user-data-dir`을 새로 주면 Edge 새 탭이 찍히므로 쓰지 않는다.
- **크림 배경과 흰 카드의 차이는 프로젝터에서 사라질 수 있다.** 밝은 회의실이면
  카드 그림자를 한 겹 더 얹지 말고 **배경을 세라믹(#edebe9)으로 한 단계 내려** 대비를 만든다.
- Pretendard에는 600이 있지만 한글 600과 400의 차이가 SoDoSans만큼 크지 않다.
  **h1/h2를 웨이트만으로 구분하기 어려우면 색 차이(초록 vs 먹색)에 더 의존한다.**

## 8. 조작법 (생성물 안내에 포함할 것)

- `→` / `Space` 다음, `←` 이전, `Home`/`End` 처음·끝, 화면 좌우 클릭·스와이프
- **`S` 발표자 노트 토글** (기본 숨김)
- `#3` 해시로 특정 장 직행, `?shot#3`은 캡처 모드
- 브라우저 인쇄(Ctrl+P, 가로)로 PDF 출력
