# Stepwire Deck — 스텝 파이프라인 해설 발표자료 생성기

유튜브 테크 해설영상의 "동작 원리를 단계로 뜯는" 스타일을 재현하는 스킬.
입력(원고·개요·자료)을 받아 **자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> **neonwire-deck의 자매 스킬**이다. 같은 청흑 캔버스·같은 상태색을 쓰지만 문법이 다르다:
> neonwire는 **인과 한 줄**(닿는다/막힌다/꺾인다)을 선 하나로 그리고,
> stepwire는 **과정 전체**(1단계→2단계→…)를 스텝퍼 크롬과 데이터 구조 다이어그램으로 뜯는다.
> "왜"를 말하면 neonwire, "어떻게"를 말하면 stepwire다.

출처: `youtube.com/watch?v=TuL1wwsk4Fo` (바이브랩스, PixelRAG 해설) 프레임 픽셀 실측.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

사용자가 이미 밝힌 항목은 건너뛴다:
1. **원고/자료** — 없으면 주제만 받아 개요부터 작성해 확인받는다.
   특히 **단계 수**(파이프라인이 몇 단계인지)를 원고에서 먼저 센다
2. **b-roll 사용 여부** — 이 스타일은 neonwire보다 사진을 자주 깐다(밝기 30%).
   (a) 사용자 제공 (b) media-gen-image 생성 (c) 없이 진행 — (c)도 유효하다
3. **출력** — 화면 발표(기본) / PPTX 변환 / PDF 인쇄

## 1. 스타일 토큰 (실측값 — 변경 금지)

```css
--bg:#061017;   /* 청기 도는 근사흑 */
--panel:#0D1722; --card:#131E2D; --line:#1E2A3C;
--fill:#14484E; /* 죽인 틸 면 — 표 하이라이트·타일 채움. 이 스킬 고유 토큰 */
--ink:#F2F5F8;  --dim:#7C8794;   --micro:#4E5A68;
--cyan:#1ECCC6; --amber:#FCA81E; --red:#FC6C6C;
```

**색 규칙**
- 상태색 의미는 neonwire와 동일: 시안=진행/적중/핵심, 앰버=수작업/결정 부담/문제, 레드=실패/불가.
- 이 스킬의 고유 문법은 **`--fill`(죽인 틸 면)**이다. 표 하이라이트·타일 적중·미니 표 채움처럼
  "면을 칠해야 할 때"는 발광 시안이 아니라 이 죽인 틸을 쓴다.
  **발광 시안은 테두리·글자·점에만** — 면까지 발광색으로 칠하면 HUD가 네온사인이 된다.
- **적중은 항상 정확히 하나다.** 타일 12칸 중 1칸, 표의 교차 셀 1개, 결과 행 1줄, 사다리의 현재 단.
  이 "전체는 어둡고 하나만 켜진다" 문법이 이 스타일의 정체성이다. 둘을 켜려면 장을 쪼갠다.

## 2. 화면 구조 (16:9 / 1920×1080 고정)

헤더(아이브로 15px/.26em → 헤드라인 52px/700 → 보조 20px)·자막(30px)·좌측 기준선 124px은
neonwire와 같다. 이 스킬의 추가 크롬:

```
┌──────────────────────────────────────────────┐
│  ①—②—●—④—⑤            ← 스텝퍼 (P1 전용, top 88px)  │
│  STEP 03 · EMBED        ← 헤더가 한 계단 내려옴(.stepped) │
│  헤드라인 52px                                 │
│                                              │
│         [ .diagram : 1920×700 ]               │
│                                              │
│  (좌하단 히어로 스탯 150px)  ● ● ● ○ ○  3/5      │  ← 진행 점 (P1 전용)
│              내레이션 자막                       │
└──────────────────────────────────────────────┘
```

- **스텝퍼**: 34px 원 + 26px 연결선. 활성 = 시안 채움 + 어두운 숫자, 비활성 = 회색 링.
- **진행 점**: 하단 중앙. 활성 점은 26px 알약으로 늘어난다 + `3/5` 모노 라벨.
- **히어로 스탯**(.stat): 좌하단, 모노 150px 시안 + 한글 단위는 절반 크기(`<small>`) + 모노 라벨.

## 3. 슬라이드 아키타입 (9종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|------|------|------|-----------|
| P1 | 스텝 파이프라인 | 스텝퍼 + 재료→도구→산출 + 진행 점 | 단계 설명 (주인공) |
| P2 | 검색 쿼리 | 검색 pill(깜빡이는 커서) + 점선↓ + 스켈레톤 행 | 질문이 들어간다 |
| P3 | 표 크로스헤어 | 행·열 하이라이트 + 교차점 수치 셀 | 표를 정확히 읽는다 |
| P4 | 타일 그리드 | 12칸 그리드 + 1칸 발광 + 돋보기 + 배지 | 전체에서 조각을 찾는다 |
| P5 | 히어로 스탯 | 좌하단 거대 수치 + b-roll | 규모 한 방 |
| P6 | 방사 맵 | 중앙 원 코어 + 점선 + 칩 3~4개 | 쓰임새·사례 나열 |
| P7 | 결정 팬 | 좌측 노드 + 곡선 화살 + "?" 카드들 (앰버) | 수작업·결정 부담 |
| P8 | 카드 클러스터 | 미니 콘텐츠 카드 4~5장 + 좌하단 숫자 | 종류를 흩어 보여준다 |
| P9 | 사다리 | 글자 타일 세로 스택 + 점선 예고 | 약어·단계 정의 |

**리듬 규칙**
- **P1이 뼈대다.** 파이프라인이 5단계면 P1을 5장 반복하고 스텝퍼의 `on`만 옮긴다.
  각 P1 사이에 그 단계를 확대하는 P2~P4를 끼운다 — "단계 선언 → 그 속을 확대" 리듬.
- P5(스탯)는 전체에서 두 번까지. P7(앰버 결정)은 반드시 뒤에서 시안 장으로 갚는다.
- P6·P8의 칩/카드는 **일부러 어긋난 높이**에 놓는다 — 정렬하면 조직도가 된다.
- P9 사다리는 3~4단이 한계. 말하는 단만 `on`, 다음 단은 점선으로 예고.

## 4. 원고 → 슬라이드 분해 규칙

1. **원고에서 파이프라인을 먼저 찾는다.** "먼저 A가 … 그 다음 B가 … 마지막으로 C가"가
   이 스킬의 본문이다. 단계 수를 세어 스텝퍼 길이를 고정하고, 단계마다 P1 한 장.
2. 각 단계의 내부 동작(검색·표 읽기·타일 분할)은 P2~P4로 확대한다.
   자막에 원고 문장을 그대로, 헤드라인은 그 동작의 이름("작은 타일로 나눠 찾는다").
3. 규모·수치("828만 문서")가 나오면 P5. 쓰임새 나열("검색·상담·검토")은 P6.
4. "매번 정해야 했다/직접 골라야 했다"류의 수작업 부담은 P7(앰버) —
   해결 장(시안 P1)이 이를 갚는 구조로 배치한다.
5. 표지는 P5 또는 P9, 마지막은 P6(쓰임새)이나 P8(다음 행동)로 닫는다.

## 5. 다이어그램 그리는 법

- 좌표계·SVG 규약(`pathLength="1"` + `.draw`·`.diagram > svg` 한정 선택자)·노드 규약은
  neonwire와 동일하다. `.diagram`은 1920×700, top 300px.
- **P1의 흐름 화살은 점선**(`.dash`)이다 — neonwire의 실선 인과선과 구별되는 표식.
  도구 노드만 시안 발광, 재료·산출 노드는 `.off`.
- P3 수치 셀은 **하이라이트 열의 중심에 정확히** 놓는다(열 폭을 계산해 좌표를 잡는다).
- 표·타일의 스켈레톤 내용은 `·····`(xtable 자동)·막대(`<i>`)로 그린다. 실제 글자를 채우지 않는다 —
  스켈레톤이어야 "구조를 읽는다"는 말이 살아난다.
- 스크린샷 금지·선 아이콘만·b-roll보다 다이어그램이 밝아야 한다는 규칙은 neonwire와 같다.

## 6. 모션 규칙 (CSS만)

- 등장 순서: **스텝퍼(d1) → 아이브로(d2) → 헤드라인(d3) → 보조(d4) → 다이어그램(d4~d7) → 진행점·자막(d8)**.
- **P3는 행(d5) → 열(d6) → 교차 셀(d7) 순서가 생명이다.** 동시에 켜면 "동시에 읽는다"가 안 보인다.
- P2 검색 커서는 `blink` 1.1s 무한 반복 — 이 장의 살아 있는 유일한 요소다.
- 회전 요소는 `--rot` 변수로(pop 키프레임이 물고 있다). `@media print`에서 transform은 유지된다.

## 7. 빌드 절차

1. `template.html`(이 스킬 폴더)을 골격으로 사용한다 — 토큰·9종 아키타입·모션·노트·내비 완비.
   예시 슬라이드 9장은 교체용 참조다.
2. 원고를 분해해 **슬라이드 시퀀스 표**(아키타입·스텝 번호·아이브로·헤드라인·자막·지배색)를
   먼저 만들어 사용자에게 보여준다. 파이프라인 단계 수를 표 머리에 명시한다.
3. `<section class="slide" data-note="...">` 단위로 생성. P1 반복 장은 스텝퍼 `on` 위치와
   `1/5` 라벨만 바꾸면 된다.
4. `{주제}-deck.html`로 저장.
5. **검증**: 스크래치패드에 ASCII 이름(`chk.html`)으로 복사 후 Edge 헤드리스 캡처
   (한글 파일명은 순검정 PNG 함정 — PowerShell 도구로 실행).
   점검: ① 적중이 한 장에 둘 이상인가 ② 발광색으로 면을 칠했는가
   ③ 스텝퍼 on 위치가 헤더 STEP 번호와 어긋났는가 ④ P3 셀이 교차점을 벗어났는가.

**이미 밟은 함정** (neonwire에서 물려받음 + 이 스킬 고유)
- `.diagram > svg` 한정 선택자를 풀면 노드 안 아이콘까지 상태색에 물든다.
- 아이콘 광은 `<svg>` 하나에만 — 도형별 drop-shadow는 네모 얼룩을 만든다.
- P3 수치 셀 좌표는 그리드 열 폭에서 계산한다 — 눈대중으로 놓으면 교차점을 벗어난다.

## 8. 조작법 (생성물 안내에 포함할 것)

- `→`/`Space` = 다음, `←` = 이전, `Home`/`End` = 처음/끝, 화면 좌/우 절반 클릭 동일
- `S` = 발표자 노트 토글, `#N` = N번 슬라이드, `?shot` = 페이지 표시 숨김(캡처용)
- Ctrl+P → PDF 저장 시 슬라이드당 1페이지

## 9. PPTX 변환

monoline-deck 스킬의 변환기를 그대로 쓴다 (`class="slide"` + `?shot#N` 규약 동일, 검증 완료):

```bash
python3 /Users/kbg1023/.claude/skills/monoline-deck/deck2pptx.py "덱파일.html"
```

같은 폴더에 같은 이름의 `.pptx`가 생성된다. 의존성: python-pptx, Edge 또는 Chrome.
