# Doodle Deck — 화이트보드 손그림 애니메이션 발표자료 생성기

연필 쥔 손이 화면에 그림을 **그려 나가는** 해설영상 스타일을 재현하는 스킬.
입력(원고·개요·자료)을 받아 **자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 이 스타일의 본질은 "완성된 그림을 보여주는 것"이 아니라 **말하는 속도에 맞춰 그려지는 것**이다.
> 그래서 모든 그림은 획 하나하나가 순서를 가지며, 자막은 어절 단위로 따라 읽힌다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

사용자가 이미 밝힌 항목은 건너뛴다:
1. **원고** — 말하듯 쓴 구어체 원고가 이상적. 없으면 주제만 받아 나레이션부터 써서 확인받는다
2. **장면 수** — 원고 한 문장 = 한 장면이 기본. 문장 수를 세어 제안한다
3. **출력** — 화면 발표(기본) / PPTX / PDF

## 1. 스타일 토큰 (절대 변경 금지 — 영상 프레임 실측값)

```css
--paper:#F5F3EF;   /* 따뜻한 미색 종이. 순백(#fff)·회색 금지 */
--ink:#353535;     /* 소프트 블랙 마커. 순검정(#000) 금지 */
--red:#CE2E3C;     /* 현재 어절 하이라이트 · 붉은 손글씨 주석 — 이 둘에만 쓴다 */
--gray:#ABA9A7;    /* 아직 안 읽은 어절 */
/* 파스텔 채색 6색 — 이 밖으로 나가지 않는다 */
--p-blue:#D8EAFB; --p-green:#CEF3DF; --p-peach:#FDE0C1;
--p-pink:#F3C3A8;  --p-brown:#C89766;  --p-sky:#D9E8FA;
```

**색 규칙**
- 화면의 90%는 종이색이다. 여백이 이 스타일의 절반이다 — 그림으로 화면을 채우려 들지 않는다.
- **채도 있는 색은 파스텔 6색뿐.** 진한 색은 잉크(선)와 빨강(하이라이트)뿐이다.
- 빨강은 **자막 현재 어절**과 **붉은 손글씨 주석** 외에는 쓰지 않는다. 남발하면 강조가 죽는다.
- 채색은 선 안쪽을 옅게 메우는 용도다. 선 없는 색면은 만들지 않는다.

## 2. 화면 구조 (16:9 / 1920×1080 고정)

```
┌──────────────────────────────────────────────┐
│                                              │
│        [그림이 그려지는 넓은 여백]              │  ← 그림은 화면 중앙~좌우 1/3 지점에
│     ✏️ 연필 쥔 손이 획 끝을 따라간다             │     크지 않게(400~700px) 놓는다
│                                              │
│                                              │
│      ╭────────────────────────────╮          │
│      │ 어절 어절 [현재어절] 어절 어절 │          │  ← 알약형 자막, bottom 7.5%
│      ╰────────────────────────────╯          │
└──────────────────────────────────────────────┘
```

- **자막 알약**: 흰 바탕 + 잉크 테두리 3.5px + full-round + 부드러운 그림자. 어절 사이 간격 44px.
  - 이미 읽은 어절 = 잉크색 / **현재 어절 = 빨간 상자 + 흰 글씨** / 아직 안 읽은 어절 = 회색
  - 어절은 `data-cap` 속성에 **띄어쓰기로만** 적으면 JS가 알약과 span을 만든다
  - 한 장면 자막은 **4~9어절**. 길면 장면을 쪼갠다 (알약이 화면 밖으로 나간다)
- **글꼴**: Gaegu(손글씨) 700. 라벨·자막 전부 손글씨다. 고딕은 쓰지 않는다.
- **그림 위치**: 한 장면에 그림 1~3개. 서로 겹치지 않게 놓고 아래 20%는 자막 영역이니 비운다.

## 3. 장면 아키타입 (6종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|------|------|------|-----------|
| D1 | 캐릭터 + 말풍선 | 로봇·사람·동물 + 말풍선 더미 | 대화·반응·의인화 |
| D2 | 오브젝트 + 화살표 + 라벨 | 사물 하나 → 화살표 → 손글씨 라벨 | 개념 이름 붙이기·정의 |
| D3 | 프레임/무대 | 빈 상자·창·무대를 그리고 그 안을 채운다 | 공간·범위·"~라는 곳" |
| D4 | 나열 | 카드·아이콘 여러 개를 순서대로 | 열거·구성요소 |
| D5 | 붉은 주석 | 이미 그린 것 위에 빨간 손글씨 | 반전·경고·핵심 한마디 |
| D6 | 판정 | 체크박스·엑스 + 짧은 라벨 | 결과·결론·비교 판정 |

**리듬 규칙**
- 같은 아키타입 3연속 금지. D1(캐릭터)과 D3(프레임)를 번갈아 호흡을 만든다.
- D5(붉은 주석)는 전체에서 2~4회. 매 장면 빨강이 나오면 빨강이 무의미해진다.
- 장면당 그림 요소 3개 이하. 손이 3개 이상 그리면 지루해진다.

## 4. 원고 → 장면 분해 규칙

1. **원고 한 문장 = 한 장면 = 자막 한 줄.** 문장을 그대로 `data-cap`에 넣는다(구어체 유지, 마침표 제거).
2. 그 문장에서 **그릴 명사 하나**를 고른다. 명사가 없으면(추상 문장) 앞 장면 그림을 유지하고 D5(붉은 주석)만 얹는다.
3. 문장이 10어절을 넘으면 의미 단위로 두 장면으로 쪼갠다.
4. 숫자·비교는 D4(나열)나 D6(판정)으로. 결론 문장은 D5나 D6으로 닫는다.
5. 그림은 **앞 장면 것을 이어 쓸 수 있다** — 같은 그림에 요소만 추가하면 "계속 그려 나가는" 느낌이 산다.

## 5. 그림 제작 규칙 (여기가 이 스킬의 핵심)

`template.html`의 예시 6장면이 6종 아키타입 참조 구현이다. 새 그림은 그 문법을 따른다.

```html
<div class="art" style="left:660px;top:300px;width:600px;height:440px">
  <svg viewBox="0 0 600 440" width="600" height="440">
    <path class="draw" style="--d:.1s;--dur:1.6s" pathLength="100" d="…"/>   <!-- 그려지는 선 -->
    <path class="fill" style="--c:var(--p-brown);--d:1.8s" d="…"/>           <!-- 나중에 드는 색 -->
  </svg>
  <div class="hand" style="--d:.1s;--dur:1.6s;offset-path:path('…')">…연필 SVG…</div>
</div>
```

**어기면 깨지는 4가지**
1. **`.art`의 width/height = svg의 viewBox 크기.** 1px = SVG 1단위여야 손의 `offset-path` 좌표가 그림과 맞는다.
2. **그려지는 path에는 반드시 `pathLength="100"`.** 실제 길이와 무관하게 dasharray 100으로 그려진다.
3. **채색은 `fill` 속성이 아니라 `style="--c:…"`로 준다.** `.art>svg path{fill:none}` 규칙이 `fill` 속성을 이긴다.
4. **손의 `offset-path`는 그 손이 따라갈 획의 `d`를 그대로 복사**하고, `--d`/`--dur`도 그 획과 똑같이 맞춘다.

- 선은 `M … h … a …` 같은 단순 도형으로 그려도 `#rough` 필터(feTurbulence 변위)가 손떨림을 입혀준다. 일부러 삐뚤게 그릴 필요 없다.
- 손은 **장면당 1~2개만.** 모든 획마다 손을 붙이면 화면이 정신없다. 가장 큰 획 하나에만 붙인다.
- 복잡한 그림이 꼭 필요하면 요소를 쪼개 여러 `.art`로 나눈다. 하나의 거대한 path는 그리는 순서가 어색해진다.

## 6. 모션 규칙

- **그려진다**: `stroke-dashoffset 100→0`, 획당 1.0~1.8s, 획 사이 `--d`를 0.4~0.6s씩 늦춘다.
- **채색은 선 다음**: 해당 윤곽선이 끝나는 시점 + 0.2s에 `--d`를 맞춰 톡 튀며(popIn) 들어온다.
- **손은 획과 함께 나타나 사라진다**: 획 시작 6%에 등장, 88%부터 페이드아웃.
- **자막은 어절당 520ms**(`WORD_MS`)로 스스로 읽어 나간다. 말이 빠른 원고면 460ms까지 줄인다.
- 슬라이드 전환은 하드컷. 페이드 전환 없음.

## 7. 빌드 절차

1. `template.html`을 골격으로 사용한다 — 토큰·6종 아키타입·연필 손·자막 엔진이 다 들어 있다.
2. 원고를 4단계 규칙으로 분해해 **장면 시퀀스 표**(아키타입·자막 어절·그릴 것·채색)를 만들어 사용자에게 보여준다.
3. `<section class="slide" data-cap="…">` 단위로 생성.
4. `{주제}-deck.html`로 저장.
5. **검증**: 헤드리스로 캡처해 ① 채색이 나오는가 ② 자막 알약이 화면 밖으로 안 나가는가
   ③ 그림이 자막과 겹치지 않는가 ④ 빨강이 남발되지 않았는가를 본다.
   - **헤드리스 캡처는 항상 애니메이션이 끝난 상태를 찍는다.** 그래서 연필 손은 캡처에 안 잡힌다(정상).
     손 동작을 눈으로 확인하려면 `.active .hand{animation-duration:60s!important}`를 임시로 주입한 사본을 찍는다.

## 8. 조작법 (생성물 안내에 포함할 것)

- `→`/`Space` = 다음, `←` = 이전, `Home`/`End` = 처음/끝, 화면 좌/우 절반 클릭도 동일
- 슬라이드를 열면 그림이 그려지고 자막이 **저절로 읽힌다**. 다시 보려면 `←` 후 `→`.
- `#N` = N번 장면 바로 열기, `?shot` = 자막을 다 읽은 상태로 고정(캡처용)
- Ctrl+P → PDF 저장 시 모든 그림이 완성 상태로 장면당 1페이지

## 9. PPTX 변환

monoline-deck 스킬의 변환기를 그대로 쓴다 (`class="slide"` + `?shot#N` 규약이 동일):

```bash
python3 /Users/kbg1023/.claude/skills/monoline-deck/deck2pptx.py "덱파일.html"
```

애니메이션은 완성 상태로 굳어 이미지 슬라이드가 된다. 의존성: python-pptx, Edge 또는 Chrome.
