# Stripe Deck — 밝은 핀테크 제품 발표자료 생성기

stripe.com 마케팅 면의 디자인 시스템을 재현하는 스킬. 입력(원고·개요·자료)을 받아
**자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 이 스타일의 두 기둥은 **상단의 그라디언트 메시**와 **weight 300의 얇은 디스플레이**다.
> 메시를 빼면 밋밋한 화이트 덱이 되고, 웨이트를 400으로 올리면 편집적 공기가 즉시 무너진다.
> 둘 중 하나라도 타협하면 다른 브랜드가 된다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

1. **원고/자료** — 없으면 주제만 받아 개요부터 작성해 확인받는다
2. **제품 화면·데이터** — 이 브랜드의 논증은 "실제 제품을 보라"다. 대시보드·표·숫자가 있으면 반드시
   목업으로 넣는다. 없으면 템플릿 내장 표 목업의 숫자만 실제 값으로 바꾼다
3. **금액·수치 단위** — 통화·소수점 자리를 미리 정한다(tabular-nums로 자릿수를 고정하므로)
4. **출력** — 화면 발표(기본) / PPTX 변환 / PDF 인쇄

## 1. 스타일 토큰 (절대 변경 금지)

```css
--primary:#533afd;        /* 인디고. 채워진 CTA와 인라인 링크 강조 전용 */
--primary-press:#2e2b8c; --primary-deep:#4434d4; --primary-subdued:#b9b9f9;
--brand-dark:#1c1e54;     /* 반전 카드·다크 버튼 */
/* 메시 스톱 — 이 목록 밖의 악센트를 추가하지 않는다 */
--cream:#f5e9d4; --ruby:#ea2261; --magenta:#f96bee;
--canvas:#fff; --canvas-soft:#f6f9fc; --hairline:#e3e8ee;
--ink:#0d253d; --ink-2:#273951; --mute:#64748d;
```

**색 규칙 (위반 시 스타일 붕괴)**
- **인디고를 본문 색으로 쓰지 않는다.** CTA와 링크 색이지 타입 색이 아니다.
- **채워진 인디고 버튼은 밴드당 하나.** 두 개를 나란히 두면 위계가 사라진다.
- 문서화된 메시 스톱 밖의 악센트색을 추가하지 않는다.
- 잉크는 순검정이 아니라 `#0d253d`(짙은 남색기)다.

## 2. 타입 규칙 — 얇음이 서명이다

| 역할 | 크기(1920 스테이지) | 웨이트 | 자간 |
|---|---|---|---|
| 히어로 h1 | 112px | **300** | -2.8px |
| 섹션 오프너 h2 | 96px | **300** | -1.92px |
| 카드/서브섹션 h3 | 64px | **300** | -1.28px |
| 컴팩트 제목 h4 | 52px | **300** | -0.52px |
| 리드 | 32px | **300** | 0 |
| 본문 | 30px | **300** | 0 |
| 수치 표 | 28px | 300 | -0.84px · **tabular-nums** |
| 버튼 | 32px | 400 | 0 |
| 캡션 | 26px | 400 | -0.78px |
| 대문자 eyebrow | 20px | 400 | +0.2px |

- 표기 크기는 **원본 웹 토큰 × 2**(히어로 56 → 112px). 음수 자간도 2배다.
- **디스플레이 웨이트를 300 위로 올리지 않는다.** 본문도 300이다. 400은 버튼과 캡션에만.
- `font-feature-settings:"ss01"`을 body에 전역으로 건다(템플릿에 이미 있음).
- **금액·숫자 셀에는 반드시 `tabular-nums`.** 이게 빠지면 조용한 금융 데이터 감각이 깨진다.
- **폰트**: Sohne는 사유 폰트다. 스펙이 지정한 대체는 **Inter weight 300 + ss01 + -1.4px 트래킹**.
  한글은 Pretendard 300이 받는다. 스택 순서를 바꾸지 않는다.

## 3. 그라디언트 메시 — 알려진 근사

원본은 유기적 블롭 형태의 **레이어드 SVG/이미지**이며, 스펙 자체가 "CSS로 렌더할 수 없다"고 명시한다.
템플릿은 **radial-gradient 5겹 + blur(10px) + 하단 페이드**로 근사한다. 이 점을 알고 쓴다:

- 더 원본에 가깝게 하려면 실제 메시 이미지를 `.mesh`의 `background-image`로 교체한다.
- 메시 **하단에 경계선이 보이면 실패**다. `.mesh::after`의 흰색 페이드를 반드시 유지한다.
- 메시는 **히어로(`.mesh.tall` 58%)와 클로징**에 집중시키고, 중간 장은 얕게(38%) 깔거나 뺀다.
  모든 장에 깔면 배경이 시끄러워져 얇은 타입이 묻힌다.

## 4. 슬라이드 아키타입 (8종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|---|---|---|---|
| S1 | 히어로 | 메시(tall) + tag + h1 + pill 버튼 | 표지 |
| S2 | 섹션 오프너 | 메시(얕게) + eyebrow + h2 | 챕터 전환 |
| S3 | 제품 UI 목업 | 좌 텍스트 38% / 우 목업(표·대시보드) | **주력** — 기능 설명 |
| S4 | 카드 3-up | feature 카드, 강조 1장만 크림 | 항목 나열 |
| S5 | 수치 | 카드 4-up, tabular-nums | 지표 |
| S6 | 크림 밴드 | `--cream` 면 + 문장 하나 | 강조·전환 |
| S7 | 비교 행 | 헤어라인 가로선만 | 비교·명세 |
| S8 | 클로징 | 메시(tall) + 중앙 정렬 + pill | 마지막 장 |

**리듬 규칙**
- **S3(제품 목업)를 기능 설명마다 짝지운다.** 스펙의 명시 요구다 — 설명만 있는 기능 장은 만들지 않는다.
- S6(크림 밴드)는 전체에서 2~3회.
- 배경은 `canvas` / `canvas-soft`를 번갈아 리듬을 만든다.

## 5. 원고 → 슬라이드 분해 규칙

1. **한 슬라이드 = 한 주장 + 제품 화면 하나.**
2. 숫자가 둘 이상이면 본문에서 빼내 S5 카드 4-up 또는 S3 목업 표로 옮긴다.
3. 기능 나열은 카드 3개까지. 그 이상은 S7 행 나열.
4. 챕터가 바뀌면 S2, 챕터 끝은 S6 크림 밴드로 닫으면 리듬이 산다.
5. 마지막은 S8, 채워진 pill 하나 + 아웃라인 pill 하나.

## 6. 형태 규칙

- **버튼은 전부 pill**이다. 라운드 사각으로 바꾸지 않는다.
- **버튼 여백을 8px 16px(덱 16px 32px) 아래로 줄이지 않는다.** 꽉 낀 pill이 거래적 감각을 만든다.
- 라운딩 사다리: 입력 `--r-sm` → 컴팩트 카드 `--r-md` → 카드 `--r-lg` → **목업 크롬 `--r-xl`**.
- 그림자는 **제품 UI 목업에만** 아주 얕게. 카드·버튼에는 넣지 않는다(리프트는 메시가 만든다).

## 7. 모션 규칙 (CSS만)

- 페이드 + 20px 상승, 0.7s, 간격 0.11s. 조용하게.
- 메시는 정지시킨다. 배경이 움직이면 얇은 타입의 가독이 떨어진다.
- `@media print`: 애니메이션 해제, 슬라이드당 1페이지.

## 8. 빌드 절차

1. `template.html`을 골격으로 사용한다 — 토큰·메시·8종 아키타입·표 목업·발표자 노트 포함.
2. 원고를 5장 규칙으로 분해해 **슬라이드 시퀀스 표**(아키타입·메시 유무·헤드라인·제품 화면·수치)를
   먼저 보여준다. **S3 비중과 메시 배치를 이 표에서 확인한다.**
3. `<section class="slide">` 단위로 생성. 목업 이미지는 `.mock .body`에 `--img`로 건다.
4. **발표자 노트**는 `data-note` 속성(HTML 태그 가능, `"` 금지). `S` 토글, 기본 숨김.
5. `{주제}-deck.html`로 저장. **PPTX 변환**은 `../monoline-deck/deck2pptx.py` 공유.
6. **검증**: 첫·중간·마지막 장을 캡처해 점검한다 —
   ① 디스플레이가 400 이상으로 굵어졌는가 ② 메시 하단에 경계선이 보이는가
   ③ 채워진 인디고 버튼이 한 장에 둘 이상인가 ④ 숫자에 tabular-nums가 빠졌는가
   ⑤ 버튼이 라운드 사각이 됐는가 ⑥ 인디고가 본문 색으로 새어 들어갔는가.

**함정**
- 한글 파일명은 Edge 헤드리스 캡처가 안 된다. 스크래치패드에 ASCII 이름으로 복사해 찍는다.
  `--user-data-dir`을 새로 주면 Edge 새 탭이 찍히므로 쓰지 않는다.
- **한글은 weight 300에서 매우 얇게 보인다.** 프로젝터·저해상도 환경에서 히어로가 사라질 수 있으니,
  현장이 어두운 발표라면 본문만 400으로 올리고 **디스플레이는 300을 지킨다**.
- `.slide > *`에 `z-index:1`이 걸려 있다. 메시 위에 요소를 놓으려면 `.mesh` 형제로 두면 된다.

## 9. 조작법 (생성물 안내에 포함할 것)

- `→` / `Space` 다음, `←` 이전, `Home`/`End` 처음·끝, 화면 좌우 클릭·스와이프
- **`S` 발표자 노트 토글** (기본 숨김)
- `#3` 해시로 특정 장 직행, `?shot#3`은 캡처 모드
- 브라우저 인쇄(Ctrl+P, 가로)로 PDF 출력
