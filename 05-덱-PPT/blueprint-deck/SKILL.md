# Blueprint Deck — 모눈 블루프린트 인포그래픽 생성기

설계 도면 위에 정보를 얹은 듯한 인포그래픽 슬라이드를 재현하는 스킬.
입력(원고·개요·자료)을 받아 **자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 이 스타일은 "말을 자막으로 흘려보내는" 덱이 아니라 **한 장에 다 담아 읽히는** 덱이다.
> 슬라이드 하나가 그 자체로 완결된 한 페이지 문서다. 여백보다 밀도가 먼저다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

사용자가 이미 밝힌 항목은 건너뛴다:
1. **원고/자료** — 개조식 정리 자료가 이상적. 없으면 주제만 받아 목차부터 작성해 확인받는다
2. **슬라이드 수** — 논지 하나당 1장. 보통 7~15장
3. **워터마크** — 우하단에 넣을 이름(기본 "Blueprint"). 필요 없으면 제거
4. **출력** — 화면 발표(기본) / PPTX / PDF

## 1. 스타일 토큰 (절대 변경 금지 — 영상 프레임 실측값)

```css
--paper:#F6F6F3;   /* 아주 옅은 회백 종이. 순백 금지 */
--grid:#DFE4E9;    /* 모눈 30px */
--grid-hi:#D2DAE2; /* 굵은 모눈 150px */
--frame:#B9C6D6;   /* 도면 프레임 · 치수선 */
--handle:#6C8FBF;  /* 선택 핸들 테두리 */
--ink:#1E272E;     /* 헤드라인 */
--body:#3A4046;    /* 본문 */
--mute:#767C83;    /* 캡션 */
--line:#D9DDE0;    /* 카드·표 테두리 */
/* 악센트 3색 — 슬라이드마다 하나만 --accent로 */
--terra:#C2703F;  --slate:#475360;  --sage:#54645A;
```

**색 규칙**
- **슬라이드 하나에 악센트는 1색.** 강조 박스 테두리·불릿·번호·인사이트 바가 모두 그 한 색을 쓴다.
- 악센트는 **섹션 단위로 바꾼다**: 도입·문제 제기=테라코타, 구조·설명=슬레이트, 사례·결과=세이지.
- 파스텔 채움색(도해 레이어 등)은 악센트 계열의 탁한 톤(#D17C50/#4B7E6E/#556D8A/#6C7076)만 쓴다. 형광·고채도 금지.
- 카드 배경은 항상 흰색. 모눈이 비쳐야 하므로 큰 색면으로 화면을 덮지 않는다.

## 2. 화면 구조 (16:9 / 1920×1080 고정)

```
┌──────────────────────────────────────────────┐
│ ┌──────────────────────────────────────────┐ │ ← 도면 프레임(inset 28px)
│ │ 헤드라인 (좌상단, 62px 800)               │ │
│ │                                          │ │
│ │   [카드 · 표 · 도해]      ▫ 선택 핸들      │ │ ← .body: 좌우 6%, 상 21% 하 20%
│ │                                          │ │
│ │ ▓▓ 하단 인사이트 바 (짙은 색 + 흰 볼드) ▓▓ │ │ ← bottom 6%
│ └──────────────────────────────────────────┘ │
└──────────────────────────────────── Blueprint┘
```

- **헤드라인**: 좌상단 고정, 62px/800, 최대 3줄. 긴 제목은 `class="sm"`(52px).
- **인사이트 바**: 그 슬라이드의 결론 한 문장. `<b>Insight:</b>` 또는 `<b>Metric:</b>`으로 시작하면 원본 톤이 산다. 표지·마지막 선언 슬라이드에는 넣지 않는다.
- **선택 핸들**: 강조하고 싶은 박스에 `class="sel"`만 붙이면 JS가 네 모서리에 꽂는다. **슬라이드당 1~2개만** — 전부 붙이면 의미가 사라진다.
- **워터마크**: 우하단 `.wm`.

## 3. 슬라이드 아키타입 (7종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|------|------|------|-----------|
| B1 | 표지 | 중앙 도해(치수선 포함) + 대형 제목 + 부제 박스 + 도구 칩 | 첫 장 |
| B2 | 헤드라인 + 노트 + 표 | 좌측 악센트 테두리 노트 + 우측 정의 표 | 정의·템플릿·명세 |
| B3 | 2열 비교 | 두 카드 + 가운데 기호(≠ → vs) + 인사이트 바 | 대조·Before/After |
| B4 | 단계 카드 | Phase 카드 2~3개 + 사이 화살표 + 배지 pill | 로드맵·단계별 도구 |
| B5 | 아이소 레이어 | 마름모 판 3~4층 + 우측 층 설명 | 아키텍처·계층 구조 |
| B6 | 순환도 | 원형 화살표 + 4방향 카드 | 프로세스 루프·왕복 흐름 |
| B7 | 번호 리스트 | 01~05 번호 + 굵은 소제목, 우측 배경 라인아트 | 요약·핵심 원칙·마무리 |

**리듬 규칙**
- 같은 아키타입 연속 금지. 표(B2)·비교(B3)·도해(B5)를 번갈아 배치한다.
- B7은 마지막 1장만. B1은 첫 1장만.
- 도해(B5·B6)는 전체의 1/3을 넘기지 않는다 — 나머지는 카드와 표로 간다.

## 4. 원고 → 슬라이드 분해 규칙

1. **논지 하나 = 슬라이드 하나.** 슬라이드 제목은 그 논지를 **문장으로** 쓴다("~입니다", "~인가?"). 명사구 제목은 이 스타일에서 힘이 없다.
2. 각 슬라이드에서 **결론 한 문장**을 뽑아 인사이트 바에 넣는다. 없으면 그 슬라이드는 아직 논지가 없는 것이다 — 합치거나 버린다.
3. 비교·대조가 있으면 B3, 단계가 있으면 B4, 층위가 있으면 B5, 반복 흐름이면 B6으로 간다. **표로 정리되는 내용은 억지로 도해하지 않는다.**
4. 숫자·비용·기간은 `pill` 배지로 오른쪽에 붙인다.
5. 마지막은 B7(핵심 N가지) + 굵은 선언 문장으로 닫는다.

## 5. 부품 사용법

```html
<section class="slide" style="--accent:var(--slate)">
  <h1 class="in d1">헤드라인 문장</h1>
  <div class="body">
    <div class="row">
      <div class="col"><div class="note in d2"><b>소제목</b><p>본문</p></div></div>
      <div class="col sel in d3"><table>…</table></div>
    </div>
  </div>
  <div class="insight in d5" style="--bar:var(--slate)"><b>Insight:</b> 결론 한 문장</div>
  <div class="wm">Blueprint</div>
</section>
```

- `.card` 흰 카드 / `.note` 악센트 테두리 강조 박스 / `.pill`(+`.gray` `.terra`) 배지 /
  `table`+`caption` 정의 표 / `.numlist` 01~05 리스트 / `.sel` 선택 핸들 / `.insight` 하단 바
- 등장 순서는 `in d1`~`d5`. 헤드라인 → 좌 → 우 → 인사이트 바 순으로 매긴다.

**어기면 깨지는 3가지**
1. **`translateX(-50%)`로 중앙정렬한 요소에 `.in`을 걸지 않는다.** 등장 애니메이션의 transform이 정렬을 덮어써 요소가 오른쪽으로 밀린다. 중앙정렬은 `left:0;right:0;text-align:center`로 한다.
2. **SVG의 선 그룹에는 반드시 `fill="none"`.** 빠뜨리면 검게 칠해진다.
3. **아이소 레이어(B5)는 층 간격 120px 고정.** 좌표가 겹치면 아래 층이 위 층에 완전히 가려져 사라진다. 우측 층 설명의 `top`도 각 층 중심에 맞춘다.

## 6. 모션 규칙

- 이 스타일은 **정적 인포그래픽**이다. 원본 영상도 슬라이드 통 전환이고 내부 애니메이션이 없다.
- 등장은 12px 상승 + 페이드 0.45s, 요소 간 0.12s 스태거까지만. 그 이상은 스타일을 해친다.
- 슬라이드 전환은 하드컷.

## 7. 빌드 절차

1. `template.html`을 골격으로 사용한다 — 토큰·7종 아키타입·부품 CSS·핸들 주입 JS가 다 들어 있다.
2. 원고를 4단계 규칙으로 분해해 **슬라이드 시퀀스 표**(아키타입·헤드라인 문장·본문 요소·인사이트 바·악센트색)를 만들어 사용자에게 보여준다.
3. `<section class="slide">` 단위로 생성.
4. `{주제}-deck.html`로 저장.
5. **검증**: 헤드리스로 캡처해 ① 카드가 `.body` 밖으로 넘치지 않는가 ② 인사이트 바와 콘텐츠가 겹치지 않는가
   ③ 한 슬라이드에 악센트가 2색 섞이지 않았는가 ④ 선택 핸들이 남발되지 않았는가를 본다.

## 8. 조작법 (생성물 안내에 포함할 것)

- `→`/`Space` = 다음, `←` = 이전, `Home`/`End` = 처음/끝, 화면 좌/우 절반 클릭도 동일
- `#N` = N번 슬라이드 바로 열기, `?shot` = 페이지 표시 숨김(캡처용)
- Ctrl+P → PDF 저장 시 슬라이드당 1페이지. **이 스타일은 인쇄물로도 그대로 쓸 수 있다.**

## 9. PPTX 변환

monoline-deck 스킬의 변환기를 그대로 쓴다 (`class="slide"` + `?shot#N` 규약이 동일):

```bash
python3 /Users/kbg1023/.claude/skills/monoline-deck/deck2pptx.py "덱파일.html"
```

같은 폴더에 같은 이름의 `.pptx`가 생성된다. 의존성: python-pptx, Edge 또는 Chrome.
