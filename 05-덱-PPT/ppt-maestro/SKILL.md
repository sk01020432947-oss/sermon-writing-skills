# ppt-maestro — 서식 기반 PPT 생성·수정 총괄

핵심 철학(영상 14편 공통): **AI가 만든 예쁜 PPT ≠ 회사에서 쓸 수 있는 PPT.**
승부는 생성이 아니라 (1) 우리 서식의 정확한 재현, (2) 수정 가능한 결과물, (3) 사람이 개입하는 반자동화(HITL)에 있다.

## Phase 0 — 라우팅 (중복 설치 방지: 기존 자산 우선)

| 요청 | 담당 | 비고 |
|---|---|---|
| 새 PPT, 스타일 자유 | **pptx-design-styles** (30스타일) | 기본 PPT 스킬 |
| "내 스타일로" 명시 | **my-ppt** | |
| 클로드 톤 IR 슬라이드 | **claude-ppt** | |
| 흑백 라인아트 발표덱 | **monoline-deck** 등 덱 5계열 | boneun 라우팅 |
| HTML 프레젠터/특수효과(발표자 모드·캔버스FX) | **html-ppt** (외부 설치본) | PPTX 변환 불가 주의 |
| A4 그레이스케일 보고서 | **genie-report** | |
| **회사/브랜드 서식 일관 재현, 템플릿 오토필, 완성본 수정·리페어** | **이 스킬** | 아래 워크플로우 |

산출 형식 결정: 회사에 **PPTX 파일 제출** → 반드시 python-pptx 경로. **화면 발표/링크 공유**만 → HTML 덱도 가능(폰트 안 깨짐·애니메이션 장점, 단 PPTX 변환 불가).

## Workflow A — 브랜드 스펙 파이프라인 (일관 대량 생성)

준비물 3종 세트(우석지니 공식): **① SKILL/스타일 정의(md) ② 샘플 PDF(시각 레퍼런스) ③ 브랜드 스펙**.
PPTX 원본을 다시 분석시키지 말 것 — 파싱 토큰 낭비. **소스 정확도: PDF > PPTX > HTML** (렌더링된 이미지가 레이아웃·여백 파악에 최적). 속도는 HTML이 빠르지만 수정 횟수가 최다.

1. **스펙 추출**: 사용자의 샘플(PDF/PPTX/이미지 캡처)을 받아 `BRAND-SPEC.md` 작성 — [references/brand-spec-template.md](references/brand-spec-template.md) 양식 사용. PPTX만 있으면 먼저 PDF로 변환(COM export) 후 분석.
2. **컬러 전략** (핵심 판단):
   - 메인이 블루 계열 → 메인·서브=블루톤, 액센트=레드/오렌지. 그대로 직행.
   - 메인이 레드/오렌지 계열(SK형) → 붉은색을 메인으로 깔면 보고서가 공포물이 됨. **메인·서브=웜 그레이 투톤, 브랜드 레드·오렌지는 액센트로만.** 대비색 블랙/화이트 명시.
3. **유형 최소 3종 설계**: 표지 + 본문 + 결론. 페이지가 늘어나면 본문 유형만 반복된다. 본문 유형은 2~3개(텍스트형/차트형/비교형)면 어떤 분량도 커버. 표지·목차는 1회용이라 서식화 불필요.
4. **샘플 게이트(HITL, 필수)**: 대량 생성 전 샘플 1~3장만 먼저 생성 → 사용자 확인 → 수정 반영 → 스펙 갱신. **스킬/스펙을 만들자마자 바로 대량 생성 금지** (우석지니가 41장 실패로 배운 규칙).
5. **대량 생성**: python-pptx로 생성. 15장 초과 시 파트 분할(10+10+15 등), 파트별 시작 페이지 넘버 지정. 내용 md와 스타일 md는 **로컬 파일로 보존**(재사용·새 세션 대비).
6. **검증**: PowerPoint COM으로 열어 PNG export → 육안 대조(기존 덱 스킬들과 동일 절차). 텍스트는 반드시 실제 텍스트 박스(이미지 속 글자 금지).

## Workflow B — 템플릿 오토필 (레이아웃 불변, 내용만 교체)

기존 PPTX의 도형·레이아웃·서식은 건드리지 않고 텍스트 런만 교체한다(OFFICE MASTER·장피엠 ppt-template-fill 방식).

3가지 케이스별 프롬프트 구조:
- **케이스1 빈 템플릿**: "첨부 양식에 맞춰 문서 작성. 주제는 ___. [세부: 모듈명 구체 기술, 인명 변경, 이력은 주제 맞게 임의 작성]"
- **케이스2 유사 내용 템플릿**: "첨부 양식 유지, 파트는 ___로 구분, 텍스트 수준을 더 세련되고 전문적인 용어·문장으로 재작성"
- **케이스3 전혀 다른 내용 템플릿**: ① 각 슬라이드 구조 분석 → ② 사용자의 업종·직무·역할 시나리오 제시 → ③ 가장 적합한 주제로 재작성. (구조·거버닝 메시지의 '철학'을 읽고 갈아끼우는 방식)

구현: python-pptx로 shape 트리 순회 → text_frame 런 교체(폰트·크기·색 속성 보존). 글자 수가 원본과 크게 다르면 오버플로 경고.

부가 산출물 — **슬라이드 인벤토리 표**: 파일명·슬라이드 번호·유형·비주얼 구조 요약·주요 도형·교체 텍스트 수·적합 주제 키워드·부적합 주제·교체 시 주의사항. 템플릿 자산이 쌓이면 이 표로 "주제 → 슬라이드 추천"이 가능해진다.

## Workflow C — 수정·리페어 (완성본 대상)

받은 PPTX를 python-pptx(+COM)로 조작. 메뉴:
- **오탈자 검수**: 전 슬라이드 텍스트 추출 → 교정 목록 제시 → 승인 후 일괄 교체(차트 내 텍스트 포함).
- **번역**: 원본 훼손 방지 — **슬라이드 복제 후** 복제본만 번역. 번역 후 줄바꿈·오버플로 점검.
- **텍스트 → 시각화**: 개조식 텍스트를 카드/프로세스/차트 다이어그램으로. "N번 슬라이드를 [카드형|프로세스 흐름|차트]로, 변환 전후 수치와 증가율 강조" 패턴.
- **병합/분할**: 두 슬라이드를 좌우 비교 1장으로, 또는 과밀 슬라이드를 2장으로.
- **전체 리디자인**: 기존 내용 유지 + 지정 스타일("모던 에디토리얼" 등 이름 붙여) 재배치. 폰트 지정(강조=Bold/Black, 본문=Medium).
- **엑셀 연계**: 엑셀 데이터 요약 표 → 차트 슬라이드 생성(살아있는 차트로).

## 알려진 버그 3종 + 대응 (반드시 사용자에게 고지)

| 증상 | 원인 | 대응 |
|---|---|---|
| 차트 안 폰트만 맑은 고딕 | 변환 계층 고질 버그 | PPT에서 차트 선택→폰트 일괄 변경 (또는 python-pptx로 chart text 폰트 명시) |
| 차트 레이블이 정수로 반올림 | 값 정수화 버그 | 데이터 레이블 토글 껐다 켜기 → PPT가 재계산 |
| 프리뷰(아티팩트)와 실제 PPTX 불일치 | 프리뷰는 화면용 렌더 | 판단은 항상 다운로드한 PPTX 기준 |

기타 규칙: 수정 어려운 차트는 Ctrl+Shift+G 그룹 해제 후 직접 수정 안내. 배경 있는 이미지는 "슬라이드 배경색과 같은 색 배경으로 생성 → 배경 제거" 기법 안내('투명한 색 설정'은 금지 — 털 달린 걸레 효과). 도형 마스킹은 자유형 도형(클릭-이동-클릭) + 이미지→도형 순 선택 + 도형 병합>교차.

## 모델·비용 규칙

PPT 생성은 고추론이 불필요 — **Sonnet급이면 충분**(품질 차이 미미, 속도·비용 우위). 복잡한 구조 분석·전체 리디자인만 상위 모델. 스펙 추출은 1회 투자이므로 공들여서(이후 생성은 스펙 재사용으로 저렴).
