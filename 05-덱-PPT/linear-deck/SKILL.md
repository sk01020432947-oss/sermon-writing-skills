# Linear Deck — 딥다크 SaaS 발표자료 생성기

linear.app의 디자인 시스템을 재현하는 스킬. 입력(원고·개요·자료)을 받아
**자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 이 스타일은 어둡지만 **분위기로 어두운 것이 아니다.** 글로우도 스포트라이트도 그라디언트도 없다.
> 깊이는 오직 **surface 4단 사다리와 1px 헤어라인**에서 나온다. 빛을 더하고 싶을 때마다
> 그것이 사다리 한 단인지 확인한다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

1. **원고/자료** — 없으면 주제만 받아 개요부터 작성해 확인받는다
2. **제품 UI 스크린샷** — 이 시스템은 **스크린샷이 논증**이다. 있으면 반드시 넣는다.
   없으면 템플릿 내장 미니 UI 목업(`.uikit`)을 쓴다 — 빈 회색 박스로 두지 않는다
3. **출력** — 화면 발표(기본) / PPTX 변환 / PDF 인쇄

## 1. 스타일 토큰 (절대 변경 금지)

```css
--primary:#5e6ad2;   /* 라벤더블루. 브랜드마크·주요 CTA·포커스·링크 강조에만 */
--canvas:#010102;    /* 푸른 기가 도는 근사흑. 순검정(#000)은 캔버스가 아니다 */
--s1:#0f1011; --s2:#141516; --s3:#18191a; --s4:#191a1b;   /* 4단 사다리 */
--hairline:#23252a; --hair-strong:#34343a; --hair-3:#3e3e44;
--ink:#f7f8f8; --ink-muted:#d0d6e0; --ink-subtle:#8a8f98; --ink-3:#62666d;
--success:#27a644;   /* 유일한 의미색 */
```

**색 규칙 (위반 시 스타일 붕괴)**
- **라벤더를 섹션 배경이나 카드 채움으로 쓰지 않는다.** 면을 칠하는 순간 브랜드가 무너진다.
- 두 번째 유채색 악센트(주황·핑크·초록)를 도입하지 않는다.
- **surface 사다리를 건너뛰지 않는다.** s1 다음은 s2다. s1에서 s4로 점프하지 않는다.
- 분위기 그라디언트·스포트라이트 카드를 만들지 않는다.
- **라이트 모드 페이지를 만들지 않는다.** 이 시스템에 밝은 면은 없다.

## 2. 타입 규칙 — 음수 자간이 정체성

| 역할 | 크기(1920 스테이지) | 웨이트 | 자간 |
|---|---|---|---|
| 히어로 h1 | 160px | 600 | **-6px** |
| 섹션 오프너 h2 | 112px | 600 | **-3.6px** |
| 서브섹션 h3 | 80px | 600 | -2px |
| 헤드라인 h4 | 56px | 600 | -1.2px |
| 카드 제목 | 44px | **500** | -0.8px |
| 서브헤드 | 40px | 400 | -0.4px |
| 본문 | 32px | 400 | -0.1px · 행간 1.5 |
| 캡션 | 24px | 400 | 0 |
| 버튼 | 28px | 500 | 0 |
| **eyebrow** | 26px | 500 | **+0.8px (양수)** |

- 표기 크기는 **원본 웹 토큰 × 2**(히어로 80 → 160px). **음수 자간도 함께 2배**다.
- 디스플레이에 음수 자간을 **공격적으로** 건다. 0으로 두면 평범한 SaaS 덱이 된다.
- **eyebrow만 자간이 양수(+0.8px)**다. 디스플레이의 음수 자간과 대비를 만드는 장치다.
- 디스플레이 600 / 본문 400 조합을 고정한다. 카드 제목만 500을 쓴다.
- **폰트**: Linear Display/Text는 사유 폰트다. 스펙이 지정한 폴백(SF Pro → system-ui)을 쓰고
  한글은 Pretendard가 받는다. 스택 순서를 바꾸지 않는다.

## 3. 화면 구조 (16:9 / 1920×1080 고정)

```
┌────────────────────────────────────────────┐
│  EYEBROW (+0.8px 자간, 회색)                 │
│                                            │
│  헤드라인 600 160px                         │  ← 음수 자간 -6px
│  -6px 자간                                  │
│                                            │
│  서브헤드 두 줄까지                           │
│  [시작하기] [문서 보기]                       │  ← 8px(덱 16px) 모서리
└────────────────────────────────────────────┘
```

- 좌우 기준선 `--pad`(112px), 상하 `--sec`(192px).
- 왼쪽 정렬이 기본이다. 중앙 정렬은 CTA 배너(L8)에서만 쓴다.

## 4. 슬라이드 아키타입 (8종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|---|---|---|---|
| L1 | 히어로 | eyebrow + h1 + 서브헤드 + 버튼 2개 | 표지 |
| L2 | 섹션 오프너 | brand eyebrow + h2 | 챕터 전환 |
| L3 | 기능 카드 3-up | surface-1 카드, 강조 카드만 s2 | 기능·항목 나열 |
| L4 | 제품 스크린샷 | 좌 텍스트 40% / 우 스크린샷 패널 | **주력** — 화면으로 증명 |
| L5 | 수치 | 카드 4-up, 숫자 80px/600 | 지표 |
| L6 | 행 나열 | changelog 스타일 헤어라인 행 | 비교·연혁 |
| L7 | 인용 | quote 카드, body-lg | 고객 사례·근거 |
| L8 | CTA 배너 | 중앙 정렬 배너 + 버튼 | 마지막 장 |

**리듬 규칙**
- **L4(스크린샷)가 전체의 30% 이상**이어야 한다. 이 시스템은 제품 화면이 논증이다.
  텍스트만 있는 장이 세 번 연속되면 덱이 죽는다.
- 배경은 대부분 `--canvas`다. `s1`/`s2` 배경 슬라이드는 리듬 환기용으로 2~3회만.
- L2(섹션 오프너)로 챕터를 열고, 챕터 안에서는 L3·L4·L5를 섞는다.

## 5. 원고 → 슬라이드 분해 규칙

1. **한 슬라이드 = 한 주장 + 그 증거.** 증거는 가급적 제품 화면이다.
2. 기능 나열은 카드 3개까지. 4개 이상이면 L6 행 나열로 바꾼다.
3. 수치는 카드 4-up(L5). 단위는 `<em>`으로 0.4em/400으로 낮춰 숫자만 남긴다.
4. 챕터가 바뀌면 L2를 넣는다. eyebrow에 `brand` 클래스를 붙여 라벤더로 표시한다.
5. 마지막은 L8, 버튼 하나로 닫는다.

## 6. 형태 규칙

- **CTA를 pill로 만들지 않는다.** 버튼은 8px(덱 16px) 모서리다. pill은 가격 탭·상태 배지 전용.
- 라운딩 사다리: 버튼 `--r-md` → 카드 `--r-lg` → **스크린샷 패널 `--r-xl`**(카드보다 한 단계 크다).
- 카드 테두리는 항상 1px `--hairline`. 그림자를 넣지 않는다.
- 스크린샷 패널은 바깥 패널(`--r-xl`) + 안쪽 이미지(`--r-lg`)의 이중 라운딩이 규약이다.

## 7. 모션 규칙 (CSS만)

- 페이드 + 16px 상승, `cubic-bezier(.16,1,.3,1)`, **0.55s로 짧게**. 간격 0.09s.
- 애플 계열의 느린 상승(0.9s)과 다르다. 이 시스템의 모션은 **빠르고 절제돼 있다**.
- 글로우·펄스·스포트라이트 금지.
- `@media print`: 애니메이션 해제, 슬라이드당 1페이지.

## 8. 빌드 절차

1. `template.html`(이 스킬 폴더)을 골격으로 사용한다 — 토큰·8종 아키타입·미니 UI 목업·
   발표자 노트가 다 들어 있다. 예시 슬라이드 8장은 교체용 참조다.
2. 원고를 5장 규칙으로 분해해 **슬라이드 시퀀스 표**(아키타입·eyebrow·헤드라인·증거)를
   먼저 만들어 사용자에게 보여준다. **L4 비중이 30% 이상인지 이 표에서 확인한다.**
3. `<section class="slide">` 단위로 생성. 스크린샷은 `.inner`에 `--img:url(...)`로 건다.
4. **발표자 노트**는 `data-note` 속성(HTML 태그 가능, `"` 금지). `S` 토글, 기본 숨김.
   좌우 여백은 `fit()`이 본문 끝선(112px)에 맞춰 계산한다.
5. `{주제}-deck.html`로 저장. **PPTX 변환**은 `../monoline-deck/deck2pptx.py` 공유.
6. **검증**: 첫·중간·마지막 장을 캡처해 점검한다 —
   ① 캔버스가 순검정(#000)이 됐는가 ② 라벤더가 면 채움으로 쓰였는가
   ③ 디스플레이 자간이 0으로 풀렸는가 ④ 버튼이 pill이 됐는가
   ⑤ surface 단계를 건너뛴 곳이 있는가 ⑥ 스크린샷 장이 하나도 없는가.

**함정**
- 한글 파일명으로 저장하면 Edge 헤드리스 캡처가 안 된다. 스크래치패드에 ASCII 이름으로
  복사해 찍는다. `--user-data-dir`을 새로 주면 Edge 새 탭이 찍히므로 쓰지 않는다.
- 음수 자간이 큰 상태에서 한글 제목을 쓰면 자소가 겹쳐 보일 수 있다. 한글 히어로는
  **-6px 대신 -4px 정도로 완화**하고, 영문 제목은 스펙값을 그대로 쓴다.
- `.slide`는 `.active`에서 `display:flex`다. `block`으로 바꾸면 세로 중앙 정렬이 깨진다.

## 9. 조작법 (생성물 안내에 포함할 것)

- `→` / `Space` 다음, `←` 이전, `Home`/`End` 처음·끝, 화면 좌우 클릭·스와이프
- **`S` 발표자 노트 토글** (기본 숨김)
- `#3` 해시로 특정 장 직행, `?shot#3`은 캡처 모드
- 브라우저 인쇄(Ctrl+P, 가로)로 PDF 출력
