# BMW M Deck — 모터스포츠 프리미엄 발표자료 생성기

BMW M 마케팅 서피스의 디자인 시스템을 재현하는 스킬. 입력(원고·개요·자료)을 받아
**자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 이 시스템은 **자체 장식 전압이 0이다.** 브랜드 에너지는 전부 **풀블리드 사진**에서 나오고
> UI는 뒤로 물러난다. 화면을 꾸미려는 모든 충동(그라디언트·그림자·라운딩·색 추가)을 거절한다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

사용자가 이미 밝힌 항목은 건너뛴다:
1. **원고/자료** — 없으면 주제만 받아 개요부터 작성해 확인받는다
2. **사진 소스** — (a) 사용자 제공 폴더 (b) media-gen-image로 생성 (c) 사진 없이 순수 검정 진행.
   **(c)는 절반까지만 유효하다** — 스펙·선언 슬라이드는 순수 검정이 정석이지만, 사진이 0장이면
   이 스타일은 성립하지 않는다. 최소 표지 1장 + 챕터당 1장은 확보한다
3. **출력** — 화면 발표(기본) / PPTX 변환 / PDF 인쇄
4. **전기 모델 톤인가** — 그렇다면 악센트를 `--ev-blue`(#0653b6)로 교체(더 차갑고 디지털한 느낌)

## 1. 스타일 토큰 (절대 변경 금지 — 이 스타일의 정체성)

```css
--canvas:#000;   /* 순검정. #111·#0a0a0a로 흐리면 이 스타일이 아니다 */
--soft:#0d0d0d;  --card:#1a1a1a;  --elev:#262626;  --carbon:#2b2b2b;
--hair:#3c3c3c;  /* 1px 헤어라인 */
--ink:#fff;      --strong:#e6e6e6;  --body:#bbb;  --muted:#7e7e7e;
/* M 트라이컬러 — 브랜드 표식 전용 */
--m-blue-l:#0066b1; --m-blue-d:#1c69d4; --m-red:#e22718;
--ev-blue:#0653b6;  /* 전기 모델 페이지 전용 */
```

**색 규칙 (위반 시 스타일 붕괴)**
- **M 트라이컬러는 CTA 색도 배경 채움도 아니다.** 스트라이프 디바이더·워드마크 악센트·모터스포츠
  표식·모델 배지에만 쓴다. 버튼에 트라이컬러를 칠하는 순간 브랜드가 무너진다.
- 트라이컬러와 헤리티지 블루 밖의 브랜드색을 추가하지 않는다.
- 히어로 타입 뒤에 그라디언트 배경을 깔지 않는다. **깊이는 사진이 만든다.**
- 드롭섀도 0개. 겹침 크롬 0개. 밝기 차이(검정 → `--card`)만으로 층을 만든다.

## 2. 타입 규칙 (이 시스템의 편집 서명)

**초굵은 대문자 헤드라인(700) × 초가는 본문(300)의 극단 대비.** 이 간격이 서명이다.

| 역할 | 크기(1920 스테이지) | 웨이트 | 규칙 |
|---|---|---|---|
| h1 (표지) | 120px | 700 | **대문자**, 트래킹 -0.5px, 2줄 |
| h2 (챕터) | 84px | 700 | **대문자**, 2줄 |
| h3 (섹션) | 60px | 700 | **대문자** |
| 스펙 수치 | 48px | 700 | 단위는 `<em>`로 0.5em/300 |
| 카드 제목 | 36px | 700 | 문장형 허용 |
| 본문 | 24px | **300** | 절대 400·500으로 올리지 않는다 |
| 라벨·버튼 | 21px | 700 | 대문자 + **트래킹 2.25px** |

- 표기 크기는 모두 **웹 토큰 × 1.5** (80px 히어로 → 120px). 트래킹 1.5px → 2.25px도 같이 스케일됐다.
- **본문 볼드 금지.** 400·500으로 올리면 "유럽 공학"이 "마케팅 과장"으로 바뀐다.
- 대문자 라벨의 트래킹을 2.25px 아래로 줄이지 않는다. 이 자간이 "기계로 찍은" 느낌을 만든다.
- 한글 대문자는 없으므로 **한글 헤드라인은 굵기·크기·줄바꿈으로 대문자 효과를 대신한다.**
  영문 라벨·키커·버튼은 반드시 대문자로 둔다 (라벨을 한글로 쓸 땐 트래킹만 유지).

## 3. 화면 구조 (16:9 / 1920×1080 고정)

```
┌──────────────────────────────────────────────┐
│  ▬▬▬  (M 스트라이프 6px)                       │
│  LABEL · 대문자 트래킹                          │
│  헤드라인 두 줄            [풀블리드 사진이       │  ← 좌측 텍스트: left 8%
│  대문자 700 120px          화면 오른쪽을         │     우측: 사진이 화면을 채운다
│                            그대로 채운다]        │
│  보조문장 300 24px 회색                         │
│  BMW M4 · Nürburgring  (오버레이 캡션)          │
└──────────────────────────────────────────────┘
```

- 좌우 기준선 `--pad:8%`. 사진은 이 기준선을 무시하고 **화면 끝까지** 나간다.
- 텍스트 가독은 그라디언트 배경이 아니라 **사진 위 검정 스크림**(`.photo::after`)이 만든다.
- 밴드 간 수직 리듬은 `--sec:144px`(웹 96px × 1.5) 기준.

## 4. 슬라이드 아키타입 (8종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|---|---|---|---|
| A1 | 타이틀 | 풀블리드 사진 + M 스트라이프 + h1 대문자 | 표지 |
| A2 | 사진 밴드 | 풀블리드 사진 + 좌측 텍스트 블록 | 장면·서사·챕터 (가장 자주) |
| A3 | 스펙 셀 | `--soft` 셀 2~4개, 수치 700 + 대문자 라벨 | 성능·수치·핵심 지표 |
| A4 | 카드 3분할 | `feature-photo-card` / `model-card` 혼용 | 항목·사례·모델 나열 |
| A5 | 세로 분할 | 사진 절반 / 텍스트 절반 | 대비·전후·A vs B |
| A6 | 헤어라인 표 | 1px 구분선 행 나열 | 라인업·항목 비교 |
| A7 | 선언 | 순수 검정 + M 스트라이프 + 중앙 2줄 | 챕터 끝·전환·결론 |
| A8 | 클로징 CTA | 풀블리드 사진 + 중앙 h3 + 아웃라인 버튼 | 마지막 장 |

**리듬 규칙 (스펙의 "Don't repeat the same surface mode")**
- **텍스트 전용 밴드 2연속 금지.** 사진 밴드 → 스펙 → 사진 밴드 → 카드 → 사진 밴드로 교차한다.
  텍스트 밴드가 연달아 나오면 모터스포츠가 아니라 사내 보고서가 된다.
- 대략 A2 40% : A3·A6 25% : A4 15% : A5 10% : A7 10%.
- **A7(선언)은 챕터 끝에만**, 전체에서 3~4회. 남발하면 무게가 사라진다.
- M 스트라이프도 남발 금지 — 표지·챕터 첫 장·선언·클로징 정도. **"중요함"을 표시하는 도구다.**

## 5. 원고 → 슬라이드 분해 규칙

1. **한 메시지 = 한 슬라이드.** 원고 문장에서 명사구를 뽑아 **대문자 2줄 헤드라인**을 만들고,
   설명은 보조문장(300)으로 내린다.
   - 원고: "카본 루프로 12kg를 줄여 무게중심을 낮췄습니다"
     → 라벨 `M CARBON` · 헤드라인 `가벼움이 / 곧 속도다` · 보조 `카본 루프 12kg 경량화, 무게중심 하강`
     → 수치가 둘 이상이면 같은 장이 아니라 **A3 스펙 셀**로 뺀다
2. 원고를 **3~5개 챕터**로 묶고, 챕터 첫 장은 A2 + M 스트라이프로 연다.
3. 숫자는 무조건 시각화: 수치 2~4개 → A3, 항목 비교 → A6, 단일 대형 수치 → A3 1칸(`--cols:1`).
4. 챕터 끝 = A7 선언 1장.
5. 표지 A1, 마지막 A8로 닫는다.
6. **애매하면 타입을 키우지 말고 사진을 키운다** (스펙: "bigger photography before bigger type").

## 6. 사진 규칙

- `.photo`에 `--img:url('photo/xxx.jpg')`만 지정하면 **스크림·24초 느린 밀기**가 자동 적용된다.
  직접 filter를 만지지 않는다.
- 사진은 **피사체가 화면을 가득 채운 것**을 고른다. 여백 많은 사진·배경 흐린 스톡컷은
  이 스타일에서 힘이 죽는다. 21:9·16:9 시네마 비율이 정석.
- 생성이 필요하면 media-gen-image 프롬프트:
  `"automotive photography, low angle, car filling the frame, wet asphalt, hard rim light, deep black background, high contrast, carbon fiber detail, no text, 16:9"`
- 스펙·선언 슬라이드(A3·A7)는 **사진 없이 순수 검정**이 정석. 빈 공간은 검정으로 둔다.
- 사진 위 캡션은 `.overlay-cap` 하나만. 좌하단, 회색 300.

## 7. 모션 규칙 (CSS만)

- 전환은 하드컷 → **요소별 순차 등장**(페이드 + 24px 상승). 간격 0.24s, 각 0.75s.
- 등장 순서 고정: **M 스트라이프/라벨(d1) → 헤드라인(d2) → 보조문장(d3) → 비주얼(d4) → 캡션(d5)**.
  클래스 `in d1`~`d5`만 붙인다.
- **M 스트라이프는 왼쪽에서 그어진다**(scaleX). 스케일·회전·바운스는 이 시스템에 없다.
- 사진은 항상 아주 느리게 밀린다(24s).
- `@media print`: 애니메이션 해제, 슬라이드당 1페이지.

## 8. 빌드 절차

1. `template.html`(이 스킬 폴더)을 골격으로 사용한다 — 토큰·8종 아키타입·모션·내비 JS가 다 들어 있다.
   예시 슬라이드 8장은 교체용 참조다.
2. 원고를 5장 규칙으로 분해해 **슬라이드 시퀀스 표**(아키타입·라벨·헤드라인 2줄·보조문장·수치·사진)를
   먼저 만들어 사용자에게 보여준다.
3. `<section class="slide">` 단위로 생성. 사진은 덱 파일 옆 `photo/` 폴더에 두고 상대경로로 참조한다
   (덱과 함께 이동해야 한다).
4. `{주제}-deck.html`로 저장.
5. **PPTX 변환**은 `../monoline-deck/deck2pptx.py`를 공유한다(`class="slide"` + `?shot#N` 규약 동일).
6. **검증**: 헤드리스로 첫·중간·마지막 장을 캡처해 점검한다 —
   ① 라운딩이 생긴 요소가 있는가(원형 아이콘 버튼 외 전부 0px여야 한다)
   ② 본문이 400 이상으로 굵어졌는가 ③ M 트라이컬러가 버튼·배경에 칠해졌는가
   ④ 텍스트 밴드가 2연속인가 ⑤ 사진이 밝아 좌측 대문자 헤드라인이 묻히는가.

**함정**
- **위치 컨테이너(`.lead`·`.cards`·`.specs`)에 `.in`을 걸지 않는다.** rise의 transform이
  `translateY(-50%)` 정렬을 덮어써 블록이 밀린다. `.in`은 항상 자식 요소에 건다.
- `*{border-radius:0}`을 전역으로 깔았다. 원형이 필요한 요소(`.btn-icon`)만 뒤에서 되돌린다.
  새 컴포넌트를 만들면 **기본이 0px**이다.
- Inter → Pretendard 폰트 순서를 바꾸지 않는다. Inter가 라틴 대문자·수치를 잡고
  한글은 글리프가 없어 Pretendard로 자동 폴백된다. 순서를 뒤집으면 라틴 트래킹이 무너진다.

## 9. 조작법 (생성물 안내에 포함할 것)

- `→` / `Space` 다음, `←` 이전, `Home`/`End` 처음·끝, 화면 좌우 클릭·스와이프도 동작
- `#3` 해시로 특정 장 직행, `?shot#3`은 페이지 표시를 숨긴 캡처 모드
- 브라우저 인쇄(Ctrl+P, 가로·배율 조정)로 PDF 출력
