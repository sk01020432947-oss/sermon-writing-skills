# Sketch Deck — 종이 위 손그림 캐릭터 해설 덱

유튜브 해설영상(감자나라ai `qNQ6fGB-cWA` 프레임 실측)의 화면 문법을 재현한다.
입력(원고·주제)을 받아 **자체완결 HTML 덱 1개**를 만든다. 한 슬라이드 = 내레이션 한 문장 = 하단 자막 한 줄.

## 0. 시작 전 확인 (한 턴에 몰아서, 이미 밝힌 것은 건너뜀)

1. **원고** — 구어체 내레이션이 이상적. 없으면 주제로 원고를 먼저 써서 확인받는다
2. **장면 수** — 원고 문장 수 ≈ 슬라이드 수(3분 영상 ≈ 15장). 문장을 세어 제안한다
3. **캐릭터** — 기본 2인(안경·파란 넥타이의 "나", 로봇 "AI"). 다른 인물이 필요하면 §5

## 1. 스타일 토큰 (변경 금지)

```css
--paper:#F8F7F2;  /* 미색 종이. 순백·회색 금지 */
--ink:#1B1B1B;    /* 잉크. 순검정 금지 */
--blue:#1F6FE5;   /* 유일한 유채색 */
--gray:#6F6F6F;   /* 보조 라벨 */
--line:#2A2A2A;   /* 박스 테두리 3px */
```

- 유채색은 **파랑 하나**. 파랑이 가는 자리: 헤드라인 키워드, 하단 자막 키워드, 키커, 박스 번호(01·02), 라벨, 밑줄 바. 그 외 전부 잉크·회색.
- 글꼴 Pretendard Variable 하나. 헤드라인·자막 800, 박스 제목 800, 본문 500~600. 손글씨 글꼴 금지(그건 doodle-deck).
- 선은 **거친 필터**(`filter:url(#rough)`: feTurbulence+feDisplacementMap)로만 손그림 느낌을 낸다. 글자에는 절대 필터를 걸지 않는다 — 박스 테두리는 `::before` 가상요소에만 필터.
- 그림자·그라디언트·둥근 큰 라운드 없음. 박스 radius 8~11px(살짝 비대칭).

## 2. 화면 구조 (1920×1080)

```
┌───────────────────────────────────────────────┐
│ 키커(파랑 20px, 128/56)          우상단 노트(회색) │
│ 헤드라인 56px 800 — 키워드만 파랑 + 손그림 밑줄   │
│                                               │
│   [무대 220~780px: 캐릭터 · 손그림 박스 · 말풍선]  │
│                                               │
│            하단 자막 64px 800 (bottom 88px)      │
└───────────────────────────────────────────────┘
```

- **키커**(`.kicker`): 장면의 섹션명. `CHAT · 방향 잡기`, `11 / 일을 맡길 때` 형식. 파랑.
- **우상단 노트**(`.note`): `설명용 예시` 같은 면책·출처 한마디. 있을 때만.
- **헤드라인**(`h1`): 좌상단 고정. 한 장면(여러 슬라이드)에 하나. 키워드는 `<em>`, 그중 최고 강조 1곳만 `<em class="ul">`(파란 손그림 밑줄이 그어짐).
- **하단 자막**(`.cap`): 내레이션 문장의 **압축(6~12자)**. 키워드 `<em>`. 매 슬라이드 바뀐다 — 이 스타일의 리듬은 자막이 만든다.
- 캐릭터는 무대 좌우 끝, 박스·말풍선은 가운데~오른쪽. 무대의 40%는 비운다.

## 3. 부품 (template.html에 CSS 있음 — 이 밖의 부품을 새로 만들지 않는다)

| 클래스 | 용도 |
|---|---|
| `.box` + `.lab/.t/.s/.n/.bar` | 손그림 박스. `.n`=파란 번호 01, `.lab`=파란 소제, `.t`=제목 30px, `.s`=회색 부연, `.bar`=파란 밑줄 |
| `.box.bubble` | 말풍선(꼬리 좌하단). 질문·요청 프롬프트를 담는다 |
| `.box.quote` | 큰따옴표 인용 한 줄(“세 번째 장을 더 쉽게 바꿔 줘”) |
| `.box.panel` + `.head` | 좌우 비교 패널(Chat vs Work) |
| `.check` | 파란 체크 목록 |
| `.arrow` / `.arrow.blue` | 손그림 화살표(흐름·단계) |
| `.mini` | `질문 → 수정 → 정리` 작은 인라인 흐름 |
| `.art` + `<use href="#man|#bot|#desk|#memo|#scroll|#folder">` | 캐릭터·오브젝트 심볼. `.tag`로 이름표 |

## 4. 원고 → 슬라이드 분해

1. **문장 하나 = 슬라이드 하나.** `data-narr`에 원문(구어체 그대로; 큰따옴표는 `&quot;`), `.cap`에 6~12자 압축(공백 포함, 문장부호 제외).
2. 문장 2~4개가 한 화면 그림을 공유하면 **같은 장면**이다. 기본 묶음: 문제+해결 = 한 장면, 방법의 요청+결과 = 한 장면, 마지막 행동 촉구 = 단독 장면. 헤드라인·키커 동일, 그림은 누적. 첫 슬라이드에서 헤드라인·기본 캐릭터가 `.in`으로 등장하고, 다음 슬라이드에서는 **이어진 요소는 `.in` 없이 그대로 두고 새 요소만 `.in d1…d6`**. (이것이 영상의 "말하는 동안 하나씩 추가되는" 움직임)
3. 나열("N가지")은 `.box` 카드 + `.n` 번호를 가로로. 절차는 카드 사이 `.arrow`.
4. 프롬프트·요청문은 반드시 `.bubble`(말하는 중)이나 `.quote`(인용) 안에. 본문 텍스트로 풀어 쓰지 않는다. 말풍선 꼬리는 좌하단 고정이므로 **말풍선은 화자의 오른쪽 위**에 놓는다.
5. 비교는 `.panel` 둘. 판단·결론은 `.check`.
6. 마지막 슬라이드는 전체 흐름을 캐릭터·화살표 한 줄로 요약하고 자막은 행동 촉구("오늘 할 일을 한 문장으로").

## 5. 캐릭터

- 기본은 template의 인라인 SVG 심볼(`#man` 안경+파란 넥타이, `#bot` 로봇). 추가 오브젝트는 같은 규칙(stroke 2.6, round cap, 채움은 `fill` 속성 직접 — `<symbol>` 안에서는 문서 CSS 클래스가 적용되지 않는다).
- 영상처럼 **그림체가 더 풍부한 캐릭터**가 필요하면 이미지 생성(사용 가능한 이미지 스킬·도구)으로 만들어 `<img>`로 넣는다. 프롬프트 골격:
  `"hand-drawn ink sketch, thin black outline, minimal cross-hatching, mostly white with one blue accent (#1F6FE5 tie/badge), cream paper background #F8F7F2, no text, full body, friendly office worker with round glasses / cute round robot"`
  같은 캐릭터는 **한 장의 레퍼런스 이미지**를 고정하고 모든 장면에 그 이미지를 참조시킨다(장면끼리 체인 참조 금지). 배경은 종이색과 같게 요청해 합성 티를 없앤다.

## 6. 빌드 절차

1. `template.html`(이 폴더)을 복사해 골격으로 쓴다 — 토큰·부품 CSS·심볼·내비 JS가 들어 있고, 예시로 영상 원본 15장면이 그대로 들어 있다. `<!-- SLIDES START -->`~`<!-- SLIDES END -->` 사이만 갈아 끼우고 `<title>`을 주제로 바꾼다.
2. 원고를 §4로 분해해 **장면표**(장면 / 슬라이드 / 자막 / 새로 등장하는 요소)를 만든다. 20장 이하면 보고만 하고 바로 빌드, 20장 초과면 표를 보이고 확인받는다.
3. `<section class="slide" data-narr="…">` 단위로 생성.
4. `{주제}-sketch-deck.html`로 Documents 또는 지정 위치에 저장.
5. **검증**: 헤드리스 크롬으로 첫 장·장면 전환 장·마지막 장을 찍어 본다 — 유채색 위반, 자막 12자 초과, 요소 겹침(특히 말풍선 vs 캐릭터 머리)을 본다. 스크린샷은 세션 스크래치패드에 둔다. URL은 `?shot` 뒤에 `#N`(순서 고정).
   ```bash
   "/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" --headless=new --disable-gpu --hide-scrollbars --window-size=1920,1080 --virtual-time-budget=4000 --screenshot="$SCRATCH/s1.png" "file:///…/deck.html?shot#1"
   ```

## 7. 조작·산출 (생성물 안내에 포함)

- `→`/`Space` 다음, `←` 이전, `Home`/`End`, 화면 좌/우 클릭, 스와이프
- `N` = 내레이션 패널 토글(녹음·TTS 대본 확인용), `#N` = N번 슬라이드, `?shot` = 카운터 숨김
- `?auto=4` = 4초마다 자동 진행 — 화면 녹화(QuickTime/OBS)로 영상화할 때
- 인쇄(⌘P) → PDF, PPTX는 `python3 ~/.claude/skills/monoline-deck/deck2pptx.py 덱.html` (공유 변환기)
- 영상 제작 파이프라인(TTS·자막 타이밍·mp4)은 `explainer-video`/`remotion` 스킬이 담당. 이 스킬은 화면까지.
