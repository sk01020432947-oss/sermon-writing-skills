# Genie Deck — 딥퍼플 머티리얼 컨설팅 슬라이드 생성기

우석지니 "제미나이 바이브 코딩 프레젠테이션" 영상의 결과물 덱을 실측 재현한 스킬.
입력(원고·회사자료·개요)을 받아 **자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 이 스타일은 컨설팅 문법의 덱이다: 슬라이드마다 **헤드라인(주장) + 거버닝 메시지(근거 요약) + 카드(증거)**.
> 화려한 전환 대신 **호버 리프트 하나**로 "지금 여기를 말하고 있다"를 보여준다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

사용자가 이미 밝힌 항목은 건너뛴다:
1. **원고/자료** — 회사소개서·IR·제안서 등. 없으면 주제만 받아 페이지별 개요부터 작성해 확인받는다
2. **슬라이드 수** — 표지 + 내용 + 클로징. 보통 8~12장. 내용은 4~5개 파트로 묶는다
3. **브랜드명** — 상단 우측 브레드크럼에 들어갈 회사/조직명 (대문자 영문 권장)
4. **표지/클로징 이미지** — 사용자가 만든 PNG가 있으면 배경으로 링크, 없으면 타이포 표지 생성
5. **출력** — 화면 발표(기본) / A4 인쇄 겸용 / PPTX

## 1. 원문 보존 원칙 (영상의 핵심 방법론 — 스타일보다 먼저다)

원본 강의가 가장 강조하는 규칙. AI는 내용을 다듬고 축약하려는 경향이 있다 — 이 스킬에서는 금지한다.

- 사용자가 준 원문(불릿·수치·고유명사·문구)을 **100% 유지**한다. 임의 요약·생략·삭제·축약·변형 금지.
- 새로운 내용을 창작하거나 덧대지 않는다. 슬라이드에 넣을 문구가 부족하면 **사용자에게 물어본다**.
- 허용되는 것은 **배치**뿐이다: 어느 카드에 어느 불릿을 넣을지, 어떤 아키타입으로 보여줄지.
- 원문이 슬라이드 그릇보다 길면 자르지 말고 슬라이드를 쪼갠다.

## 2. 스타일 토큰 (절대 변경 금지 — 영상 프레임 실측값)

```css
--purple:#562EA1;      /* 브랜드 딥퍼플: 표지·클로징 배경, 헤드라인, 강조 */
--purple-deep:#4A1F8F; /* 거버닝 바, 바 차트 그라디언트 진한 쪽 */
--violet:#7B38E8;      /* 바 차트 그라디언트 밝은 쪽 */
--canvas:#F2F5F7;      /* 슬라이드 캔버스 — 아주 옅은 회색, 순백 금지 */
--card:#FFFFFF;        /* 카드 — 캔버스 위에서만 흰색이 산다 */
--ink:#1A2233;         /* 카드 타이틀·강조 */
--body:#3C4447;        /* 본문 */
--mute:#8A94A0;        /* 캡션·비활성 브레드크럼·각주 */
--track:#E4E8EB;       /* 차트 트랙·표 괘선·타임라인 연결선 */
--letterbox:#0F172A;   /* 화면 여백 레터박스 (Tailwind slate-900 실측) */
```

**색 규칙**
- **악센트는 딥퍼플 단일.** 헤드라인·거버닝 바·KPI 숫자·차트·타임라인이 전부 퍼플 계열 하나로 간다. 제2 악센트 금지.
- 그라디언트는 **바 차트에만** (`--purple-deep → --violet`, 90deg). 텍스트·배경 그라디언트 금지.
- 그림자는 중립 회색(`rgba(15,23,42,…)`)만. 색 있는 글로우 금지.
- 풀퍼플 면은 표지·클로징 두 장뿐. 내용 슬라이드에 큰 퍼플 색면을 깔지 않는다.

**타이포**
- 헤드라인: Poppins 800 64px. **한글 헤드라인은 `class="ko"`** (Noto Sans KR 900, 행간 1.18) — 라틴 행간 1.12를 한글에 그대로 쓰면 받침이 물린다.
- 본문: Noto Sans KR. 카드 불릿 22px, 거버닝 25px, 캡션 17px.
- 표지 타이틀은 굵기 대비가 핵심: 800 라인과 `<span>`(300) 라인을 번갈아 쌓는다.

## 3. 슬라이드 해부도 (16:9 / 1920×1080 고정)

```
┌──────────────────────────────────────────────────┐
│ INTRODUCTION  PART 01 | …  PART 02 | …   브랜드 | n/N │ ← .partnav (현재 파트만 <b>)
│ Headline Statement                                │ ← h1 64px 퍼플
│ ▌거버닝 메시지 1~2줄 (퍼플 좌측 바)                  │ ← .gov
│                                                  │
│   [흰 카드들 — 호버하면 살짝 떠오르며 그림자]          │ ← .zone (top 345px)
│                                                  │
└──────────────────────────────────────────────────┘
```

- **파트 내비**: 목차가 곧 내비다. `Introduction | Part 01~04` 형식, 현재 파트만 `<b>`(퍼플+밑줄). 우측 `.brand`에는 브랜드명만 쓴다 — `| n / N` 페이지 번호는 JS가 자동으로 붙인다.
- **헤드라인**: 명사구보다 **주장 문장**("Where AI Agent Services Begin"). 최대 2줄.
- **거버닝 메시지**: 그 슬라이드의 근거 요약 1~2줄. 표지·클로징 외 **전 슬라이드 필수**.
- **호버 리프트**: `.card`·`.track`·`.tl`에 내장(-8px + 그림자). 발표 중 마우스로 "지금 이 카드"를 가리키는 용도 — 추가 애니메이션을 더 넣지 않는다.

## 4. 슬라이드 아키타입 (8종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|------|------|------|-----------|
| G1 | 표지 | 풀퍼플 + 굵기 교차 대형 타이포 + 로고 (또는 이미지 링크) | 첫 장 |
| G2 | 리드 카드 | 카드 1장 풀폭: 아이콘 타이틀 + 불릿 3~4 | 도입·정의·문제 제기 |
| G3 | 2열 카드 | 카드 2장 대비 (Vision/Mission, Before/After) | 대조·양축 설명 |
| G4 | 3열 카드 | 카드 3장 병렬 (제품군·서비스 라인) | 병렬 나열 |
| G5 | KPI 스탯 | 스탯 카드 3장(대형 퍼플 숫자) + 하단 요약 카드 | 성과·수치 증명 |
| G6 | 바 차트 | 카드 1장: 그라디언트 가로 바 + 각주 | 성장·비교 수치 |
| G7 | 타임라인 | 연도 + 아이콘 원 4개 + 연결선, 마지막만 `.fill` | 로드맵·연혁 |
| G8 | 클로징 | 풀퍼플 + 원형 마크 + 굵기 대비 한 줄 + 로고 | 마지막 장 |

**리듬 규칙**
- 같은 아키타입 연속 금지 (G3→G3 대신 G3→G6→G4처럼 섞는다). 영상 원본도 리드→2열→차트→3열→KPI→타임라인 순환이다.
- G1은 첫 장만, G8은 마지막 장만. G5·G6(숫자 슬라이드)는 파트당 1장이면 충분하다.
- 표가 필요하면 카드 안에 `<table>` — thead는 ink 굵은 밑줄, 강조 셀만 `class="hl"`(퍼플).

## 5. 원고 → 슬라이드 분해 규칙

1. 원고를 **4~5개 파트**로 묶고 파트명을 정한다 (Introduction / Company / Technology / Service / Experience 식). 이것이 전 슬라이드 상단 내비가 된다.
2. 슬라이드 하나 = 주장 하나. 주장을 헤드라인 문장으로, 근거 요약을 거버닝 메시지로 쓴다.
3. 내용 형태로 아키타입을 고른다: 대조=G3, 병렬 셋=G4, 수치 증명=G5/G6, 시간축=G7, 그 외=G2.
4. 불릿은 카드당 3~4개가 상한. 넘치면 카드를 쪼개거나 슬라이드를 나눈다 — 원문을 자르지 않는다(§1).
5. 아이콘은 카드 타이틀당 1개, 인라인 SVG(Lucide 계열 24×24 stroke)로 넣는다. 외부 폰트·CDN 아이콘 금지 — 템플릿의 SVG를 복사해 쓰거나 같은 문법으로 그린다.

## 6. 표지·클로징 이미지 슬롯 (영상의 핵심 워크플로)

원본 강의는 표지·클로징만큼은 "회사 톤앤매너가 중요하니 직접 만들어 링크하라"고 가르친다.

- 사용자가 PNG를 주면: `<section class="slide cover" style="background-image:url('cover.png')">` 로 배경만 걸고 내부 `.wrap`을 비운다. **덱 HTML과 같은 폴더에 이미지를 두라고 안내한다.**
- 없으면: 템플릿의 타이포 표지(굵기 교차 스택)를 내용에 맞게 채운다.
- 나중에 교체할 수 있게 두 슬라이드의 주석을 남겨 둔다 (템플릿에 이미 있음).

## 7. 빌드 절차

1. `template.html`을 골격으로 사용한다 — 토큰·8종 아키타입·내비·노트·인쇄 CSS가 다 들어 있다.
2. 원고를 5단계 규칙으로 분해해 **슬라이드 시퀀스 표**(아키타입·파트·헤드라인·거버닝·카드 구성)를 만들어 사용자에게 보여준다.
3. `<section class="slide">` 단위로 생성. 템플릿의 샘플 슬라이드는 전부 교체한다.
4. `{주제}-deck.html`로 저장.
5. **검증**: 헤드리스 캡처로 ① 카드가 `.zone` 밖으로 넘치지 않는가 ② 한글 헤드라인에 `ko` 클래스가 붙었는가
   ③ 파트 내비의 `<b>`가 실제 파트 진행과 일치하는가 ④ 거버닝 메시지가 3줄로 넘치지 않는가를 본다.
   한글 파일명은 스크래치패드에 `chk.html`로 복사한 뒤 **PowerShell 도구**로 Edge 헤드리스 캡처(`?shot#N`).

## 8. 조작법 (생성물 안내에 포함할 것)

- `F11` = 전체화면 발표. 화면 **좌/우 절반 클릭** = 이전/다음 (영상 시그니처), `→`/`Space`/`←`, `Home`/`End`
- 카드에 마우스를 올리면 떠오른다 — 발표 중 포인팅 용도
- `S` = 발표자 노트 토글 (`data-note` 속성, 하단 패널)
- `#N` = N번 슬라이드 바로 열기, `?shot` = 페이지 표시 숨김(캡처용)
- **A4 인쇄**: Ctrl+P → 가로 방향, 슬라이드당 1페이지로 잡힌다(@page A4 landscape 내장). 여백 없음 확인

## 9. PPTX 변환

monoline-deck 스킬의 변환기를 그대로 쓴다 (`class="slide"` + `?shot#N` 규약 동일):

```bash
python3 /Users/kbg1023/.claude/skills/monoline-deck/deck2pptx.py "덱파일.html"
```

같은 폴더에 같은 이름의 `.pptx`가 생성된다. 의존성: python-pptx, Edge 또는 Chrome.
