# Airbnb Deck — 소비자 마켓플레이스형 발표자료 생성기

airbnb.com의 디자인 시스템을 재현하는 스킬. 입력(원고·개요·자료)을 받아
**자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 이 시스템은 **사진과 여백으로 온기를 만든다.** 색은 Rausch 하나뿐이고 그마저 아껴 쓴다.
> 따뜻함을 색으로 더하려는 순간(파스텔 추가, 그라디언트) 다른 브랜드가 된다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

1. **원고/자료** — 없으면 주제만 받아 개요부터 작성해 확인받는다
2. **사진** — 이 시스템은 **사진 카드 그리드가 주력**이다. 4장 이상 확보하는 것이 좋다.
   없으면 템플릿의 따뜻한 그라디언트 플레이스홀더가 대신하지만 힘이 절반으로 준다
3. **출력** — 화면 발표(기본) / PPTX 변환 / PDF 인쇄

## 1. 스타일 토큰 (절대 변경 금지)

```css
--rausch:#ff385c;         /* 유일한 브랜드 전압. 화면당 하나 */
--rausch-active:#e00b41;
--ink:#222; --body:#3f3f3f; --muted:#6a6a6a; --muted-soft:#929292;
--hairline:#ddd; --hairline-soft:#ebebeb;
--canvas:#fff; --soft:#f7f7f7; --strong:#f2f2f2;
/* 그림자는 사실상 한 단계뿐이다 */
--shadow:rgba(0,0,0,.02) 0 0 0 1px, rgba(0,0,0,.04) 0 4px 12px, rgba(0,0,0,.1) 0 8px 16px;
```

**색 규칙 (위반 시 스타일 붕괴)**
- **Rausch는 화면당 하나.** 주 CTA·검색 오브·평점 점에만 쓴다.
- Luxe(#460479)·Plus(#92174d)는 서브브랜드 색이다. **일반 덱에서 쓰지 않는다.**
- 파스텔·그라디언트를 추가하지 않는다. 온기는 사진이 만든다.
- 텍스트 위계는 #222 → #3f3f3f → #6a6a6a 세 단계로 내린다.

## 2. 타입 규칙 — 알려진 스케일 승격

원본은 **마케팅 디스플레이 스케일이 없다.** 홈 h1이 28px, 가장 큰 토큰이
`rating-display` 64px/700/-1px다(리스팅 평점 표시용). 1920 덱에서 28px×2=56px는 표지로 약하다.

> **이 스킬의 판단:** `rating-display`(64/700/-1px)를 **덱의 히어로 목소리로 승격**하고,
> 나머지 토큰은 원본 × 2를 유지한다. 이 승격은 스펙에 없는 확장이므로 여기 명시해 둔다.

| 역할 | 크기(1920 스테이지) | 웨이트 | 자간 |
|---|---|---|---|
| 히어로 h1 (승격) | 128px | 700 | -2px |
| 섹션 h2 | 56px | 700 | 0 |
| 리스팅형 h3 | 44px | 500 | -0.88px |
| 서브섹션 h4 | 40px | 600 | -0.36px |
| 본문 | 32px | 400 | 0 · 행간 1.5 |
| 카드 메타·가격 | 28px | 400/600 | 0 |
| 배지 | 22px | 600 | 0 |

- **폰트**: Airbnb Cereal은 사유 폰트다. 지오메트릭 산세 대체로 Inter, 한글은 Pretendard.

## 3. 슬라이드 아키타입 (8종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|---|---|---|---|
| A1 | 표지 | 히어로 + **검색 pill** | 첫 장 (검색바가 브랜드 표식) |
| A2 | 사진 카드 4-up | 카테고리 스트립 + 카드 그리드 | **주력** — 항목 나열 |
| A3 | 2단 사진 | 좌 텍스트 / 우 큰 사진 | 서사·사례 |
| A4 | 큰 숫자 | rating-display 크기 수치 3개 | 지표 |
| A5 | 항목 행 | 얕은 헤어라인 행 | 포함 항목·명세 |
| A6 | 결정 카드 | 좌 맥락 / 우 예약형 카드 + Rausch | 제안·결정 |
| A7 | 정보 카드 3-up | 원형 아이콘 + 테두리 카드 | 기능 설명 |
| A8 | 클로징 | CTA + 푸터 링크 | 마지막 장 |

**리듬 규칙**
- **A2(사진 카드)가 전체의 30% 이상.** 이 시스템은 사진 그리드로 말한다.
- 흰 캔버스와 `--soft`(#f7f7f7)를 번갈아 리듬을 만든다.
- **사진 카드와 정보 카드를 한 장에 섞지 않는다.** 두 카드 문법이 충돌한다.

## 4. 원고 → 슬라이드 분해 규칙

1. **한 카드 = 한 항목**, 제목 한 줄 + 메타 한 줄 + 수치 한 줄. 카드 안에 문단을 넣지 않는다.
2. 수치는 A4로 빼고 rating-display 크기로 키운다.
3. 결정·제안은 A6 한 장으로 모으고 Rausch 버튼을 거기 둔다.
4. 마지막은 A8, Rausch 하나 + 아웃라인 하나.

## 5. 형태 규칙

- **카드 라운딩 14px(덱 28px)** — 이 시스템의 서명이다. 8px도 20px도 아니다.
  큰 사진 면은 한 단계 키워 20px(덱 40px).
- 버튼은 **8px(덱 16px) 라운딩**이 기본이고, pill은 검색바·오브·배지·필터에만.
- 아이콘 버튼은 언제나 원형.
- **그림자는 한 단계뿐**이다. 기본은 그림자 없음 + 1px 헤어라인, 강조할 카드에만 `--shadow`.

## 6. 모션 규칙 (CSS만)

- 페이드 + 20px 상승, 0.6s, 간격 0.10s. 부드럽고 따뜻하게.
- 사진 확대·패럴랙스 금지. 사진은 정지해 있고 카드가 등장한다.
- `@media print`: 애니메이션 해제, 슬라이드당 1페이지.

## 7. 빌드 절차

1. `template.html`을 골격으로 사용한다 — 토큰·8종 아키타입·검색 pill·발표자 노트 포함.
2. 원고를 4장 규칙으로 분해해 **슬라이드 시퀀스 표**(아키타입·배경면·제목·사진 유무)를 먼저 보여준다.
   **Rausch가 장마다 하나인지, A2 비중이 충분한지 여기서 확인한다.**
3. 사진은 `.photo`/`.hero-photo`에 `--img:url(...)`로 건다.
4. **발표자 노트**는 `data-note` 속성(HTML 태그 가능, `"` 금지). `S` 토글, 기본 숨김.
5. `{주제}-deck.html`로 저장. **PPTX 변환**은 `../monoline-deck/deck2pptx.py` 공유.
6. **검증**: 첫·중간·마지막 장을 캡처해 점검한다 —
   ① Rausch가 한 장에 둘 이상인가 ② 카드 라운딩이 14px에서 벗어났는가
   ③ 그림자를 여러 단계로 늘렸는가 ④ 사진 카드와 정보 카드를 섞었는가
   ⑤ 파스텔·그라디언트를 추가했는가.

**함정**
- 한글 파일명은 Edge 헤드리스 캡처가 안 된다. 스크래치패드에 ASCII 이름으로 복사해 찍는다.
  `--user-data-dir`을 새로 주면 Edge 새 탭이 찍히므로 쓰지 않는다.
- 원본 스케일이 작아 **여백을 원본 비율로 두면 덱이 헐거워 보인다.** 템플릿은 여백을 ×2로
  키워 균형을 맞췄다. 여기서 더 늘리지 않는다.
- 검색 pill은 표지 전용이다. 매 장에 넣으면 UI 목업처럼 보인다.

## 8. 조작법 (생성물 안내에 포함할 것)

- `→` / `Space` 다음, `←` 이전, `Home`/`End` 처음·끝, 화면 좌우 클릭·스와이프
- **`S` 발표자 노트 토글** (기본 숨김)
- `#3` 해시로 특정 장 직행, `?shot#3`은 캡처 모드
- 브라우저 인쇄(Ctrl+P, 가로)로 PDF 출력
