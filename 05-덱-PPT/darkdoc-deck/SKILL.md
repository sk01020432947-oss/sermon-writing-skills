# Darkdoc Deck — 다크 시네마틱 다큐 발표자료 생성기

유튜브 다큐멘터리형 해설영상 스타일을 재현하는 스킬. 입력(원고·개요·자료)을 받아
**자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

> 이 스타일은 "밝은 화면에 정보를 얹는" 것이 아니라 **어둠 위에 빛 몇 점만 남기는** 방식이다.
> 화면의 70% 이상이 거의 검다. 밝힐 곳을 늘리는 모든 유혹을 거절한다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

사용자가 이미 밝힌 항목은 건너뛴다:
1. **원고/자료** — 없으면 주제만 받아 개요부터 작성해 확인받는다
2. **배경 이미지 소스** — (a) 사용자 제공 폴더 (b) media-gen-image로 생성 (c) 없이 순수 암전 진행.
   **(c)도 완전히 유효하다** — 원본 영상도 데이터·선언 슬라이드는 순수 검정 배경이다
3. **출력** — 화면 발표(기본) / PPTX 변환 / PDF 인쇄

## 1. 스타일 토큰 (절대 변경 금지 — 이 스타일의 정체성)

```css
--bg:#0D0E13;     /* 청색기 도는 근사흑. 순검정(#000)·회색(#222) 금지 */
--ink:#E8E6DE;    /* 따뜻한 오프화이트. 순백(#fff) 헤드라인 금지 */
--dim:#7C7C80;    /* 보조문장 */
--micro:#5E6068;  /* 마이크로 라벨 */
--line:#2A2C34;   /* 헤어라인 */
/* 씬 악센트 — 슬라이드당 정확히 1개 */
--amber:#C08A2E; --blue:#3E73AC; --red:#8E3A31; --ice:#2E5A86;
```

**색 규칙 (위반 시 스타일 붕괴)**
- **슬라이드 하나에 악센트색은 1개.** 두 색이 나오는 유일한 예외는 A vs B 비교 차트(대립 = 레드 vs 블루).
- 악센트는 **의미에 묶는다**: 호박=자원·돈·기술, 블루=기계·데이터·냉정, 브릭레드=위험·실패·경고, 아이스=심층·숨은 것.
- 채도 높은 원색·형광·그라디언트 배경 금지. 악센트도 이미 죽인 색이다.
- 흰색은 **자막 한 곳에만** 쓴다. 나머지 텍스트는 전부 오프화이트/회색.

## 2. 화면 구조 (16:9 / 1920×1080 고정)

```
┌──────────────────────────────────────────────┐
│                                              │
│   ● 키커 라벨                                  │  ← 좌측 정보블록: left 8%, 세로중앙
│   헤드라인 두 줄                     [비주얼]   │  ← 우측 비주얼존: left 44%~94%
│   볼드 63px                        차트/노드/  │
│                                    카드/인물   │
│   보조문장 두 줄 회색 23px                      │
│                                              │
│              내레이션 자막 (흰 볼드 30px)        │  ← bottom 6.2%, 중앙
└──────────────────────────────────────────────┘
```

- **키커**: 악센트색 8px 원 + 라벨(17px, weight 600, **자간 .28em**). 시간·장소·출처·챕터명. 최대 14자.
- **헤드라인**: 63px / weight 700 / line-height 1.22 / 자간 -.025em. **정확히 2줄**, 줄당 3~7자.
  긴 문장은 헤드라인이 아니라 보조문장으로 내린다. 한 줄짜리 헤드라인은 리듬이 죽는다.
- **보조문장**: 23px, 회색, line-height 1.85, 2줄. 헤드라인을 **설명하지 말고 이어서 말한다**.
- **자막(.cap)**: 그 장면에서 실제로 말하는 한 문장. 원고의 구어체 그대로. 1줄(최대 34자).
  발표용으로 노트가 더 필요하면 `.cap.multi`(25px)로 2줄까지 허용.

## 3. 슬라이드 아키타입 (7종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|------|------|------|-----------|
| S1 | 풀블리드 + 정보블록 | 어둡게 깐 b-roll 전면 + 좌측 블록 | 장면·서사·분위기 (가장 자주) |
| S2 | 정보블록 + 차트 | 좌측 블록 + 우측 막대 비교 | 수치 대결·전후 비교 |
| S3 | 히어로 숫자 | 중앙 거대 숫자(150px, weight 300) + 단위 | 금액·연도·비율 한 방 |
| S4 | 중앙 선언 | 중앙 2줄(66px), 둘째 줄 악센트색 + 배경 고스트 글리프 | 질문·전환·결론 |
| S5 | 세로 분할 | 화면 중앙 1px 악센트 세로선 + 한쪽에만 텍스트 | 대비·"이쪽 vs 저쪽" |
| S6 | 인물 카드 | 원형 인물 + 다크 카드(직함) + 필요시 붉은 사선(부정) | 실존 인물 등장 |
| S7 | 노드 체인 | 악센트 테두리 노드 + 1px 연결선 + 캡션 | 흐름·변환·구조 |

**리듬 규칙**
- 같은 아키타입 3연속 금지. S1(장면) 사이에 S3/S4(중앙형)를 끼워 호흡을 만든다.
- 대략 S1 45% : S2·S7 25% : S3·S4 20% : S5·S6 10%.
- **S4(선언)는 챕터 끝에만.** 남발하면 무게가 사라진다. 전체에서 3~4회.

## 4. 원고 → 슬라이드 분해 규칙

1. **한 문장 = 한 슬라이드.** 자막에 원고 문장을 그대로 넣고, 그 문장에서 **명사구 2~3개를 뽑아** 헤드라인 2줄을 만든다.
   - 원고: "기존 방식이 26.2%를 틀렸다고 하면" → 헤드라인 `오류율 / 대결`, 키커 `ILSVRC 2012`, 보조 `기존 방식이 26.2% 틀릴 때 / 알렉스넷은 15.3%`
2. 원고를 **3~6개 챕터**로 묶고, 챕터마다 **악센트색 1개**를 배정한다. 챕터가 바뀔 때만 색이 바뀐다.
3. 숫자가 나오면 무조건 시각화한다: 단일 수치 → S3, 두 수치 비교 → S2, 흐름 → S7.
4. 실존 인물·기업이 처음 등장하면 S6 카드 1장.
5. 챕터 끝 = S4 선언 1장으로 닫는다.
6. 표지는 S3(연도) 또는 S4(제목), 마지막은 S4(질문/결론)로 끝낸다.

## 5. 배경 b-roll 규칙

- `.bg`에 `--img:url('broll/xxx.jpg')`만 지정하면 **어둡게 깔기·좌측 스크림·비네트·22초 켄번스 줌**이 자동 적용된다. 직접 filter를 만지지 않는다.
- 사진은 **어둡고 심도 얕고 인물 얼굴이 정면으로 없는 것**을 고른다. 밝은 사진은 아무리 눌러도 이 스타일이 안 나온다.
- 생성이 필요하면 media-gen-image 프롬프트:
  `"cinematic still, very low key lighting, deep shadows, muted desaturated colors, shallow depth of field, film grain, night, 16:9"`
- **데이터·선언 슬라이드(S2/S3/S4/S7)는 배경 없이 순수 암전이 정석**이다. 사진을 넣고 싶은 충동을 참는다.

## 6. 모션 규칙 (CSS만)

- 씬 전환은 **크로스페이드가 아니라 하드컷 → 암전 → 요소별 순차 등장**이다. (원본 영상 계측: 요소 간격 ≈0.24s, 각 0.75s)
- 등장 순서 고정: **키커(d1) → 헤드라인(d2) → 보조문장(d3) → 비주얼(d4) → 자막(d5)**. 클래스 `in d1`~`d5`만 붙이면 된다.
- 막대는 **바닥에서 위로 자란다**(scaleY, 1.05s, 0.55s 지연). 연결선·분할선은 **그어진다**(scaleX/scaleY).
- 배경은 항상 아주 느리게 확대된다(22s). 정지 배경은 이 스타일에서 죽은 화면이다.
- `@media print`: 전 애니메이션 해제, 최종 상태 고정, 슬라이드당 1페이지.

## 7. 빌드 절차

1. `template.html`(이 스킬 폴더)을 골격으로 사용한다 — 토큰·7종 아키타입·모션·내비 JS가 다 들어 있다. 예시 슬라이드 7장은 교체용 참조다.
2. 원고를 4단계 규칙으로 분해해 **슬라이드 시퀀스 표**(아키타입·키커·헤드라인 2줄·보조문장·자막·악센트색·배경)를 먼저 만들어 사용자에게 보여준다.
3. `<section class="slide">` 단위로 생성. 챕터 악센트는 `style="--accent:var(--blue)"`로 슬라이드에 건다.
4. 배경 이미지는 덱 파일 옆 `broll/` 폴더에 두고 상대경로로 참조한다(덱과 함께 이동해야 함).
5. `{주제}-deck.html`로 저장.
6. **검증**: 브라우저로 열어 첫·중간·마지막 슬라이드를 캡처해 점검한다 —
   ① 한 슬라이드에 악센트 2색 이상 섞였는가 ② 헤드라인이 1줄이거나 4줄이 됐는가
   ③ 배경이 너무 밝아 좌측 텍스트가 묻히는가 ④ 자막이 문어체로 딱딱해졌는가.

**이미 밟은 함정 두 개**
- `.info`·`.viz` 같은 **위치 컨테이너에 `.in`을 걸지 않는다.** rise 애니메이션의 transform이 정렬을 덮어써 블록이 아래로 밀린다. `.in`은 항상 자식(키커·헤드라인·보조문장)에 건다.
- **고스트 글리프(S4)에 한자를 쓰지 않는다.** Pretendard 동적 서브셋에 없어 폴백 글꼴로 뭉개진 덩어리가 된다. 한글 한 글자 또는 숫자만.

## 8. 조작법 (생성물 안내에 포함할 것)

- `→`/`Space` = 다음, `←` = 이전, `Home`/`End` = 처음/끝, 화면 좌/우 절반 클릭도 동일
- `#N` = N번 슬라이드 바로 열기, `?shot` = 페이지 표시 숨김(캡처용)
- Ctrl+P → PDF 저장 시 슬라이드당 1페이지

## 9. PPTX 변환

monoline-deck 스킬의 변환기를 그대로 쓴다 (`class="slide"` + `?shot#N` 규약이 동일):

```bash
python3 /Users/kbg1023/.claude/skills/monoline-deck/deck2pptx.py "덱파일.html"
```

같은 폴더에 같은 이름의 `.pptx`가 생성된다. 의존성: python-pptx, Edge 또는 Chrome.
