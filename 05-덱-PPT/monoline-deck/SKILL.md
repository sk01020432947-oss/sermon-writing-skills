# Monoline Deck — 흑백 라인아트 모션 발표자료 생성기

유튜브 해설영상형 발표 스타일(순백 배경 + 흑백 라인아트 + 부분볼드 자막)을 재현하는 스킬.
입력(원고·개요·자료)을 받아 **자체완결 HTML 슬라이드 덱 1개 파일**을 생성한다.

## 0. 시작 전 확인 (한 턴에 몰아서 질문)

사용자가 이미 밝힌 항목은 건너뛴다:
1. **원고/자료** — 없으면 주제만 받아 개요부터 작성해 확인받는다
2. **섹션 수** — 스테퍼 아이콘 개수(3~8개 권장). 원고에서 자동 분해 후 확인
3. **출력 용도** — 화면 발표(기본) / PDF 인쇄 병용 (인쇄 시 애니메이션 최종상태 고정)

## 1. 스타일 토큰 (절대 변경 금지 — 이 스타일의 정체성)

```css
:root {
  --bg: #ffffff;          /* 순백. 크림/아이보리 금지 */
  --ink: #111111;         /* 잉크 블랙. 순검정(#000) 대신 */
  --gray-line: #c6c6c6;   /* 비활성 스테퍼 아웃라인 */
  --gray-skel: #e3e3e3;   /* 목업 스켈레톤 바 */
  --stroke-w: 3.5px;      /* 라인아트 기본 획 굵기 (3~4px) */
}
```

- **색은 흑백뿐이다.** 유일한 예외: 실제 브랜드 로고를 보여줄 때 그 로고의 원색(예: Claude 오렌지 #D97757). 로고 외 어떤 요소에도 유채색 금지.
- **글꼴**: Pretendard Variable (CDN). 제목 대비 = Light(300)/Regular(400) 본문 + **ExtraBold(800)~Black(900) 키워드**. 자간 -0.02em.
- **그림자는 blur 없는 솔리드 오프셋만**: `box-shadow: 10px 10px 0 var(--ink)` — 흐림(blur) 그림자 금지.
- **모서리**: 큰 박스 radius 16~24px, pill은 full-round.

## 2. 화면 구조 (16:9 고정)

```
┌────────────────────────────────────────────┐
│              [제목 자막 — 상단 중앙, y≈12%]  │
│ ○                                          │
│ ○   ┌──────────────────────────┐           │
│ ●   │                          │           │  ● = 현재 섹션(검은 원+흰 아이콘)
│ ○   │      중앙 콘텐츠 영역       │           │  ○ = 대기(회색 아웃라인 원)
│ ○   │  (일러스트/목업/다이어그램)  │           │  세로 2px 회색 선으로 연결
│ ○   └──────────────────────────┘           │
│ ○                                          │
└────────────────────────────────────────────┘
```

- **제목 자막**: 상단 `top:13%`, 한 줄(최대 2줄), 문장 중 **핵심 구 1개만 볼드**. 예: `이 매뉴얼은 직원들을 **운영하면서**`
- **좌측 스테퍼**: 화면 왼쪽 x≈5%, 세로 중앙 정렬. 섹션당 원 1개(지름 ≈52px), 안에 라인 아이콘. 현재 섹션 = 검은 채움+흰 아이콘, 지나간/남은 섹션 = 흰 채움+회색 테두리+회색 아이콘. 인트로/아웃트로 슬라이드에서만 숨김.
- **콘텐츠 영역**: 중앙(`top:20%; height:56%`). 텍스트온리 슬라이드는 콘텐츠 없이 문장을 화면 정중앙 대형으로. 일러스트는 세로 320px 이내로 컴팩트하게(하단 푸터와 겹침 방지).
- **하단 핵심문장 푸터(기본 포함)**: 표지·아웃트로를 제외한 모든 슬라이드 하단에 **5줄 요약**을 넣는다. 각 줄 최대 90자, 원고의 실제 문장 기반(핵심 논지+근거+일화 디테일+인용), 줄 구분은 `<br>`, 줄마다 볼드 1구 이내.

```css
.notes{position:absolute;bottom:6.5%;left:6%;right:6%;text-align:center;
  font-size:19px;font-weight:400;line-height:1.7;letter-spacing:-0.01em}
.notes b{font-weight:800}
```

## 3. 슬라이드 아키타입 (7종 — 이 중에서만 조합)

| 코드 | 이름 | 구성 | 사용 시점 |
|------|------|------|-----------|
| A | 텍스트 온리 | 정중앙 대형 문장(clamp 40~64px), 부분 볼드 | 전환·선언·강조 문장 |
| B | 제목+라인아트 | 상단 제목 + 중앙 SVG 일러스트(문서·연필·체크 등) | 개념 설명 |
| C | 제목+UI 목업 | 브라우저/앱 창 와이어프레임(굵은 테두리, ○○○ 신호등, 회색 스켈레톤 바) | 제품·화면 설명 |
| D | 제목+다이어그램 | 라운드 박스(굵은 테두리+오프셋 그림자) + 세로/가지 커넥터 | 조직도·구조·흐름 |
| E | 제목+배지+캐릭터 | pill 배지(아이콘+볼드 텍스트) + 로봇 등 캐릭터 행렬 | 자동화·반복작업 |
| F | 로고 스포트라이트 | 중앙 브랜드 로고(원색 허용) + 하단 볼드 로고명 | 도구·브랜드 소개 |
| G | 밑줄 강조 | A와 같되 볼드 키워드 아래 굵은(6px) 검은 밑줄 | 최고 강조 1~2회만 |

**리듬 규칙**: 같은 아키타입 3연속 금지. A(텍스트)를 사이사이 끼워 호흡을 만든다. 비율 대략 A 40% : 나머지 60%.

## 4. 원고 → 슬라이드 분해 규칙

1. **한 호흡 = 한 슬라이드.** 문장이 길면 의미 단위로 쪼갠다 (슬라이드당 8~20자 제목이 이상적, 최대 30자).
2. 원고를 **3~8개 섹션**으로 묶고 섹션마다 스테퍼 아이콘 1개를 배정 (문서·노트북·책·열쇠·로봇·조직도·시계·카메라 등 lucide 계열 라인 아이콘).
3. **볼드 키워드 선정**: 문장당 1구(2~8자). 조사를 빼고 명사구/동사 핵심만. 볼드가 문장의 절반을 넘으면 실패.
4. 숫자·나열은 D(다이어그램)나 E(캐릭터 행렬)로 시각화. "N가지" 류는 스테퍼 섹션과 일치시킨다.
5. 도구/제품명이 처음 등장하면 F(로고) 슬라이드 1장을 삽입.

## 5. 라인아트 제작 규칙

- **인라인 SVG로 직접 그린다** (외부 이미지 의존 금지). `stroke: var(--ink); stroke-width: 3.5; fill: none; stroke-linecap: round; stroke-linejoin: round`.
- 자주 쓰는 부품: 문서(모서리 접힌 사각+가로줄), 브라우저 창(라운드 사각+상단바+○○○), 로봇(사각 머리+안테나+점 눈+바퀴), 체크 원, 연필, 레고 블록, 말풍선.
- 채움이 필요한 부분(머리카락·넥타이 등)만 `fill: var(--ink)`.
- 복잡한 인물 컷이 꼭 필요하면 media-gen-image 스킬로 `"clean black and white line art, thick uniform outlines, white background, minimal cartoon style"` 생성 후 임베드 — 단, 기본은 SVG.
- **스켈레톤 바**(목업 안 더미 텍스트): `height 12~16px; border-radius 8px; background: var(--gray-skel)` 길이를 60~90% 랜덤 변주.

## 6. 모션 규칙 (CSS만, JS는 슬라이드 전환용)

- 슬라이드 진입 시 요소별 **순차 등장**: `fadeUp 0.5s ease both` + 요소당 `animation-delay` 0.12~0.18s 스태거.
- 제목은 항상 먼저, 일러스트/박스가 뒤따른다. 다이어그램은 부모 박스 → 커넥터 → 자식 박스 순.
- G(밑줄)는 밑줄이 `scaleX 0→1` (transform-origin: left, 0.4s, 제목 등장 후 0.3s 지연)로 그어진다.
- 스테퍼 활성 전환: `background 0.3s ease`.
- `@media print`: 모든 애니메이션 해제(`animation: none; opacity: 1; transform: none`), 슬라이드당 1페이지.

## 7. 빌드 절차

1. `template.html`(이 스킬 폴더)을 읽어 골격으로 사용한다 — 토큰·아키타입 CSS·`.notes` 푸터·내비게이션 JS가 이미 들어 있다.
2. 원고를 4단계 규칙으로 분해해 슬라이드 시퀀스 표(아키타입·제목·볼드 키워드·비주얼 메모)를 먼저 만들고 사용자에게 보여준다 (30장 초과 시 특히).
3. 슬라이드를 `<section class="slide" data-step="N">` 단위로 생성. 스테퍼는 JS가 `data-step`을 읽어 자동 활성화.
4. 완성 파일은 사용자 문서 폴더 또는 지정 위치에 `{주제}-deck.html`로 저장.
5. **검증**: 브라우저 프리뷰로 열어 첫 슬라이드·중간 다이어그램·마지막 슬라이드 스크린샷 확인 — 흑백 위반(유채색), 볼드 과다, 스테퍼 어긋남을 점검한 후 전달한다.

## 8. 조작법 (생성물 안내에 포함할 것)

- `→`/`Space` = 다음, `←` = 이전, `Home`/`End` = 처음/끝
- **화면 클릭**: 좌측 절반 클릭 = 이전, 우측 절반 클릭 = 다음 (버튼 없이 화면 전체가 보이지 않는 클릭 존)
- 우측 하단에 페이지 카운터(N / 전체)만 표시 — 좌우 이동 버튼은 화면에 나타나지 않는다
- URL 뒤에 `#N` = N번 슬라이드 바로 열기, `?shot` = 페이지 카운터도 숨김(캡처용)
- 브라우저 인쇄(Ctrl+P) → PDF 저장 시 전 슬라이드가 페이지별로 출력

```bash
python3 /Users/kbg1023/.claude/skills/monoline-deck/deck2pptx.py "덱파일.html"
```

같은 폴더에 같은 이름의 `.pptx`가 생성된다. 의존성: python-pptx(설치됨), Edge 또는 Chrome.

## 10. 영·한 토글 변형 (강의용 기본)

강의·수업용 덱은 **영어 본문 + 오른쪽 한국어 패널(N 키)** 변형으로 만든다. 골격은 `template-toggleN.html`(이 스킬 폴더).
- 파일명: `ChNN_<Slug>_monoline_EN-KO-toggleN.html` (예: `Ch05_Welfare-State-History_monoline_EN-KO-toggleN.html`). 앞의 `<Base>`=`ChNN_<Slug>`가 데이터 파일 이름의 기준이 된다.
- 슬라이드 본문(제목·박스·pill·하단 5줄 `.notes`)은 **영어**, 각 `<section>` 끝에 `<aside class="ko-panel"><div class="kp-title">한국어 제목</div><p>…</p></aside>`로 한국어 요약 2~3문단.
- `#stage.ko-on` 규칙이 패널이 켜졌을 때 본문을 60% 폭으로 줄이므로 본문 글자 수는 토글 전후 모두 넘치지 않게 잡는다.
- 사용자가 "한국어만"·"영어만"을 명시하면 그때만 기본 `template.html`을 쓴다.

## 11. 강의 해설 JSON (덱과 함께 반드시 생성)

덱과 같은 폴더에 `_notes_<Base>.json` — **슬라이드 수와 같은 길이의 한국어 문자열 배열**. 각 항목 형식:
```
[n/N] 슬라이드 제목\n· 핵심 줄 1 · 핵심 줄 2 …\n\n[EN key lines]\n- …\n\n[강의 노트]\n강사가 그 슬라이드에서 말할 내용(3~5문단, 예시·시험 팁 포함)
```
이 파일이 S 키 해설 화면의 원문이다. 번역은 12절.

## 12. 편집기 · 해설 · 번역 후처리 (필수 — 빠뜨리면 미완성)

완성된 덱마다 아래를 실행한다. 도구는 이 스킬 폴더 `tools/`에 있다.

1. 슬라이드 본문 단위 추출
   `python3 ~/.claude/skills/monoline-deck/tools/extract_slide_units.py "<덱>.html"` → `_slides_<Base>.json` (k→HTML 목록)
2. 번역 (sonnet 서브에이전트 병렬, 파일당 1개)
   - 해설: `_notes_<Base>.json` → `_notes_<Base>.{en,zh,ne,my,vi}.json` (같은 길이 배열, `[n/N]` 접두 유지, `[강의 노트]` 라벨 번역)
   - 본문: `_slides_<Base>.json` → `_slides_<Base>.{zh,vi,my}.json` (k→번역 HTML 객체, 태그 순서 동일)
   - 검증: `python3 ~/.claude/skills/monoline-deck/tools/check_slide_units.py _slides_<Base>.json _slides_<Base>.zh.json` (missing·tag-mismatch·empty 0)
   - 네팔어·미얀마어는 출력이 길어 64K 토큰 한도에 걸린다 → **5개 항목씩 별도 파일로 쓰고 python3로 합치라고** 지시. 에이전트들이 스크래치패드를 공유하므로 **고유한 임시 파일명**을 쓰게 한다.
3. 편집기 주입 (멱등, 재실행 가능, 번역 파일이 있으면 자동 포함)
   `python3 ~/.claude/skills/monoline-deck/tools/deck_editor_patch.py "<덱>.html"`
4. 검증: `node --check`로 주입 스크립트 문법, 브라우저에서 E(툴바 한 줄)·S(현재 슬라이드 해설·언어 선택)·툴바 언어 선택(본문 전환)·Ctrl+Z 확인.

주입되는 기능(사용법 화면 `?`에 자동 정리됨): E 편집 모드(텍스트 편집 / 이동·숨기기 모드, Shift+클릭·범위 드래그 복수 선택, 드래그·방향키 이동, Ctrl+[ ] 글자 크기, 색상, 등장 모션, 정렬, 숨기기/모두 보이기/초기화, Ctrl+Z/Y, Ctrl+S HTML 저장, 브라우저 자동 저장, 감추기/☰ 메뉴), 툴바 슬라이드 언어(원문 EN·中文·Tiếng Việt·မြန်မာ), S 해설(현재 슬라이드, ko/en/zh/ne/my/vi), ? 사용법.
