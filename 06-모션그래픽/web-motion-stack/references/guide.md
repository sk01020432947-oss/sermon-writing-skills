# web-motion-stack 가이드 (catalog.json에서 생성)

출처: [이제 영상까지 바이브 코딩으로 만듭니다 | 클로드](https://www.youtube.com/watch?v=p8rphwT9g-A) — 코드깎는노인, 9:07

영상 전체가 코드로 만든 모션그래픽이다. AI 영상 제작을 '생성 모델'과 '코드' 두 갈래로 나누고, 웹 기술 7층(CSS·JS·GSAP·SVG·Canvas·Three.js·WebGL/WebGPU)으로 움직임을 만드는 원리, Claude Code(Opus 5.5)에 한 줄 요청 → 말로 부분 수정 → 4K 60fps MP4 출력의 흐름, 그리고 코드 영상의 장점(정확한 글자·쉬운 제작·눈으로 검수·자기검토 루프)을 보여 준다.

## A. 관점 — 코드로 만드는 영상

### A1 AI 영상은 두 갈래다 (0:08)
① 영상 생성 모델: 프롬프트를 넣으면 AI가 장면과 움직임을 통째로 생성한다. ② 코드: 움직이는 화면을 코드로 짓고 그 화면을 영상처럼 쓴다. 이 스킬은 ②를 다룬다.
- 프롬프트: 영상 생성 모델 말고, 웹 코드로 움직이는 화면을 만들어 영상으로 쓸 거야.
- 응용: 사람·실사·표정이 필요하면 ①(media-gen-video), 글자·도형·도표·개념이면 ②.

### A2 웹페이지의 움직임은 전부 코드다 (0:42)
글자가 서서히 나타나고, 이미지가 움직이고, 스크롤하면 화면이 전환되는 것 — 매일 보는 웹사이트의 움직임이 모두 코드로 만든 것이다. 즉 '영상처럼 보이는 화면'은 이미 웹에서 흔하다.
- 프롬프트: 웹사이트 히어로 섹션처럼 글자가 떠오르고 이미지가 서서히 움직이는 장면
- 응용: 웹사이트에서 본 인터랙션을 그대로 영상 장면으로 옮길 수 있다.

### A3 조금 더 복잡하게: 입자·3D·카메라 (1:01)
수많은 입자가 화면을 날고, 3D 물체가 회전하고, 카메라가 공간 안으로 들어가거나 물체 주변을 도는 장면도 브라우저 안에서 만든다.
- 프롬프트: 카메라가 공간 안으로 천천히 들어갔다가 중심 물체 주변을 반 바퀴 도는 3D 장면
- 응용: 샘플 W05·W06·W08.

### A4 브라우저 화면을 녹화하면 MP4 (1:16)
필요하면 그 화면을 녹화해 일반 영상 파일(MP4)로 쓴다. 실제로는 화면 녹화가 아니라 프레임마다 시각을 지정해 찍는 방식(seek 렌더)이 끊김 없이 정확하다.
- 프롬프트: 완성되면 MP4로 변환해줘.
- 응용: render.mjs(빠른 확인) / render_hq.mjs(납품용).

### A5 새 기능이 아니라 원래 잘하던 코딩 (3:20)
Claude에 '영상 만들기 기능'이 따로 생긴 게 아니다. 화면은 결국 코드이고, Claude는 그 코드를 이미 잘 쓴다. 그래서 방법은 '요청하기'뿐이다.
- 응용: 앱을 바이브코딩하던 방식 그대로 영상을 만든다.

### A6 기술을 조합하면 영상 표현 전부 (3:03)
웹은 글자·이미지만 띄우는 곳이 아니다. 기술을 조합하면 2D 모션그래픽, 파티클 효과, 3D 애니메이션, 카메라 연출까지 하나의 환경에서 된다.
- 프롬프트: 배경은 셰이더, 제목은 GSAP, 도형은 SVG, 입자는 Canvas로 한 장면에 섞어줘.
- 응용: 장면마다 가장 맞는 층을 고르고 한 타임라인에 묶는다(아래 7층 표).


## B. 제작 흐름 — 요청·수정·출력

### B1 요청은 프롬프트 하나 (3:33)
Claude Code에서 Opus 5.5(노력 높음)에게 한 문단으로 요청했다. 주제 한 줄 + 길이(약 10초) + 기술(웹 기술 다양하게) + 강조점(타이포그래피) + 제약(OFL 글꼴만).
- 프롬프트: 「웹은 역동적인 모션그래픽을 표현하기에 가장 적합한 환경이다」를 주제로 약 10초 분량의 모션그래픽을 만들어줘. HTML·CSS·JS·SVG·Canvas·WebGL·Three.js를 다양하게 쓰고 타이포그래피를 강조해. 글꼴은 SIL Open Font License 글꼴만 써.
- 응용: 프롬프트 레시피 R1.

### B2 제약을 건다: OFL 글꼴만 (3:47)
상업적으로 안전한 OFL 글꼴만 쓰라고 지정하면 결과물의 라이선스 문제가 사라진다. 결과 화면 하단에 'SIL OFL 1.1'이 표기됐다.
- 프롬프트: 글꼴은 SIL OFL 1.1 글꼴만, 화면 구석에 라이선스를 작게 표기해.
- 응용: 설교·교회 영상 배포 전 글꼴 라이선스 점검을 아예 요구사항으로.

### B3 극단적 제약이 부딪히면 Claude가 해법을 만든다 (4:02)
에이전트 지침(AGENTS.md)에 '외부 자료를 가져와 쓰지 말라'가 있었다. 'OFL 글꼴만' + '외부 자료 금지'가 충돌하자 Claude는 글꼴을 직접 그려 만들고 OFL 라이선스를 붙였다.
- 프롬프트: 외부 파일·웹폰트·이미지를 내려받지 마. 필요한 그림과 글자는 코드로 직접 그려.
- 응용: 오프라인·보안 환경 작업, 저작권이 걱정되는 소재. 샘플 G09.

### B4 수정은 코드 한 부분만 (4:26)
생성 모델 영상은 '수정'이 아니라 요구를 반영한 '새 영상 생성'이다(전체가 바뀜). 코드 영상은 색·크기·문구 값만 바꾸면 그 부분만 바뀐다(sun fill, radius, title text).
- 프롬프트: 2번 장면의 해 색만 #3CF0C4로, 제목을 '바다 노을'로 바꿔줘. 나머지는 그대로.
- 응용: 값을 상단 CONFIG 객체로 빼 두면 수정이 더 쉽다(확장 E7).

### B5 미리보기 장치는 최종본에서 뺀다 (4:48)
Claude가 만든 화면에는 상·하단 설명 문구와 재생 컨트롤이 있었다. 영상으로 쓸 때는 보이면 안 되므로 '없애 줘'라고 요청했다.
- 프롬프트: 상단·하단 문구와 재생 바를 없애고 장면만 꽉 차게 보여줘.
- 응용: 하네스의 ?embed=1 / --embed 가 같은 역할.

### B6 출력: 4K 60fps MP4 (5:05)
마지막 단계는 MP4 변환 요청. 4K(3840×2160) 60프레임으로 지정했다. 1초에 60장을 찍는다.
- 프롬프트: 4K(3840×2160) 60fps MP4로 변환해줘.
- 응용: node render_hq.mjs <폴더> --scale 3 --fps 60

### B7 입력의 세 단계: 한 줄 → 기획서 → 대본 (6:04)
주제 한 줄만 줘도 만든다. 구체적 기획(메시지·대상·톤·장면 구성·스타일·길이)이 있으면 그걸 주고, 대본이 있으면 '이 대본을 시각화해줘'라고 하는 게 좋다. 입력이 구체적일수록 의도대로 나온다.
- 프롬프트: 다음 대본을 문장마다 한 장면으로 시각화해줘: …
- 응용: 샘플 G05. 대본+나레이션 타이밍은 claude-motion-studio 모드 A·D.


## C. 장점 — 왜 코드 영상인가

### C1 해상도 독립: 점·선·면은 크기를 고른다 (5:22)
MP4는 화소의 격자다. 4K는 3840×2160 ≈ 830만 화소/장면이라 큰 화면에서 확대하면 선이 흐려진다. 웹 방식은(구현에 따라) 점·선·면을 수치로 표현하므로 변환할 때 원하는 크기를 고를 수 있다.
- 프롬프트: 모든 도형은 SVG/벡터로, 출력은 4K로.
- 응용: DOM·SVG는 공짜로 선명. Canvas·WebGL은 devicePixelRatio를 곱해야 한다(E2).

### C2 글자가 정확하다 (6:25)
이미지·영상 생성 AI는 글자가 자주 망가진다. 코드 영상은 텍스트를 그대로 그리므로 오타 확률이 AI 답변의 오타 수준이다. 그래서 글자가 많은 설명형 영상에 특히 강하다.
- 프롬프트: 화면 문구는 이미지가 아니라 실제 텍스트로 그려.
- 응용: 설교 본문·성경 구절·통계 수치처럼 한 글자도 틀리면 안 되는 영상.

### C3 만들기 쉽다: 바이브코딩 그대로 (6:57)
목표는 영상이지만 과정은 앱·웹사이트를 만드는 바이브코딩과 같다. 말로 요청하면 AI가 코드를 만든다.

### C4 보이는 게 전부: 눈으로 검수한다 (7:12)
바이브코딩으로 만든 앱은 겉은 멀쩡해도 속에 보안 문제·데이터 오류가 있을 수 있고, 개발 지식 없이는 판단이 어렵다. 영상은 결과물이 화면 자체라서 눈으로 보고 괜찮으면 괜찮은 것이다. 움직임이 어색한지, 글자가 작은지, 장면이 너무 빠른지, 구성이 이상한지 — 코드를 몰라도 보인다.
- 프롬프트: 완성되면 1초 간격 콘택트시트를 뽑아 직접 보고, 움직임 어색·글자 작음·너무 빠름·구성 어긋남을 고쳐.
- 응용: 샘플 G10. 검수 체크리스트 R9.

### C5 첫 시도에 만족하긴 어렵다 — 자기검토 루프 (8:03)
이미지를 보고 SVG로 따라 그리게 했을 때 1차는 엉성했지만, AI가 결과를 여러 번 확인하며 고치자 크게 좋아졌다. 만들기 → 보기 → 고치기를 반복시키면 품질이 꾸준히 올라간다.
- 프롬프트: 렌더 결과를 캡처해 참조 이미지와 비교하고, 차이가 없어질 때까지 최대 4번 스스로 고쳐.
- 응용: 샘플 G07. 콘택트시트 자동 비교(E5).

### C6 개념 설명은 정지 이미지보다 영상 (8:27)
추상적·개념적인 내용이 많은 콘텐츠는 보조 화면이 자주 필요하다. 정지 이미지보다 움직이는 영상이 전달력이 확실히 좋다. 그래서 영상 콘텐츠 전반의 품질이 올라갈 것이다.
- 프롬프트: 이 개념(태양계 공전)을 5초 B롤로 보여줘.
- 응용: 설교·강의의 개념 B롤. 샘플 X01.


## D. 연출 문법 — 이 영상이 쓰는 화면 장치

### D1 오프닝 훅: 워프 + 한 단어 + '전부 코드' (0:00)
빛줄기가 중심에서 뻗는 하이퍼스페이스 위로 '역동적인' 한 단어가 번짐에서 선명하게 맺히고, 첫 문장이 '이게 전부 코드로만 이루어진 영상'이다. 결과물을 먼저 보여 주고 방법을 약속한다.
- 프롬프트: 빛줄기가 가속하는 워프 배경 위로 핵심 단어 하나가 블러에서 선명하게 맺히는 3초 오프닝
- 응용: 샘플 G01.

### D2 쇼케이스 그리드: 기술 6칸 미리보기 (0:04)
2D TRANSFORM · SVG MORPH · CANVAS WAVE · VARIABLE TYPE · WEBGL SHADER 칸이 번호와 함께 격자로 놓여 각자 움직인다. '이런 걸 다 만든다'를 한 화면에 요약한다.
- 프롬프트: 6칸 격자에 각 칸마다 다른 기술 데모가 돌아가고 칸 번호가 붙은 쇼케이스
- 응용: 이 도감의 갤러리 자체가 같은 문법.

### D3 번호 알약 태그로 현재 위치 (0:15)
좌상단 '01 METHOD 01', '02 HOW · 기본 재료', '03 01/05 · GSAP'처럼 민트 번호 칩 + 고정폭 영문 라벨이 늘 같은 자리에 있다. 시청자가 지금 몇 번째 이야기인지 안다.
- 프롬프트: 모든 장면 좌상단에 '번호 칩 + 섹션 이름' 태그를 같은 위치·크기로
- 응용: 모든 샘플의 .tag.

### D4 챕터 카드: 큰 번호 + 한 줄 제목 + 유령 숫자 (0:26)
'02 이번 영상에서 소개할 방법', 'CHAPTER 05 수정하고, 출력하기'. 거대한 민트 숫자와 짧은 제목, 배경에는 외곽선만 있는 큰 숫자가 흐른다.
- 프롬프트: 챕터 전환마다 큰 번호와 한 줄 제목, 배경에 외곽선 숫자가 천천히 흐르는 카드
- 응용: 샘플 G02.

## E. 확장 — 영상에 없지만 실제로 해 보며 확인한 것

### E1 시간은 타임라인 하나에만 (seek 결정론)
CSS @keyframes·transition·setTimeout·Math.random은 '재생'에는 되지만 프레임 단위 렌더에서 어긋난다. 모든 움직임을 GSAP 타임라인 하나에 올리고, Canvas·WebGL·Three.js도 tl.to(state,{t:DUR, onUpdate:draw})로 시간을 받아 그리면 어느 프레임이든 정확히 다시 그린다.
- 프롬프트: 모든 움직임은 GSAP 타임라인 하나로, 캔버스·3D는 onUpdate에서 t로 그려. Math.random 금지, 시드 난수 사용.
- 응용: 모든 샘플의 공통 골격.

### E2 4K에서 Canvas·WebGL을 선명하게
DOM·SVG는 배율만 올리면 선명하지만 Canvas·WebGL은 백버퍼를 width×devicePixelRatio로 키워야 한다. 반대로 Three.js 점 크기처럼 월드 단위 값에 DPR을 곱하면 4K에서 3배로 뭉친다 — 실제 렌더 테스트(W08)에서 발견해 고쳤다.
- 프롬프트: 캔버스는 devicePixelRatio만큼 키우고, 월드 단위 크기에는 곱하지 마.
- 응용: 4K 출력 전 한 프레임을 잘라 확대 확인.

### E3 물리 시뮬레이션은 미리 계산
튕김·충돌처럼 앞 프레임에 의존하는 움직임은 seek가 안 된다. 로드할 때 30fps로 끝까지 계산해 배열에 넣고, seek(t)는 해당 프레임을 그리기만 한다.
- 프롬프트: 입자 시뮬레이션은 로드 시 전체 프레임을 미리 계산해 두고 재생은 인덱스로.
- 응용: 샘플 W05.

### E4 SVG 모핑은 점 개수만 맞추면 된다
MorphSVG 같은 유료 플러그인 없이, 점 개수와 명령 구조가 같은 두 path의 d를 GSAP가 숫자끼리 보간한다. 원·별·물방울을 같은 20점 다각형으로 정의했다.
- 프롬프트: 모핑할 도형은 같은 점 개수의 path로 만들어 d 속성을 보간해.
- 응용: 샘플 W04.

### E5 자기검토를 기계화: 콘택트시트
C5의 '여러 번 확인'을 자동화한다. 렌더 → ffmpeg tile로 한 장 요약 → Claude가 그 이미지를 직접 읽고 겹침·잘림·빈 화면을 고침(최대 3회). 이 스킬의 20개 샘플도 이렇게 검수했다(바늘 사라짐, 패널 미표시, 4K 점 뭉침을 이 단계에서 잡음).
- 프롬프트: 렌더 후 콘택트시트를 직접 보고 문제를 고쳐 다시 렌더해. 최대 3회.
- 응용: ffmpeg -i clip.mp4 -vf "fps=6/길이,scale=480:-1,tile=3x2" -frames:v 1 check.jpg

### E6 수정이 쉬운 코드로 처음부터
B4를 극대화: 문구·색·길이·장면 순서를 맨 위 CONFIG 객체로 분리하라고 처음부터 요청한다. 그러면 다음 영상은 CONFIG만 바꿔 대량 생산한다(설교 시리즈, 주간 공지).
- 프롬프트: 문구·색·초를 파일 맨 위 CONFIG 객체에 모아, 나중에 값만 바꿔 재사용하게 해.

### E7 MP4로 굳히지 않고 라이브 HTML로 쓰기
예배 대기 화면·키오스크·웹사이트 배경은 MP4 대신 HTML을 브라우저 전체화면으로 띄우면 해상도 제한도 반복 이음새도 없다(셰이더 W07은 무한 루프 가능).
- 프롬프트: 이 장면을 전체화면 무한 반복 HTML로도 줘.
- 응용: index.html을 그대로 열기(라이브 모드는 자동 반복).

### E8 층 선택은 '무엇이 몇 개 움직이나'로
요소가 수십 개 이하이고 글자 중심이면 DOM+GSAP, 선·아이콘이면 SVG, 수백~수천 개면 Canvas, 수만 개·빛·왜곡이면 WebGL, 깊이·카메라가 필요하면 Three.js. 한 장면에 여러 층을 겹쳐도 시간은 하나.
- 응용: 아래 7층 결정표.

### E9 접근성·안전
초당 3회 이상 번쩍임 금지, 본문 대비 4.5:1 이상, 글자는 1080p 기준 24px 이상(모바일 시청). 통계는 출처 있는 값만, 없으면 화면에 '예시'.
- 프롬프트: 번쩍임 초당 3회 이하, 글자 최소 24px, 수치는 출처 표기.

### E10 한글은 설치된 OFL 글꼴로
영상의 '글꼴 직접 만들기'(B3)는 라틴 몇 자에 그친다. 한글은 설치된 OFL 글꼴(Noto Sans KR·고운바탕·고운돋움·나눔)을 이름으로 지정하고, 렌더 전에 document.fonts.check로 실제 로드를 확인한다.
- 프롬프트: 한글은 Noto Sans KR(본문)·Gowun Batang(제목)만 써. 둘 다 이 맥에 설치된 OFL 글꼴이야. 렌더 전에 글꼴이 실제로 로드됐는지 확인해.
- 응용: 설교 본문 카드·강의 자막처럼 한글이 주인공인 모든 장면.

### R1 한 줄 주제형 (영상 원문 방식) — 빨리 맛보기, 방향 탐색
```
「{주제 한 문장}」를 주제로 약 {10}초 분량의 모션그래픽을 만들어줘.
HTML·CSS·JS·SVG·Canvas·WebGL·Three.js 같은 웹 기술을 다양하게 쓰고 타이포그래피를 강조해.
글꼴은 SIL Open Font License(OFL) 글꼴만 써.
하나의 index.html로, 1920×1080 기준.
```

### R2 제약 지침형 (AGENTS.md / 프로젝트 지침에 고정) — 반복 작업, 저작권·보안이 걱정될 때
```
[고정 규칙]
- 외부 파일·웹폰트·이미지·CDN을 내려받지 않는다. 그림과 글자는 코드로 직접 그린다.
- 글꼴은 OFL 글꼴만. 화면 구석에 라이선스를 작게 표기.
- 모든 움직임은 GSAP 타임라인 하나. Math.random·CSS animation 금지(시드 난수 사용).
- 강조색 1개 + 경고색 1개 + 어두운 배경. 장면마다 좌상단 번호 태그.
- 마지막 0.8초는 완성 상태로 정지.
```

### R3 기획서형 — 의도한 결과가 분명할 때
```
다음 기획서대로 모션그래픽을 만들어줘.

- 스타일: {배경·강조색·글꼴·움직임 동사} / 금지: {템플릿 느낌, 3색 초과, 이유 없는 글로우}
- 길이·비율: {10초, 16:9}
```

```
아래 대본을 문장마다 한 장면으로 시각화해줘. 글자는 핵심어만 크게, 나머지는 도형·도식으로 보여줘.

{대본}
```

### R7 따라 그리기 + 자기검토형 — 참조 이미지를 벡터로 옮길 때, 품질이 아쉬울 때
```
첨부한 이미지를 SVG로 따라 그려줘.

차이가 없어질 때까지 최대 4번 반복하고, 회차별 결과를 남겨.
```

### R8 층 지정형 — 원하는 표현이 분명할 때
```
한 장면에 층을 겹쳐줘:
- 배경: WebGL 셰이더(빛 번짐 + 느린 물결)
- 중간: Canvas 입자 300개(천천히 위로)
- 앞: SVG 선이 그려지는 아이콘
- 제목: GSAP로 줄 마스크 등장
시간은 GSAP 타임라인 하나가 모든 층을 지휘하게.
```

### R9 검수 체크리스트형 — 완성 직전
```
렌더 후 1초 간격 콘택트시트를 직접 보고 아래를 점검해 고쳐줘(최대 3회):
□ 움직임이 어색하거나 튀는 곳
□ 글자가 작거나(1080p 기준 24px 미만) 잘리거나 겹치는 곳
□ 장면이 너무 빨라 읽을 수 없는 곳(글자 장면은 최소 2초 정지)
□ 구성·여백이 어긋난 곳, 빈 화면
□ 4K에서 캔버스·3D가 흐리거나 뭉치는 곳
```
